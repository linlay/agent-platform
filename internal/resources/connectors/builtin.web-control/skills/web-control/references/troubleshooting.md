# Page operation failures

- `target_required`: supply the exact `surfaceId` from `workpanel_open`, `surface_open` or `surface_list`.
- `browser_connection_required`: Desktop could not provide the Chrome workspace connection required by this Run. Desktop may reuse an authorized live workspace or lazily connect with remembered authorization; when remembering is enabled, new Chrome Chats may continue that workspace. Do not demand manual setup before the first authorized tool call. If this error is returned, follow the browser settings or Chat controls guidance and continue in a new Run. An accepted WorkPanel Run cannot change backend midway. Do not loop connection prompts, supply an arbitrary endpoint or use another Chat to evade a failed lease.
- Follow-up, resend, new Chat or derived Chat in a new Run: use `surface_list` to rediscover currently authorized pages, then obtain fresh observations and AWCP manuals. A shared live workspace can retain a page, but never another Run's refs or manual binding. After true reconnection, discard old surfaceIds even if a URL looks unchanged. Do not open a duplicate merely to continue.
- `browser_busy`: another Run controls the workspace, or its prior requests have not finished releasing it. Wait for release or let the user use the host's takeover controls when intended; do not busy-poll, cancel a different task without authorization, or create another connection to escape ownership. The next controlling Run still needs a canonical lease and fresh observations/manuals.
- `browser_run_unavailable`: this Run's lease ended or is not valid for the request. Workspace continuity cannot revive it. Follow the host's new-Run recovery flow, rediscover pages, and reconcile uncertain writes rather than replaying them.
- A website navigation failure can be wrapped as `desktop_cdp_client_rejected`; diagnose it using `details.clientErrorType` and the host's safe message, not just the outer code. The following page errors are distinct from Chrome connection/extension authorization errors. Do not clear saved authorization, disconnect or reconnect to repair the site. A failed open may already have created a tab: list this Run's pages and inspect a relevant live surface only if its surfaceId was actually returned. Do not guess an ID, observe a nonexistent page or open more tabs in a retry loop.
  - `page_connection_refused`: check the address and website availability. For a local address, report that its service may be stopped; do not ask for Chrome authorization again or start/change services without authorization.
  - `page_name_not_resolved`, `page_connection_interrupted`: check the website address, DNS or network availability described by the host. The error does not prove that an earlier request failed to reach the site.
  - `page_navigation_timeout`, `page_navigation_interrupted`: navigation may already have reached the site or partially loaded. Reconcile any available page state and preserve the action outcome before a deliberate retry; do not blindly reopen, reload or repeat a possibly consequential request.
  - `page_navigation_blocked`, `page_security_error`: the user checks the browser policy, certificate or security warning in Chrome. Do not disable protections or bypass the warning.
  - `page_navigation_failed`: preserve the host's generic navigation diagnostic and check the address and availability. Do not invent a more specific cause or infer lost browser authorization.
- `browser_page_creation_failed`: creating or attaching the new tab failed; Chrome may already contain the tab. Follow the host's guidance about a debugger conflict or closed window, and rediscover authorized pages before considering another open. This is not a website navigation failure or permission to change browser configuration.
- A stale or unavailable observation: read `surface_observe` again on the same authorized page and use its new observationId/ref pair. Never translate an old reference into a guessed selector or replay an action whose outcome is unknown.
- A Chrome action already returned a fresh nested `observation`: use it directly to verify state and select the next ref. `observationError` only describes the follow-up observation; preserve the original action outcome and read state before retrying.
- A background Chrome action reported `outcome:not_started`: if the observed control is enabled, activate that exact authorized surface, obtain a new observation and retry once. Do not apply this recovery to disabled controls, `complete` or `unknown` outcomes. Activation is not required for ordinary background reads.
- `dialog_pending` with an unknown outcome: the triggering action may have opened a native JavaScript dialog. Inspect the returned dialogs and use `surface_dialog` for the authorized accept/dismiss decision; never replay the triggering action. Browser/site permissions, extension authorization, OTP and CAPTCHA require the user.
- Upload or download size/scope/integrity rejection: correct the selected current-Chat file or download identity; do not use absolute paths, another Chat, raw CDP or the user's Downloads directory. Downloads are delivered only after save returns saved:true. Save required downloads before disconnect/takeover; retention is temporary and bounded.
- Chrome capability unavailable: use AWCP through `awcp_manual`/`awcp_invoke`, or the permitted typed surface tools. Chrome still does not support `surface_evaluate` or raw `surface_cdp`; AWCP does not open those routes. Do not probe unsupported methods or switch transport.
- `target_not_found`, `surface_not_ready`: the page closed, was replaced or has not registered. Rediscover it with `surface_list` in the same Run. Do not automatically open a replacement.
- `target_not_owned_by_chat`, `target_not_in_current_surface`, `site_control_unavailable`: the page is outside this Run's authorized Chrome workspace, its WorkPanel/application grant, or an ended grant. Shared-workspace pages are usable only through a current valid lease. Do not guess another tab from its URL or borrow the foreground page or another application's page.
- `current_target_unavailable`: there is no current page; pass a surfaceId from `surface_list`.
- `invalid_args`: correct every reported field using native JSON types. The rejected call did not execute and says nothing about earlier calls. Never reload a form to repair a parameter error.
- `method_not_allowed`: Desktop and Platform must be deployed together. Do not retry removed methods or switch transport.
- `web_action_unavailable`: a host action could not be routed. This does not mean the page is read-only; rediscover the page and use the other surface tools.
- `desktop_cdp_unsupported_runtime`: the surface and AWCP tools require the Desktop runtime. Only the WorkPanel tools work without it.
- `exceptionDetails` from `surface_evaluate`: a script failure. Inspect the details and the current page state. A script's return value is not a host execution status.
- Timeout or cancellation after a mutation: preserve any explicit `action.outcome`; without a definitive outcome, side effects may have happened. In Chrome, use the returned observation or `surface_observe` to reconcile business state. In WorkPanel use an AWCP read section, semantic observation or permitted read-only evaluation. `surface_state` alone only establishes page metadata, not a saved form or submitted transaction.
- Empty download list after a click: no captured file is available yet. This is not proof that the server did not respond. Check the supported HTTP attachment path, current surface and returned metadata; do not repeatedly trigger a write, scan Downloads or switch to direct network retrieval.

## AWCP

`awcp_protocol_unavailable` means the host confirmed that the selected page has no AWCP entry; the permitted surface content tools may then serve the task. A valid manual with no matching action, or a task explicitly calling for standard UI interaction, can also use standard operations within the same grant. `awcp_unsupported_protocol`, `awcp_invalid_contract` and authorization failures are not permission to bypass a rejected operation. `source_chat_not_ready` requires restoring this Run's canonical Chat binding; sharing a live workspace cannot substitute another Run's owner or revive a failed lease. Chrome and WorkPanel use the same manual/section/invoke sequence; each new Run reads its own manual, and neither an AWCP failure nor an unknown write outcome permits switching to a click or submit replay.

Read the directory with `awcp_manual`, then the section with `section` and `revision`, then call `awcp_invoke` on the same page. Do not probe or invoke AWCP through `surface_evaluate`.

Host `awcp_preflight_rejected` carries `stage:desktop_preflight`, `executionStarted:false` and one of `manual_required`, `page_changed`, `stale_revision` or `action_not_found`. Read the unread section; for stale or page-changed evidence, revalidate the page and read its fresh directory and section. Do not substitute another page or guess an action name.

Page `invalid_arguments.details.fieldErrors` may guide a deliberate low-impact correction against the section schema. Timeout, disconnect, cancellation and unknown outcomes require read-only reconciliation before a new mutation. See [AWCP](awcp.md).
