# 独立听写

`cmd/agent-dictation` 提供一次录音到文字的独立服务。它不装配 `app.New`、数据库、Agent 目录、Runtime 或工具，不创建 Chat/Run，不调用 Query/TTS。Platform 语聊仍直接调用 `internal/speech`，保留原有语聊协议、打断、等待和播放编排。

## 实现归属

- `internal/speech`：从 voice 移入的唯一 DashScope socket、ASR、TTS 实现及测试。每个调用方独立创建客户端；连接和任务不跨业务共享。ASR 期限由调用者管理，Platform 显式保留 60 秒总期限。
- `internal/authn`：纯 JWT 验签、身份数据和 bearer 子协议解析。Runtime 身份映射、请求上下文和资源票据仍在 Server。
- `internal/models.LoadModelFile/LoadProviderFile`：原 registry 和听写共用单文件解析。听写仅读取声明的两个文件，不实例化 registry、不扫描其他文件。
- `internal/dictation`：配置、鉴权、HTTP/WS 和一次听写生命周期。

每次连接读取并冻结模型和 Provider；修改文件只影响新连接。Provider 的 SSO token 保持按请求读取。共用配置解析器与模型数据类型不触发 Platform 的配置加载、后台刷新或业务初始化。

## 配置与发布

`make release-dictation` 单独构建；`make release` 同时发布 Platform 和听写两个 Program Bundle。支持同一 `PROGRAM_TARGET_MATRIX`；听写包不携带 Platform 的 sidecar、Agent 或运行时数据。

独立配置模板为 `configs/dictation.example.yml`。服务只需监听地址、`modelFile`、`providerFile`、JWT 验签、SSO token 文件和出站代理。代理使用现有 `auto/pac_auto/direct/fixed`，不另设代理类型。

Unix 包部署示例（Windows 对应 `.ps1`）：

```sh
./deploy.sh --output-dir /absolute/dictation-config --registry-dir /absolute/runtime/registries
# 在独立 .env 中设置所需凭据文件路径；密钥不进入前端。
./start.sh --daemon --config-dir /absolute/dictation-config --state-dir /absolute/dictation-state --log-dir /absolute/dictation-logs --port 11964
./stop.sh --state-dir /absolute/dictation-state
```

部署脚本只在目标不存在时生成 `.env` 和 `dictation.yml`；已有配置保留。`--registry-dir` 仅用于生成两个明确的只读路径，默认模型 `dashscope-paraformer-realtime-v2.yml` 和 Provider `dashscope.yml` 与语聊模板一致；自定义语聊模型的部署应显式调整这两个输入。启动脚本不复制或修改 registry。

Desktop 沿用服务管理器的配置/状态/日志分目录、端口及 `/healthz` 检查，传入 SSO 文件，通过现有 `auth.publicKey` capability 提供公钥。听写是可选服务，不进入核心启动依赖。Web 可独立部署同一程序，托管入口将下列两个精确路径转发到 `DICTATION_BASE_URL`，且优先于通用 `/api`；前端只下发 `DICTATION_ENABLED`。

签名算法为现有 RS256，必须有有效 exp 和非空身份；按部署设置 issuer、audience、allowedSubjects。可使用本地公钥或 JWKS。公网部署应明确配置身份约束及可信来源；不得在 URL 中传递凭据。代理先核验来源，再转发应用访问令牌或同源会话对应的凭据。

## 接口

| 路径 | 行为 |
|---|---|
| `GET /healthz` | 无需身份的进程健康检查，不连接 ASR |
| `GET /api/dictation/capabilities` | 认证后返回 ApiResponse；检查两份定义及凭据可用性，不连接 ASR |
| `GET /api/dictation/ws` | 认证后升级；一次连接只执行一次听写 |

capabilities 的 data 为 `{enabled,reason,version:1,websocketPath,maxRecordingSeconds:60,input:{codec:"pcm_s16le",sampleRate:16000,channels:1,frameMs:20}}`。错误原因不包含模型配置、凭据或正文。

客户端先发 `{"type":"start"}`，收到上游 `task-started` 对应的 `ready` 后发送二进制音频。每帧 640 字节；最后一帧允许非空、偶数字节的短尾包，之后只允许 `{"type":"stop"}`。累计不得超过 1,920,000 字节。未知控制字段、重复开始及非法音频会结束连接。

服务端仅发 `ready/partial/final/error`；`partial/final.text` 是本轮完整快照，不能直接追加。录音最多 60 秒，正常停止后 ASR 最多再等待 10 秒定稿；网络送达余量不计入允许的音频长度。连接关闭取消上游，包括等待定稿期间。没有自动重录、旧引擎回退或跨连接重放。

## 验证边界

隔离测试验证鉴权、来源、配置故障隔离、完整文字快照、尾包和取消；真实供应商、真人麦克风及 Windows 原生生命周期仍需目标环境验收。交叉编译包不代表完成设备验收。
