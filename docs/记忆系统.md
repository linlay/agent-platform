# Markdown 记忆与用户资料

## 数据与边界

Memory 以纯 Markdown 为唯一事实源，不使用 SQLite、embedding、评分、scope、自动学习、数据库快照或双写。知识索引归 KBX；本次不改动正在演进的知识库能力。旧 Memory 未上线，不提供旧数据迁移或双模式运行。

目录沿用 Platform 现有配置：

```text
<runtime>/owner/OWNER.md
<AP_RUNTIME_MEMORY_DIR>/memory.md
<AP_RUNTIME_MEMORY_DIR>/daily/YYYY-MM-DD.md
```

`AP_RUNTIME_MEMORY_DIR` 默认 `<runtime>/memory`。文件可以不存在，首次保存时创建。隐藏 `.memory.lock` 仅提供跨进程互斥，不保存记忆内容。每个文件最大 256 KiB，UTF-8；路径由服务端固定解析，不接受客户端绝对路径、目录穿越或文件/每日目录符号链接。

这是当前个人 Platform 实例的一份共享资料，供该实例授权的 Agent 使用；它不是多租户私人数据隔离机制。已有 HTTP 鉴权与管理端部署边界仍适用，多用户隔离未实现。

## 内容职责与记录原则

- `OWNER.md`：用户明确提供的身份、称呼、语言与协作偏好。用户主导维护，Agent 只能根据明确要求修改，不能推断档案。
- `memory.md`：跨会话仍有价值的事实、长期约定与经验。按主题修改、去重，并标明项目、时间和适用范围。
- `daily/YYYY-MM-DD.md`：当天已确认的进展、临时决定和待跟进事项。它不是聊天流水或待执行动作的成功记录。

只记录有后续价值、可验证的信息；不写密码、Token、私钥、猜测或外部材料里的指令。当前用户纠正优先于旧记忆，记忆内容不授予工具权限。用户要求遗忘时同时检查长期记忆与日期日志；原始 Chat 历史属于独立数据，不自动删除。整理发生在用户或当前 Agent 显式操作中，不在 Run 结束后自动调用模型学习。

## 运行时

```yaml
# configs/runtime.yml
memory:
  enabled: true
  context-max-chars: 12000
  timezone: Local

# agent.yml：显式授权个人记忆能力
memoryConfig:
  enabled: true
```

全局默认开启文件记忆运行能力；Agent 仍需显式 `memoryConfig.enabled: true`。管理页面独立于 Agent 是否启用，可始终维护文件。关闭全局开关不删除文件。

Native 新 Run 在准入时读取 `memory.md`，注入精简记录原则与有界内容；超过字符预算明确标记并让模型使用 `memory_read` 读取全文。日期日志不自动全量注入，使用文字查询或指定日期按需读取。文件保存不触发 catalog 重载，也不需要重启；后续 Run 使用新版，活动 Run 上下文保持其快照。

`contextConfig` 的 `owner` 标记沿用现有启用规则，只读取唯一 `OWNER.md`，不再递归读取 owner 目录中的其他 Markdown；普通 Native Run 在准入时冻结 Owner 内容。ACP/Proxy 外部引擎未接入 Native 个人记忆注入，不能视为自动支持。

工具只保留三项，参数是新文件协议，不兼容旧 record ID / scope / category：

- `memory_read {kind,date?}`：读取 owner / memory / daily，返回文档及 revision。
- `memory_search {query?,before?}`：不传 query 时列出日期；否则进行大小写不敏感的字面文字匹配，每页最多 200 份日期文件、40 个文件的首个匹配片段，可用日期游标查更早记录。它不是语义索引。
- `memory_write {kind,date?,operation,content?,revision}`：save 替换全文，append 仅追加每日记录，delete 删除文件。日期缺省使用配置时区的当天。

写入仅允许已启用记忆的普通 Native main 根 Run；子任务、Team、BTW 只读上下文和 run_query 派生根不直接改写个人记忆。OWNER 修改的用户意图由 Agent 记录原则约束。通用文件权限机制不由本能力改变。

## 编辑协议

所有接口为 HTTP，复用 JSON `{code,msg,data}` 包裹和现有鉴权；不新增 WebSocket 文件管理入口。

| 方法 | 路径 | 参数 / 返回 |
| --- | --- | --- |
| GET | `/api/memory/file` | query `kind=owner|memory|daily`、daily 的 `date`；返回 kind/date/content/revision/exists |
| PUT | `/api/memory/file` | body `kind,date?,content,revision`；返回新文档 |
| DELETE | `/api/memory/file` | body `kind,date?,revision`；返回不存在的文档状态 |
| GET | `/api/memory/daily` | 可选 `before` 日期游标；返回 dates/nextBefore/today |
| GET | `/api/memory/search` | `query`、可选 `before`；返回 matches/nextBefore/maxMatches/searchedDailyFiles |

revision 是内容 SHA-256；不存在文件使用 `missing`。保存/删除在进程间锁内复验 revision，冲突返回 409；写入临时文件后原子替换。锁协调所有通过 Platform 进行的 UI/Agent 写入；外部编辑器直接写盘不参与锁，因此需要在保存前重新加载。Desktop/WebClient 遇到冲突保留草稿，不自动覆盖或重试旧内容。

## 下线范围

SQLite store、FTS、fact/observation 生命周期、scope 管理、consolidate/promote/timeline、数据库快照、日期日志双写、专用 memory.log 与评估脚本均已删除。旧 Agent 静态 `agents/<key>/memory/memory.md` 不再加载。旧 `/api/memory/{meta,scope/*,record/*,history,context-preview}` 和 `/api/learn` 不注册；旧 managementTools/embedding/autoRemember 以及 runtime SQLite/检索权重配置明确拒绝。旧 prompts.memory 模板仍被配置加载器忽略，不参与执行。

Chat、摘要/上下文压缩、其他 SQLite 存储和知识库代码不属于此次 Memory 下线范围。WebClient `/memory` 变为三类文件编辑页；Desktop 在技能中心旁提供“记忆与资料”入口，文件业务均由 Platform 负责。
