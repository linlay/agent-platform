# 记忆系统

## 当前范围

Memory 是默认关闭的可选手工记录能力，固定使用 SQLite store。保留 fact / observation 的显式读写、FTS 文本检索、上下文注入、历史记录、手工晋升与 `memory_consolidate`。记录只能来自显式工具或管理操作；Run 完成后不自动学习、整理或调整置信度。

知识库使用独立的 KBASE embedding、LanceDB generation、索引与检索链路，不依赖 Memory。专用 `mode: KBASE` 继续关闭 Memory。Chat 历史、会话摘要和上下文压缩不属于此次退役的长期记忆学习能力。

## 保留流程

```text
显式 memory 工具 / 管理接口写入
  -> SQLite fact / observation
  -> 文本检索与重要度排序
  -> 已启用 Memory 的 Agent 在 query 前召回
  -> Stable Memory / Current Session / Relevant Observations 注入
```

Agent 的 `memory/memory.md` 是静态背景提示，不进入 runtime memory store；owner、AGENTS.md 和正式 Prompt 的构造规则保留。`snapshot/*.md` 是导出/审阅视图，不是数据库事实源。

## 配置与工具

Memory 需同时开启 `configs/runtime.yml -> memory.enabled` 和 Agent `memoryConfig.enabled`；全局默认关闭。

- `AP_RUNTIME_MEMORY_DIR`：数据目录。
- `memory.db-file-name`：SQLite 文件名。
- `memory.context-top-n`、`memory.context-max-chars`：上下文召回条数和文本预算。
- `memory.search-default-limit`：工具搜索默认条数。
- Agent `memoryConfig.managementTools`：额外注入管理工具。

基础工具：`memory_write`、`memory_read`、`memory_search`。
管理工具：`memory_update`、`memory_forget`、`memory_timeline`、`memory_promote`、`memory_consolidate`。
手工 consolidate 仍可归档过期观察、合并重复项、晋升符合条件的观察；没有自动触发入口。

## 已退役能力及升级处理

以下实现和入口已删除，不提供旧执行路径：

- Memory embedding、向量检索及混合评分。
- 模型记忆摘要、启发式 learn fallback、Run 完成后的自动学习/整理/反馈。
- Learn 产生 Skill candidate 的入口；已有候选的存储及查询保留。
- `/api/learn` 和 `/api/memory/context-preview`：HTTP 返回未注册路由的 404，WebSocket 返回未知 type 的 `invalid_request`（400）。

升级时删除以下旧配置；即使 Memory 关闭，配置中仍包含这些字段也会明确报错：

- Agent `memoryConfig.embedding`、`memoryConfig.autoRemember`。
- Provider 的旧 `memory` 节；KBASE 的顶层 embedding/model 配置不受影响。

以下旧配置在加载时静默忽略，可按需清理；无论 Memory 是否开启，都不会阻止启动、影响有效配置或恢复已退役能力：

- `configs/runtime.yml -> memory.hybrid-vector-weight`、`memory.hybrid-fts-weight`。
- `configs/prompts.yml -> memory` 模板节。

SQLite schema、application_id 和 user_version 不变，不删除或迁移旧数据库。历史 embedding 列继续作为存储契约保留，但不读取、计算或更新向量；旧 `learn` 来源和反馈历史仍可查询。已有手工记录的读取、更新、文本检索与历史接口继续使用。

## 实现入口

- `internal/memory/`：存储、文本召回与手工治理。
- `internal/tools/tool_memory.go`、`tool_memory_consolidate.go`：显式工具。
- `internal/server/handler_memory_console_*.go`：保留的管理端记录、scope 与历史接口。
- `internal/server/session_builder.go`：启用时组装上下文。
