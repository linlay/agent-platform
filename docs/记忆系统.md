# 记忆系统：Platform worker 与 memx

## 总体设计

Platform 在自己的后台 goroutine 中定期组织维护，memx 是按次启动、执行后退出的 Go CLI。不需要连接器，不引入常驻 memx、监听端口或内部 scheduler。

```text
全局定时器 / POST /api/memory/update / memory_update
  → 同一个串行 worker（跨进程锁）
  → Chat 存储导出已完成会话的原始问答
  → memx receipt 检查批次收据
  → Platform 同步持久模型连接配置（仅配置变化时写入）
  → memx update 调模型提取事实、校验证据、写入 daily、提交收据
  → memx summarize 整理截至昨天的长期事实
  → 后续 Native Run 冻结 summary 到上下文
```

Platform 负责调度、Chat 格式适配、Agent 授权、模型连接配置同步、超时、取消和状态。memx 独立调用模型，负责提取提示词、结构化响应解析、引用校验、Markdown 布局、来源、幂等、互斥、恢复及总体整理。memx 支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 的非流式 JSON 请求；提取策略为 system，问答原文为不可信 user 数据，无工具、Owner 或 Agent prompt，不产生额外 Chat。

## 数据与内容职责

```text
<runtime>/owner/OWNER.md                    # 用户明确维护，不自动改写
<AP_RUNTIME_MEMORY_DIR>/summary.md          # 总体记忆
<AP_RUNTIME_MEMORY_DIR>/daily/YYYY-MM-DD.md  # 当日事实与报告
<AP_RUNTIME_MEMORY_DIR>/.memx-receipts/      # 批次 ID / 输入摘要
<AP_RUNTIME_MEMORY_DIR>/.memx-pending.json   # 仅未完成事务存在
<AP_RUNTIME_MEMORY_DIR>/.memx-summary.json   # 自动区域完整性摘要
<cfg.Paths.StateDir>/memx/models.yml       # 私有持久模型连接配置
<cfg.Paths.StateDir>/memory-worker/         # worker 锁、起点、游标、Chat 版本
```

Markdown 是内容来源，收据不进入上下文。文件最大 256 KiB、UTF-8；固定路径，拒绝路径穿越和文档/每日目录符号链接。这是个人 Platform 实例共享记忆，不提供多租户隔离。

- daily：有后续价值的用户陈述、偏好、决定和临时事项，以及明确标注“助手报告（未独立核验）”的回答摘要。自动条目带原文摘录、Chat/Run/source ID、源内容 SHA-256、发生时间、项目和主题 key；编码注释保存同一条事实的结构化来源。正文经人工修改后，该注释不能重新生成原文。
- summary：读取截至昨天的 daily 自动条目，按项目和主题 key 合并，较新用户陈述覆盖旧陈述，只提升 durable=true 的用户事实。助手报告不能提升。按字符预算优先保留较新条目，遗漏数由 CLI 返回，daily 原文仍保留。跨日整理是对模型已提取事实的确定性归并，不额外调用模型写长篇摘要。
- 人工内容：summary 的 memx:summary 标记之外完全保留；daily 人工笔记保留但不自动提升。自动区域被人工修改或删除时，汇总返回 revision_conflict，保留人工版本。

已有 memory.md 在启动时、仅当 summary.md 不存在时复制一次，原文件保留作备份，此后不作为第二份活跃内容源；.summary-migrated 标记防止删除 summary 后在重启时恢复旧备份。原 API/tool 的 kind=memory 与新增 kind=summary 指向同一文件。旧 SQLite memory、scope 和旧学习协议仍不迁移、不恢复。

## 全局配置

统一配置于 configs/runtime.yml，启动时读取，修改后重启 Platform。分发模板 configs/runtime.example.yml 显式关闭全局记忆，并预设 worker.model-key 为 th-minimax-m3；启用时需确认模型注册表中存在该 key。以下为启用示例：

```yaml
memory:
  enabled: true
  context-max-chars: 12000
  timezone: Local
  worker:
    enabled: true
    model-key: ""                 # 留空使用 Platform 默认聊天模型
    poll-interval-seconds: 300     # 默认 5 分钟，允许 10～86400 秒
    timeout-seconds: 120           # 每次 CLI 调用上限，允许 10～600 秒
    max-batches: 20                # 每轮提取尝试上限，允许 1～200
    summary-max-chars: 8000        # 自动汇总区预算，允许 256～65536
```

Agent 仍须显式配置 memoryConfig.enabled: true。全局 memory.enabled=false 关闭记忆上下文和维护触发，不删除文档，管理端仍可编辑文件。worker.enabled=false 仅停用定时维护，手动触发仍可用。只学习当前有效、启用记忆的 Native Agent；ACP/Proxy/Channel、Team 不自动学习。OWNER 的注入规则仍由 contextConfig.owner 控制。

启动后先检查一次，此后按配置间隔检查。单队列串行运行，重复手工请求合并到排队/运行中的任务。停止 Platform 时取消模型请求和子进程并等待退出。此定时器属于应用内部，不创建用户 automation。

## 已完成 Chat 与增量处理

“已完成 Chat”是当前没有活动 Run（持久化 COMPLETED_AT_=0）、没有待回复的 HITL/awaiting，且已有完成记录的普通会话；不要求归档。重新打开的 Chat 等再次完成后处理。

1. 首次启用保存配置时区当天零点作为扫描起点；重启沿用，跨日不丢积压。不会首次启用就向模型发送全部旧历史。跨午夜 Run 按证据实际发生日期写 daily。
2. 使用独立于 UI 置顶排序的分页出口；排除 automation、run_query 派生会话。已处理且完成时间/Run 数未变化的 Chat 跳过。每轮最多扫描 200 个 Chat，游标持久化，扫完后再核对下一轮。本期读取当前 Chat 存储，不回扫已归档会话。
3. 读取物理原始 query、非空 steer 和 assistant 正文，不使用压缩后的历史窗口。排除 system、reasoning、压缩摘要、审批审计、工具正文、附件正文、子任务及内部协调消息。失败/取消 Run 的用户陈述可以保留，助手回答不作为完成结果。
4. 每个 source 段最多 4,000 个 Unicode 字符，每批正文最多 24,000 字节；超出分批。大于 64 MiB 的单个 Chat JSONL 报错。稳定 source ID、内容哈希及 batch ID 用于重试去重。
5. memx 校验引用确实存在、来源角色、哈希和基本凭据模式。无可记事实也提交空收据。模型/写入失败不确认成功；一个 Chat 失败不会阻断后续 Chat，下一轮会重试。
6. 每轮末尾以本地昨天为 cutoff 幂等归并。跨日第一次检查完成昨日整理，停机后补做；迟到事实重新归并。当日事实先入 daily，明确要求立即记住长期约定时用 memory_write。

主题 key、durable 和语义提取依赖模型；引用校验证明来源存在，不能证明模型理解绝对正确。提示要求排除猜测、计划、凭据及外部材料指令，助手报告始终带未独立核验标记。

## 手工触发与内置工具

接口沿用现有鉴权及 JSON {code,msg,data}：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | /api/memory/update | 空 body 或 {} 触发增量；也接受 startDate/endDate/includeArchived 手工范围；202 返回 accepted 和任务状态 |
| GET | /api/memory/status | 开关、配置模型、时区、增量状态及最近一次手工范围任务的进度与错误 |
| POST | /api/memory/cancel | `{id}` 取消指定手工任务，不取消定时增量任务 |
| GET | /api/memory/file?kind=summary | 总体记忆；兼容 kind=memory，也支持 owner/daily |
| PUT / DELETE | /api/memory/file | 原 kind/date/content/revision 编辑协议 |
| GET | /api/memory/daily | 日期分页，支持 before |
| GET | /api/memory/search | daily 字面搜索，支持 query/before |

accepted 不是记忆保存成功；通过 status 判断完成，再读取文件。达到处理上限的剩余材料留待后续检查；停用定时维护时可再次手工触发。公开状态是本进程最近结果，持久化进度通过 checkpoint/收据恢复。

启用记忆的 Agent 自动获得四个工具：

- memory_read {kind,date?}：读取文档与 revision。
- memory_search {query?,before?}：日期列表或文字查询。
- memory_write {kind,date?,operation,content?,revision}：立即 save/append/delete。用户说“记住这条”用此工具；append 仅 daily，summary 使用 save。
- memory_update {}：请求整理已完成 Chat，当前活动 Chat 不纳入；不能声称排队即已保存。

写入/触发仅允许启用记忆的普通 Native main 根 Run；子任务、Team、BTW、只读执行和 run_query 派生根禁止。OWNER 修改仍要求用户明确指示。

Native 新 Run 准入时冻结 summary 内容及 revision 到 system 上下文；超过预算明确提示截断和 memory_read。daily 按需查询。新写入对后续 Run 生效，活动 Run 保留快照。记忆是背景数据，不授予权限，当前用户指令优先。

## 互斥、恢复与人工修改

Platform worker 持有状态目录的跨进程锁；memx 每次维护持有 .memx-instance.lock。文档提交与 UI/tool 共用 .memory.lock；模型调用期间不占文档锁，提交时重新读取，追加 daily 并校验 summary 自动区。

memx 先持久化 .memx-pending.json，逐文件原子替换，最后保存收据/汇总摘要并删除日志。中断后先恢复：文件已是提交内容则跳过，仍是原 revision 则补写，第三方修改则冲突退出。Platform 编辑发现未完成日志时返回冲突，避免抢先覆盖。这是进程崩溃恢复，不宣称多文件对读者瞬时可见或任意掉电下数据库级事务保证。

人工整理宜编辑自动区之外。删除自动事实时，应同时删除 daily 中完整 memx:fact 块（含编码来源）和 summary 对应条目；修改 summary 自动区会暂停后续汇总并报告冲突。当前没有语义 forget API、永久禁止重新学习的 tombstone 或自动冲突合并，文件删除不等于完整语义遗忘。原始 Chat 不自动删除。

## 持久模型连接

Platform 同时向子进程注入 `MEMX_CONFIG_FILE=<StateDir>/memx/models.yml`。当前 CLI 原生入口仍是 `MEMX_CONFIG_DIR`，Platform 用它指向相同文件；不得认为单独设置 FILE 已获得原生支持。

Platform 将 provider 与 model 的 `compat.request.always` 递归合并（model 优先），同步到 `models.extraction.request.extraBody`；不启用交互式 `whenReasoningEnabled`。MiniMax 的 `reasoning_split: true` 等参数由配置传递，不在 MEMX 按模型名称分派。MEMX 校验大小和保留字段，禁止覆盖证据、工具、鉴权、stream 与输出上限，config show 对值脱敏。它仍独立直连模型，不回调 Platform，也不复制模型注册表或交互式执行循环。

Platform 为每个 memx 子进程注入 `MEMX_CONFIG_DIR=<StateDir>/memx`，覆盖进程继承的同名变量。首次维护时通过 `memx config set --stdin` 设置完整模型快照；后续业务命令自动复用，不传 --config-dir。每轮维护前重新解析注册模型，仅连接内容变化时再次同步。不变配置不重复写入，不向每个业务命令重复传凭据。model-key 留空使用注册表默认聊天模型。同步失败时不启动本轮 update/summarize，错误通过 worker status 报告。

Platform 只传完整 URL、实际模型名、协议、鉴权、超时、输出上限、额外请求头和已解析的请求兼容参数，不持有提取提示词、事实结构或模型响应解析。memx 配置使用 schemaVersion=1、models.extraction；protocol 为 openai_chat/openai_responses/anthropic_messages。API key 通过私有文件持久化；配置目录独立于记忆目录，业务命令显式传 --root 绝对路径，模型目录由 MEMX_CONFIG_DIR 选择。memx 的目录优先级为显式 --config-dir > MEMX_CONFIG_DIR > OS 默认目录；环境变量未设置才使用默认目录，所选显式值为空或不是绝对路径时拒绝。有效显式 flag 可以覆盖无效环境变量。config set/show/validate 与 update 使用同一解析规则，--root 不随模型目录变化。

Platform 在维护任务开始时同步配置，并在配置写入前核验 CLI 的 configDirEnv 能力，避免不支持此环境变量的二进制把凭据写入独立用户的默认目录。

隐藏 config 支持 set --file、set --stdin、validate --file 和脱敏 show，不出现在 memx 顶层帮助。相同快照不重写，非法配置不替换旧文件，角色整体替换不继承旧密钥。Unix 目录 0700、文件 0600；Windows 配置采用仅当前用户访问的 DACL。直接文件写入必须预校验并原子替换，使用与 CLI 一致的格式。

每个 update 启动时读取一次模型快照，执行中不热切换；新进程使用新配置。完成批次不因模型或密钥变化而重提取。模型失败不写成功收据，公开错误不暴露上游正文和密钥。当前使用非流式 JSON 模型接口，不传递任意 provider compat 请求体覆盖；完整模型文件契约见相邻 memx 的 docs/CONFIG.md。


## 手工按日期范围整理

`POST /api/memory/update` 接受以下 JSON：

```json
{"startDate":"2026-07-01","endDate":"2026-10-05","includeArchived":true}
```

起止日期均必填，使用配置的 memory.timezone，包含两端日期；结束日期不可晚于今天。选择以 Run 的完成时间为准，保留所选 Run 的完整原始问答，daily 仍按每条证据的发生日期保存。任务提交时冻结上限；当天请求仅包含提交前完成的轮次。跨日对话的事实可能落在范围之外的 daily，这是证据真实日期，不将旧事实改记为今天。

手工和定时维护共用串行执行器、跨进程锁、模型配置与 memx receipt/update/summarize 协议。模型来自 memory.worker.model-key，留空使用默认聊天模型，不接受请求级模型覆盖。worker.enabled=false 只关闭定时器，手工范围仍可执行；memory.enabled=false 禁止所有维护触发。已有定时任务运行时返回 409；同一活动手工范围重复提交返回原任务，不重复排队，不同范围返回 409。

手工任务完整分页处理范围，max-batches 只限制每轮自动增量，不截断手工任务。`.state/memory-worker/range.json` 保存独立进度，不改 checkpoint.json 的 since、游标或 seen。每个 Chat 完成后保存游标，批次提交由 memx 收据保护；中断后可能重新检查当前 Chat，但同一完整 Run 的稳定批次不会再次调用模型。服务重启后自动恢复未完成任务，即使定时器已关闭；模型 key 或时区变化时暂停为失败，要求重新提交范围。取消保留已经写入的事实，失败可重试同一范围。

includeArchived 只覆盖当前 Chat 存储的受管归档库（`<ChatsDir>/archive/archive.db`），通过原始 JSONL 导出证据，不恢复 Chat。它不扫描任意备份目录或历史 `runtime/archive/chats/*` 导出；这些数据需另行受控导入。当前和归档保持相同来源 ID、分段与批次算法，复用收据去重；这不等于任意重新分批或语义事实去重。

范围整理仍只接受当前有效、启用记忆的普通 Native Agent；已删除、停用记忆、ACP/Proxy/Channel、Team 不提取，状态中的 skippedRuns 显示不符合 Agent 条件的范围内轮次。活动/awaiting 会话、automation 和 run_query 来源从候选集中排除。修改 Agent 的记忆开关后可以重新提交范围，不受自动 seen 限制。

GET status 的 manual 返回任务 id、起止日期、状态（queued/running/canceling/completed/failed/canceled）、扫描对话数、选中/跳过/无正文轮次数、新处理与收据复用批次数，以及可用时的 newFacts。memx 0.3.2 新增 factCount；旧 CLI 未返回该字段时不把未知值显示为零。newFacts 仅统计本次获得确认的新批次结果，不是记忆库的总量；崩溃提交后靠收据恢复的事实可能不计入本次计数。

完成表示范围处理和汇总成功，不保证每批都有可记事实；当日事实在 daily，长期汇总仍只整理截至昨天的 durable 用户事实。人工编辑冲突会使任务显示 failed，保存的人工版本不覆盖。`/memory` 的任务状态与文档编辑分开，重新加载结果沿用未保存草稿保护。
