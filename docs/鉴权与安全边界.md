# 鉴权与安全边界

## 当前状态

服务鉴权以 JWT 为主，支持本地公钥文件与 JWKS。resource ticket 用于保护 `/api/resource` 文件访问。CORS 由 `configs/runtime.yml` 的 `cors` 节控制。敏感配置通过 `.env` allowlist、真实 `configs/*.yml`、真实 `configs/*.pem` 或外部 Secret 注入，不提交仓库。

工具级文件和命令权限不在本文展开，见 [工具目录权限](工具目录权限.md)。

## 核心流程

```text
HTTP / WebSocket request
  -> token 提取
  -> 本地公钥或 JWKS 验签
  -> issuer 等声明校验
  -> handler
```

resource 访问在普通鉴权之外还可启用 ticket：

```text
GET /api/resource?file=...&t=...
  -> 校验 resource ticket
  -> 定位 AP_RUNTIME_CHATS_DIR 内资源
  -> 返回文件
```

浏览器可通过现有 `Authorization: Bearer ...` 或 `access_token` Cookie fetch `/api/resource`；显式 Bearer 优先，非法 Bearer 不会降级使用 Cookie。ChatScope 请求的 `file=<chatId>/<relativePath>` 继续支持 resource ticket；无认证主体时 ticket 必须与逻辑资源键 chatId 匹配，已有合法主体时仍执行当前用户与 active/archive chat 的所有权校验。路径穿越、错误 chatId、其他用户 chat、symlink escape 与内部 `.tools`/`.btw` 路径均拒绝。

绝对路径请求必须同时提供 `chatId` 与 Bearer/Cookie 主体，resource ticket 永远不能授权。普通 Agent 仅可读取当前 Workspace；Team chat 拒绝全部绝对路径。`/tmp/...` 对普通 Agent 按清理后的词法前缀放行，并按产品决策允许 symlink 跳出 `/tmp`，所以它是明确、独立且高风险的例外，不代表扩大 Workspace 权限。真实 `/api/resource` 请求地址只属于客户端 adapter 的 HTTP 数据面，不是 Markdown 协议。

## 约束与注意事项

- 本地公钥文件路径固定为 `configs/local-public-key.pem`，不提供 YAML 或环境变量覆盖。
- `auth.jwks-uri` 非空时走 JWKS 模式。
- WebSocket 鉴权复用 HTTP token 校验链路。
- JWT `exp` / `iat` 与 resource ticket payload `e` 是 token 内部 NumericDate（秒），不受普通 API epoch-milliseconds 字段约束。只有对 Desktop/WS 公开的 auth expiry 才映射为 `expiresAt` epoch milliseconds；缺少 `exp` 时省略该字段。
- provider `apiKey` 按明文字符串读取，不提供加密或解密机制。
- `runtimeConfig.env` 不通过 catalog API 回显。
