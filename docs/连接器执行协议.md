# 连接器执行协议

## 职责

Platform 提供标准连接器能力：目录和描述、CLI/MCP 执行、部署级凭据管理、授权复核、取消/超时及可选幂等收据。是否由 WebApp、Desktop 或其他客户端调用，不影响连接器核心契约。应用授权、页面生命周期、应用与资源的关联及 SDK 由调用方维护；Platform 不接收 appId，不建立应用模型，也不注册业务 operation/profile 或读取 operations.json。

执行授权仅包含可信主体、连接器/adapter 权限和收据命名空间。`idempotencyNamespace` 是调用方选择的稳定去重分区，不代表应用身份、凭据账户或资源所有权；它不授予权限。发布产物是独立 Chat 能力，见 [API 与协议](API与协议.md#已发布产物读取)，不放入连接器 Scope。

## 身份与执行授权

`/api/connectors/execution/grants` 和 `/api/connectors/auth`（含 `/cancel`）始终要求 JWT，即使普通 API 的鉴权关闭。可信授权主体沿用已有本地身份契约：已验证 JWT 的非空 subject、`scope=app` 和非空 deviceId/device_id；这里的 app 是现有 JWT 的本地程序角色，不是被调用应用的标识。请求体不能选择主体。该角色原有的部署级连接器授权能力不扩大为普通用户或匿名权限。

- `POST /api/connectors/execution/grants`：`{version:3,idempotencyNamespace,execution:[{connectorId,adapter}]}`。
- 返回 `{grantId,token,idempotencyNamespace,expiresAt}`，token 以 `cxg_` 开头，expiresAt 为 epoch milliseconds。
- `DELETE /api/connectors/execution/grants?grantId=...`：仅同主体可撤销。

授权有效期 15 分钟，仅保存在进程内存，重启失效；撤销、到期及服务关闭取消关联调用。最多 1024 个活动授权，每个最多 64 个不重复的连接器/adapter 组合，无通配符。adapter 只允许 cli/mcp；命名空间沿用连接器 ID 的字符规则，长度不超过 128。可信调用方签发最小所需权限并负责自身内部授权和及时撤销，不能把登录成功视为执行授权。

接口严格拒绝 appId、chatIds、subject、operations、allowWrite 等未定义字段。普通 JWT 不能直接调用 execution list/describe/invoke，执行 token 不能管理凭据、签发授权或读取 Chat。

## 目录与执行

以下接口均为 POST，Authorization 使用 `Bearer <cxg_token>`：

| 路径 | 请求 | 返回 |
| --- | --- | --- |
| `/api/connectors/execution/list` | `{}` | `{items:[{connectorId,name,packageVersion,adapters}]}`，仅授权集合 |
| `/api/connectors/execution/describe` | `{connectorId}` | `{connectorId,revision,adapters,components}` |
| `/api/connectors/execution/invoke` CLI | `{connectorId,adapter:"cli",args:string[],idempotencyKey?,credentialRevision?}` | `{invocationId,connectorId,adapter,credentialRevision,exitCode,stdout?,stderr?}` |
| 同上 MCP | `{connectorId,adapter:"mcp",component,toolName,arguments,idempotencyKey?,credentialRevision?}` | 相同身份字段及 `mcp` 原生结果 |

安装目录的标准发现仍可使用既有 `GET /api/connectors`；受限 execution/list 只列当前授权可见的连接器。

执行前检查 configured、凭据状态、credentialRevision、包锁和包内容指纹，并复核连接器/adapter 权限。CLI 直接传 argv，不拼接 Shell 字符串；最多 256 项、拒绝 NUL，禁止调用方指定 executable/cwd/env。入口、固定工作目录、configEnv、准备状态和认证绑定来自安装包及现有 connectorauth。环境只保留基本运行变量与当前连接器凭据，不继承 Platform JWT 或其他连接器凭据。通用 CLI 执行不是 OS 沙箱，授权范围包含连接器本身允许的读写操作。

Windows 原生 exe 直接启动，标准 Node cmd shim 解析为 Node 与脚本参数，不经过 cmd /c；不支持的脚本明确拒绝。MCP 使用包内已配置组件及原生工具参数，拒绝禁用组件/工具，保留 content/structuredContent/isError。oneid-token MCP 的通用执行限制不变。

输入和结果限 1 MiB，执行期限 30 秒。请求取消、授权撤销/到期取消执行；返回前仍复核授权。CLI 非零退出、MCP isError 是业务结果，调用方必须检查。已开始的业务调用不因本地连接器退出登录而丢弃真实结果或已完成收据，但新调用重新检查配置和凭据。

## 凭据管理

`GET/POST/PUT/DELETE /api/connectors/auth?id=...` 复用既有连接器认证管理器，分别查询状态、发起认证、提交 token/OAuth 客户端参数、退出。`component` 参数与既有管理接口一致。

- `GET /api/connectors/auth?id=...&sessionId=...` 查询指定会话。
- `POST /api/connectors/auth/cancel?id=...&sessionId=...` 取消指定会话。

现有 `/api/admin/connectors/auth` 及连接器 connect/disconnect/check 等入口继续保留其原协议。凭据统一保存在 `.state/connectors/<id>`；Agent、管理端和通用执行共用部署级凭据，不提供多租户账号隔离。执行授权不选择账号，认证许可也不隐式授予 execution 权限。

## 幂等与旧收据

有副作用的请求应由调用方提供稳定 `idempotencyKey`（8～128 个字母、数字、点、下划线、冒号、连字符）。未提供时没有去重保证，Platform 不自动重试。

收据继续位于 `.state/connectors/<connectorId>/invocations`，定位摘要保持 `subject + NUL + idempotencyNamespace + NUL + connectorId + NUL + execution-v2 + NUL + key`。`execution-v2` 是固定磁盘兼容盐，不等于当前 HTTP 版本。先独占创建并同步 claim，再派发；同 key 同参数返回已有结果，不同参数返回 `idempotency_conflict`，未完成或破损 claim 返回 `invocation_outcome_unknown`、不派发。执行错误、超时、撤销或落盘失败保持原 claim，不承诺外部 exactly-once。

v2 客户端迁移必须将原 appId **原样**用作 idempotencyNamespace，并保持原 subject、key 和业务参数。这样旧完成收据仍返回旧结果，旧未完成请求仍拒绝重放。不要加入 v3 前缀、改 namespace、换 key 或因升级自动重发；这些都会改变调用方的去重身份。Platform 不删除、重写旧收据，也不替调用方推断旧键。更早 operation 契约的收据不解释为 argv 请求，仍需调用方保留其既有已执行标记并人工对账。

## 传输迁移

旧入口统一返回 HTTP 410 `connector_contract_upgrade_required`，不转发、不颁发兼容 token、不执行旧请求：

| 旧入口 | 新入口 |
| --- | --- |
| `/api/desktop/webapp/grants` | `/api/connectors/execution/grants`，version 改为 3，移除 appId/chatIds，使用稳定 idempotencyNamespace |
| `/api/webapp/connector/{list,describe,invoke}` | `/api/connectors/execution/{list,describe,invoke}`，使用 cxg_ token |
| `/api/desktop/connector/auth`、`/cancel` | `/api/connectors/auth`、`/cancel` |
| `/api/webapp/artifact/{list,get,read}` | `/api/chat/artifacts/{list,get,read}`，使用可信 JWT 和现有 Chat 权限 |

相邻 zenmind-desktop 当前 `src/main/modules/desktop-actions/webapp-connector.ts` 使用旧入口，并检查 wap_ 前缀、appId 回显和 version:2，需同步迁移这些校验、grant 请求、产物请求及撤销地址。页面与资源的授权、运行状态观察和代理取消仍由客户端负责。本仓库不修改相邻客户端；使用这些能力的客户端与 Platform 必须同批发布，旧客户端在新服务上明确失败，不静默扩大授权。
