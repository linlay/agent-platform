# 工具参数错误与恢复提示

Platform 控制准入、Desktop domain 信封、Web 公共字段校验及 `run_status/run_interrupt` 使用结构化参数诊断。已知字段提供预期类型、范围和恢复方法；未知键名和值不回显。

## 诊断契约

`internal/toolinput` 只处理确定的本地输入契约，不做字符串到数字的隐式转换。JSON 整数按 JSON 解码后的数字检查整数性。`1` 和 `100` 有效；`0`、`101`、`1.5`、`"100"`、null 都拒绝。

示例（省略已有外层字段）：

```json
{
  "error": "control_request_rejected",
  "stage": "admission",
  "executionState": "not_started",
  "field": "args.limit",
  "expected": "JSON integer in range 1–100",
  "actual": "string",
  "message": "args.limit requires JSON integer in range 1–100 (actual: string). Set args.limit to 100; example: limit:100.",
  "recovery": {
    "strategy": "fix_input",
    "message": "Set args.limit to 100; example: limit:100."
  }
}
```

缺失值用 `missing`，显式 null 用 `null`，错误数组元素用如 `args.preservePaths[0]`。预期及示例来自静态契约，不包含用户的 content、凭据、环境值或未知键名。未知字段使用安全路径 `args.<unknown>` 和允许字段列表，以去除不受支持的字段；不保存被拒字段原文。

权限检查仍先于平台控制参数校验；不能用更好的报错扩大权限。`catalog_manage` 和 Chat 删除继续要求原有一次性批准；typed error 穿过审批准备通路时仍使用已有 `tool_review_failed` 外层错误码。Desktop 的 unknown_action、action_tool_mismatch 错误码保持兼容。

## 覆盖范围与限制

- 控制动作与枚举从当前服务端定义列出合法值；错误工具的动作提示正确归属。未知 runtimeStatus 组件返回参数错误，已存在但故障的组件继续由状态快照表达。
- `run_status/run_interrupt` 要求非空字符串 runId，interrupt.message 必须为字符串，未知字段拒绝；所有权与禁止链式调用保持独立。链式调用错误需交回发起的普通主 Agent，修改 runId 不能解除限制。
- `run_query`、`run_env`、AWCP 及 revision、游标、源码格式等服务错误各自校验，尚未全部统一到此格式。Web 专用 CDP、坐标与页面 schema 仍由对应模块校验。
- Desktop domain 信封通过不代表看板业务参数已全部验证，也不授予私有运行字段写权限。运行结果由 Desktop 运行生命周期维护；`confirmation_unavailable` 表示确认入口不可用，不能绕过确认。
- 本文不提供第三方 MCP/CLI 的通用 schema 校验，也不改变 Catalog、Plan、挂载或业务授权。

平台控制资源与操作能力见 [平台控制连接器](Platform控制工具设计.md)。
