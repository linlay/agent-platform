# 知识库中心（KBases Center）

知识库中心管理部署级独立知识库，不要求创建 Agent。WebClient 从设置菜单进入 `/kbases`，提供多 collection 新建、列表筛选、详情、名称描述编辑、collection 增删与来源修改、删除、手动更新索引、按集合浏览文档和多种召回测试。

## 存储和职责

配置与运行数据固定从 `AP_RUNTIME_DIR` 派生，不增加环境变量或 YAML paths 配置：

```text
kbases/
  README.md
  example/library.example.yml  # 模板，不加载为实际知识库
  <id>/library.yml             # 人和管理台共同维护的期望配置
ru-kbases/
  libraries/<id>/
    state.json                 # Platform 状态、时间戳、配置指纹
    index.sqlite               # KBX 数据库
    …                          # index.cache.sqlite、lance/、sources/、texts/、tables/、锁等
```

`kbases/` 是配置事实源；`ru-kbases/` 是持久运行数据，由 Platform 和 KBX 维护，不提交、不打包、不手工编辑。**不能按 `ru-*` 通配清理：`ru-agents/` 启动清空重建，`ru-kbases/` 必须跨重启保留。** 停止相关索引任务后，可以显式删除运行目录以重建；下次访问退回 `unindexed`，手动更新会重新创建运行目录。库配置及 source 文档不会因此丢失。

### 配置格式与编辑

```yaml
name: "项目文档"
description: "部署级参考资料"
collections:
  - name: "docs"
    sourcePath: "/absolute/path/to/documents"
```

库 ID 只由目录名决定，接受 1–64 位小写 ASCII 字母、数字、下划线或连字符，以字母或数字开头；管理台创建仍生成随机稳定 ID，手工创建可以使用 `project-docs`。含定义文件但 ID 不合法的目录（例如 `Project-Docs`）在列表显示诊断，须手工改为合法目录名；不会静默忽略。配置只接受 `name`、`description`、`collections`，collection 只接受 `name`、`sourcePath`；未知字段报错，不保存 ID、索引状态、时间戳或模型凭据。使用仓库既有 YAML 子集，拒绝重复映射键。手写时**值一律加双引号**，collections 使用逐行 `- name:` 的块列表，不支持 `collections: [{…}]` 行内列表；数字名称未加引号时返回明确提示。单引号内的 `''` 按 YAML 规则还原为一个单引号。管理台保存会重新生成 YAML，原注释和排版不保留。

一个库可以创建和编辑 1–32 个 collection。集合名称接受 1–64 个 Unicode 字母、数字、下划线或连字符，以字母或数字开头；库内名称与 canonical 源目录分别不能重复。来源是 Platform 主机上现存的绝对目录，加载手写配置和管理台保存时均规范化符号链接及路径。来源暂时离线时，加载会解析仍存在的父目录与符号链接，并核对完成索引的范围；范围一致且最后一次索引完整时仍允许检索、浏览与读取，返回 `sourceWarnings`，同时在 `error` 展示离线提示，状态仍为 `ready`。来源声明或可观察的符号链接目标变化，不得复用旧范围；无法确认身份时须恢复来源后刷新。创建和刷新要求来源在线，刷新前置校验失败不撤销旧索引。已声明的同一来源暂时不可用时，仍允许管理台编辑名称描述。来源不能包含或位于 `kbases/`、`ru-kbases/` 任一根内。原始文档留在 source 目录，不复制成配置目录资源。

配置按请求读盘，没有目录 watcher 或自动索引。一个库 YAML 错误、路径无效、运行状态损坏只使该库返回 `state: error` 与 `error` 诊断，其余库正常显示。详情 GET 同样返回可展示的单库诊断；刷新和检索仍拒绝无效配置。仅含 `library.example.yml` 的示例目录不进入目录列表，无同名运行数据时 GET、PUT、DELETE 和 refresh 同样返回 404；只有包含 `library.yml` 或待诊断的旧 `library.json` 才被视为库配置目录。即使存在同名孤儿运行目录，显式清理也不会删除模板目录。

### 状态、指纹和删除

`state.json` 保存 `createdAt`、`updatedAt`、`indexedAt`、`state`、`error`、`taskFingerprint` 与 `appliedFingerprint`。离线路径通过仍存在的父目录与符号链接解析，再与成功索引的范围指纹比对；不根据未经核对的历史路径直接放行。配置不含时间戳；缺少运行状态时，创建时间退回配置文件修改时间，响应更新时间取配置修改时间和状态更新时间的较新值。

指纹只包含按名称排序后的 **collection 名称与规范化 sourcePath**。路径键、重复检测和根重叠检查复用 `pathutil` 的平台规则：macOS/Windows 路径大小写折叠，macOS 同时使用 NFC；实际传给 KBX 的 Host 路径不改写。已有运行数据的旧指纹若不匹配，需手动刷新。库的展示名称、描述和集合顺序不改变指纹。后续增加 pattern、ignore、chunking 时须把它们纳入指纹；召回默认值不应纳入。当前不接受尚未实现的这些配置字段。

每次刷新冻结集合快照和任务指纹，开始时撤销旧索引的可读状态。成功后只把该快照的指纹记为已应用，不在完成时重读配置计算指纹，也不回写 `library.yml`。任务期间的手工编辑因此不会被覆盖；若当前配置与已应用指纹不同，返回 `unindexed`、`indexedAt: 0` 并拒绝旧范围读取，需再次更新。失败、partial 和中断不恢复为 ready，即使集合范围未变也不恢复旧可读状态：KBX 原地对账可能已改变集合、文本或向量，范围指纹不能证明数据库仍完整。可靠保留旧版本需要另行实现索引副本与成功切换，本次不提供。配置有效但运行状态不存在，或已就绪库的数据库丢失时，同样为 `unindexed`。

损坏或未知状态的 `state.json` 在管理端显示错误，显式刷新可将其作为空状态重新索引；权限错误、非普通文件和符号链接仍拒绝，不作为普通损坏吞掉。创建失败会回滚本次独占创建的配置与运行目录。

管理台显式删除会删除配置目录与对应运行目录，先处理运行数据、再处理配置；每侧先原子改名为同级 `.deleted-<id>-<随机值>`，再递归删除。清理中断残留只在隐藏隔离目录中，不会继续暴露为 ready；若配置尚未移除，其状态退回 unindexed，可重建或再次删除。隔离残留不自动恢复或清理，可在停止相关服务后人工检查清理。坏 YAML 不阻止显式删除；管理台提供完整有效的名称与 collections 时，也可覆盖修复坏配置。手工删除配置或改目录 ID 不触发运行数据清理：管理列表显示 `orphaned: true`、`state: error` 与恢复/删除提示；管理端可显式删除孤儿数据。删除从不触碰原始 source 文档。库目录、运行目录、定义文件、状态文件和数据库不允许符号链接替换。

这是不兼容升级：旧 `kbases-center/` 不再读取，不自动迁移；新配置目录中的旧 `library.json` 会明确报错。旧中心数据可在停止旧服务后删除，按保留的来源目录重建。Agent capability 仍使用 `kbase/<agentKey>/kbx/<scopeHash>/` 或 workspace 存储，本次不迁移或清理；`ru-kbases/agents/` 尚未接入。

`internal/kbasescenter` 负责配置、运行状态、路径校验、CRUD 和任务快照；`internal/kbx.CenterEngine` 调用受管 KBX；App 装配，Server 仅提供 HTTP 映射。`library.yml` 是 Platform 格式，KBX 不直接读取：Platform 用集合维护命令把期望配置对账进运行数据库。模型连接仍来自部署级配置快照，不写入逐库配置，不继承用户目录中的 KBX 配置。

## 索引与召回

新建后是 `unindexed`，手动更新后进入 `indexing`，更新期间拒绝浏览与检索，避免读到尚未完成对账的数据库。先校验所有源目录身份，通过结构化集合目录清理已不在定义中的 collection，再顺序注册新增集合；已有集合先通过 `collection set-path` 对齐来源，再调用 `update -c <name> --no-commands`，新集合调用 `collection add --name <name>`。有 embedding 时继续逐集合 embed 并核验全库向量完整性。注册成功但扫描中断时，重试先判断哪些已经注册，保留已完成的集合。CLI 非成功退出或摘要不完整均进入 `error`，错误带集合名；全部成功进入 `ready`。HTTP 请求结束不取消任务；Platform 停机取消任务，重启后的遗留 `indexing` 显示为中断，需要手动重试。每库同一时刻仅一个更新任务，更新期间拒绝编辑与删除。任务上限 30 分钟。

召回 `method` 缺省为 `query` 综合召回，另支持全文 `search`、向量相似度 `vsearch` 和图检索 `gsearch`；均使用 Agent envelope，前三种获取完整 chunk，图检索沿用其原生证据输出。查询省略集合时覆盖该库声明的全部集合，可用 `collections` 限定一个或多个；未知集合拒绝。返回 KBX chunk、原文、行号、向量相似度及原引用，另从引用解析 `collection` 和 `relativePath` 方便界面展示，不改写片段身份或全局排名，最多 50 条。`query` 按 KBX 可用能力降级，保留真实 trace，页面显示实际通道及降级；严格 `vsearch/gsearch` 不可用时明确失败，页面据 status 禁用未就绪方式。图谱构建尚未接到中心，不宣称完整图谱维护能力。

文件浏览逐集合消费 `ls kbx://<name> --agent` 并合并，返回集合与相对路径。正文引用只能指向当前库声明的集合，不接受父目录跳转或越界引用；读取前 200 行并展示截断提示。没有命中以空结果呈现；KBX 不可用、索引失败和不完整结果不会伪装为正常空库。

本期不提供逐库模型配置、自动监听、上传、知识包导入导出、Agent 挂载或运行期跨进程任务重连。这里只接入独立库的显式手动维护，不改变 Agent capability 现有的目录监听和 maintenance worker 协议。

## 全局模型配置

Platform 从 `configs/runtime.yml` 的 `kbx.embedding.model-key` 和模型 registry 生成私有快照 `<StateDir>/kbx/index.yml`，所有独立库共用。`kbx.embedding.prompt` 支持 `raw` 和 `qwen3`；配置变更重启 Platform 生效。生成文件不应人工维护凭据。

子进程通过 CLI 支持的 `--config` 显式选择文件，并设置隔离的 `KBX_CONFIG_DIR`；不依赖未支持的 KBX_CONFIG_FILE。

未选择 embedding 时默认 `query` 使用可用全文通道；选择后更新索引逐集合追加 `embed -c <name>` 并核验向量完整性，`query` 可使用全文与向量。全文更新成功但向量失败仍返回错误。更换模型后需更新索引，由 KBX 检查向量兼容性。查询扩展、重排及图谱模型尚未配置。

## HTTP 契约

接口沿用 Platform 现有 HTTP 鉴权和 `{code,msg,data}` 包裹，管理中心为部署级资源。

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/admin/kbases | 定义数组，包含单库错误与 `orphaned` 运行数据诊断 |
| POST /api/admin/kbases | `{name,description,collections:[{name,sourcePath}]}` 创建 |
| GET /api/admin/kbases/{id} | 单库定义、状态与最近错误；坏配置返回可展示诊断 |
| PUT /api/admin/kbases/{id} | `{name,description,collections?}` 编辑，允许增删集合及修改名称/来源；省略集合保留当前来源 |
| DELETE /api/admin/kbases/{id} | 删除中心副本，保留源文件 |
| POST /api/admin/kbases/{id}/refresh | 启动后台更新，返回 indexing 定义 |
| GET /api/admin/kbases/{id}/status | KBX 状态数据 |
| GET /api/admin/kbases/{id}/files | KBX 文档目录 |
| POST /api/admin/kbases/{id}/search | `{query,limit,collections?,method?}` 召回，默认数量 10、method=query |
| GET /api/admin/kbases/{id}/read?ref=… | 按 `kbx://<collection>/<relativePath>` 读取正文 |

不存在返回 404，索引期间的冲突返回 409，错误方法返回 405，参数或执行失败返回 400，中心未装配返回 503。查询和读取有 30 秒超时。

## 验证

`internal/kbasescenter` 测试覆盖多集合持久化、目录/名称校验、配置/运行分离、坏配置隔离、手工编辑快照、孤儿目录与运行数据重建、集合范围、删除保留源文件、并发更新拒绝、路径隔离和中断恢复；审计回归覆盖模板入口保护、离线读取与路径改向、失败刷新禁读、坏状态恢复、删除隔离、创建回滚及 YAML/目录 ID 诊断。Server 测试覆盖单/多集合 CRUD、模板入口 404 与 HTTP 错误。`KBX_CENTER_TEST_BIN=<受管 bin 目录> go test ./internal/kbx -run TestCenter -count=1` 在临时库验证首次建库、再次更新、跨集合全文/综合召回、正文读取、文档更新与删除同步，以及本机确定性 embedding fixture 的多集合向量构建和范围过滤。`TestCenterRealSplitStorageLifecycle` 通过真实受管 KBX 验证分离目录建库、检索、删除运行根后重建、真实来源离线后的检索和正文读取，以及删除保留 source。该 fixture 不向外部模型发送用户文档，不代表真实语义质量；完整图谱的查询质量尚未做目标环境验证。

模型注册表的 `embedding.batchSize` 可限制每次向量 HTTP 请求的文本条数，Platform 将其写入全局 KBX 配置的 `models.embedding.batch_size`。省略或为 0 时沿用 KBX 默认值；负数拒绝。接口的批量上限应按所用服务配置，例如本地 text-embedding-v4 接口实测返回过 20 条和 10 条两种限制，部署选用更严格的 10 条。该值不改变源文档或分块策略。

## 召回分数

中心搜索结果 `score` 表示原始查询与 chunk 的向量相似度，`scoreType` 为 `vector_similarity`；没有对应向量评分时为 `score: null, scoreType: unavailable`。综合 query 通过 `--explain` 读取原始查询的 vec contribution.backendScore，不使用扩展查询分数、RRF 分或 `1 / rank`；严格 vsearch 使用 KBX 返回的向量分。纯全文 search、图 gsearch 和综合检索中的纯全文候选不虚构向量相似度。原 KBX 分数保存在 `rankingScore`，结果顺序、chunk/evidence 和 trace 均保留。WebClient 显示“向量相似度”与四位小数，不可用显示 `—`；相似度不代表答案正确率。
