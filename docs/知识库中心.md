# 知识库中心（KBases Center）

中心统一拥有共享库的配置、索引、自动维护和状态。Agent 只绑定一个 libraryId；库内可有多个 collection。WebClient `/kbases` 可管理来源、过滤规则、索引状态和召回测试；新建项目可选库或从目录同时创建库和 Agent。

## 存储和配置

```text
kbases/<id>/library.yml       # 期望配置
ru-kbases/<id>/state.json     # 状态和已应用来源指纹
ru-kbases/<id>/index.sqlite   # KBX 与配套持久数据
ru-kbases/.worker.lock        # 部署调度锁
```

没有 libraries 中间层；`libraries` 保留不可作为 ID。ID 接受 1–64 位小写 ASCII 字母、数字、下划线或连字符，字母数字开头。非库运行目录用点前缀。ru-kbases 必须跨重启保留，不随 ru-agents 清空，也不能按 ru-* 批量清理。

```yaml
name: "研发知识"
description: "AI 建设与研发述职资料"
collections:
  - name: "ai"
    sourcePath: "/Users/linlay/Documents/知识库测试用文档/AI建设文档"
    include:
      - "**/*.md"
      - "**/*.pdf"
      - "**/*.docx"
      - "**/*.pptx"
    exclude:
      - "private/**"
    chunk:
      unit: "chars"
      maxChars: 3600
      overlapChars: 540
  - name: "research"
    sourcePath: "/Users/linlay/Documents/知识库测试用文档/研发中心各条线述职"
```

省略 include 使用七种默认文本/文档扩展名；显式空 include 拒绝。省略 exclude 使用默认值，显式空数组只关闭自定义默认排除，不关闭 KBX 内置安全排除。chunk 省略沿用默认值；自定义必须使用 chars。名称/sourcePath/include/exclude/chunk 及部署强制排除目录进入来源指纹，展示名称/描述及 collection 顺序不改变指纹。更改切块执行全量对账重新发布 chunk；Agent topK 和候选预算不改变指纹。

来源目录在加载与维护前检查 canonical 身份，与 ChatsRoot 分离，禁止读取 StateDir/库配置/运行数据；来源中的 runtime/state 子目录排除。配置按请求读盘，单库错误隔离，手写 YAML 错误显示诊断。仅含 library.example.yml 的模板目录不进入管理操作。来源离线但已应用指纹一致时仍可读取索引，原文件下载需要来源在线。

## 调度、状态和删除

中心自动监听：500ms 合并、五分钟全量对账、启动及中断后重新对账、文件增量更新，每库一个维护任务，全局最多两个。查询与刷新不持有跨库全局锁。手工刷新调用同一维护通路，更新期间编辑/删除返回 409。最长维护 35 分钟。详细 CLI 协议见 [KBX 接入](KBX接入.md)。

普通更新保留读取并标记 stale/indexing，读到的是 KBX 已提交内容，不是固定旧快照。全文已完整而 embedding 失败时可读 degraded；未知 partial 或中断不可读，自动重试。来源、集合、过滤/切块变化立即撤销旧范围读取。刷新只写 state.json，不覆盖 library.yml；外部修改会使旧任务的完成指纹与当前配置不符，从而拒绝读取并重新对账。

删除有引用库返回 409 和引用 Agent 列表；引用关系由 App 注入，中心不 import catalog。管理端 Agent 保存与删库共享 mutation 边界；外部编辑器/Bash 的并发写入不受该边界保护，Run/工具仍逐次重新核验。显式删除移除配置和运行数据，但保留源文件；删除前原子隔离为隐藏 .deleted-* 目录，启动重试清理生成的残留。手工删除 YAML 保留孤儿索引并在列表提示，模板目录受保护。创建回滚只处理本次新建资源。

这是硬切升级：旧 Agent 配置字段和 AP_RUNTIME_KBASE_DIR 明确拒绝。旧 ru-kbases/libraries 布局与旧 Agent 索引目录 runtime/kbase 完全忽略，不进行旧布局检查、不加载、不迁移，也不移动或删除数据。中心按 kbases/<id>/library.yml 配置自动在 ru-kbases/<id>/ 生成索引；需要原有知识时，从来源重建中心库并配置 libraryId 绑定。

## 检索与来源

管理台仍支持 query/search/vsearch/gsearch、collection 筛选和 200 行正文预览。Agent 查询使用完整 Manager 层，保留过滤、minScore、图证据和证据分页；不会复用管理台的薄封装。路径为 collection/relativePath，source ID 包含 libraryId。聊天来源通过专用的 /api/chat/sources/read 和 /file 入口核验已发布引用与当前库绑定，独立于 Workspace 文件权限。

图谱自动构建、逐库模型、上传和知识包导入导出尚未接入。

## 全局模型配置

Platform 从 `configs/runtime.yml` 的 `kbx.embedding.model-key` 和模型 registry 生成私有快照 `<StateDir>/kbx/index.yml`，所有独立库共用。`kbx.embedding.prompt` 支持 `raw` 和 `qwen3`；配置变更重启 Platform 生效。生成文件不应人工维护凭据。

子进程通过 CLI 支持的 `--config` 显式选择文件，并设置隔离的 `KBX_CONFIG_DIR`；不依赖未支持的 KBX_CONFIG_FILE。

未选择 embedding 时默认 `query` 使用可用全文通道；选择后更新索引逐集合追加 `embed -c <name>` 并核验向量完整性，`query` 可使用全文与向量。全文更新成功但向量失败报告 degraded，并保留全文可读。更换模型后需更新索引，由 KBX 检查向量兼容性。查询扩展、重排及图谱模型尚未配置。

## HTTP 契约

接口沿用 Platform 现有 HTTP 鉴权和 `{code,msg,data}` 包裹，管理中心为部署级资源。

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/admin/kbases | 定义数组，包含单库错误与 `orphaned` 运行数据诊断 |
| POST /api/admin/kbases | `{name,description,collections:[{name,sourcePath}]}` 创建 |
| GET /api/admin/kbases/{id} | 单库定义、状态与最近错误；坏配置返回可展示诊断 |
| PUT /api/admin/kbases/{id} | `{name,description,collections?}` 编辑，允许增删集合及修改名称/来源；省略集合保留当前来源 |
| DELETE /api/admin/kbases/{id} | 删除库；有绑定 Agent 时 409，保留源文件 |
| POST /api/admin/kbases/{id}/refresh | 启动后台更新，返回 indexing 定义 |
| GET /api/admin/kbases/{id}/status | KBX 状态数据 |
| GET /api/admin/kbases/{id}/files | KBX 文档目录 |
| POST /api/admin/kbases/{id}/search | `{query,limit,collections?,method?}` 召回，默认数量 10、method=query |
| GET /api/admin/kbases/{id}/read?ref=… | 按 `kbx://<collection>/<relativePath>` 读取正文 |

不存在返回 404，索引期间的冲突返回 409，错误方法返回 405，参数或执行失败返回 400，中心未装配返回 503。查询和读取有 30 秒超时。

## 验证

`internal/kbasescenter` 测试覆盖多集合持久化、目录/名称校验、配置/运行分离、坏配置隔离、手工编辑快照、孤儿目录与运行数据重建、集合范围、删除保留源文件、并发更新拒绝、路径隔离和中断恢复；审计回归覆盖模板入口保护、离线读取与路径改向、失败刷新禁读、坏状态恢复、删除隔离、创建回滚及 YAML/目录 ID 诊断。Server 测试覆盖单/多集合 CRUD、模板入口 404 与 HTTP 错误。`KBX_CENTER_TEST_BIN=<受管 bin 目录> go test ./internal/kbx -run TestCenter -count=1` 在临时库验证首次建库、再次更新、跨集合全文/综合召回、正文读取、文档更新与删除同步，以及本机确定性 embedding fixture 的多集合向量构建和范围过滤。`TestCenterRealSplitStorageLifecycle` 通过真实受管 KBX 验证分离目录建库、检索、删除运行根后重建、真实来源离线后的检索和正文读取，以及删除保留 source。该 fixture 不向外部模型发送用户文档，不代表真实语义质量；完整图谱的查询质量尚未做目标环境验证。

模型注册表的 `embedding.batchSize` 可限制每次向量 HTTP 请求的文本条数，Platform 将其写入全局 KBX 配置的 `models.embedding.batch_size`。省略或为 0 时沿用 KBX 默认值；负数拒绝。接口的批量上限应按所用服务配置，例如本地 text-embedding-v4 接口实测返回过 20 条和 10 条两种限制，部署选用更严格的 10 条。该值不改变源文档或分块策略。

## 召回分数

中心搜索结果 `score` 表示原始查询与 chunk 的向量相似度，`scoreType` 为 `vector_similarity`；没有对应向量评分时为 `score: null, scoreType: unavailable`。综合 query 通过 `--explain` 读取原始查询的 vec contribution.backendScore，不使用扩展查询分数、RRF 分或 `1 / rank`；严格 vsearch 使用 KBX 返回的向量分。纯全文 search、图 gsearch 和综合检索中的纯全文候选不虚构向量相似度。原 KBX 分数保存在 `rankingScore`，结果顺序、chunk/evidence 和 trace 均保留。WebClient 显示“向量相似度”与四位小数，不可用显示 `—`；相似度不代表答案正确率。
