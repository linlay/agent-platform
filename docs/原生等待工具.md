# 原生等待工具

## 挂载与调用

Native Agent 可在 `toolConfig.tools` 显式增加 `sleep`。该工具进入公共工具目录，不依赖 Bash、宿主命令或 Container。也可通过 Platform `preset-tools` 自动挂载到已有 Native Agent，通过 `toolConfig.excludeTools` 排除。ACP/外部引擎不会因此获得此 Native 工具。

模型调用示例：

```json
{"durationMs": 60000}
```

`durationMs` 必填，为 1～86,400,000 的整数，单位毫秒；不接受其他字段。工具描述引导模型用它替代 Bash `sleep`。

## Run 和 steer 语义

- 使用进程内 timer 等待，Run 保持活动的工具执行状态，不进入 HITL/suspended，不创建第二条 Run。
- 正常到点返回 `reason: "elapsed"`，随后当前 Run 的模型循环继续执行。
- 等待中收到已通过现有鉴权与准入校验的 steer，立即唤醒并返回 `reason: "steer"`。开始等待前已经排队的 steer 也会唤醒，不会遗漏。
- sleep 只观察通知，不消费指令。现有模型循环在工具结果之后注入排队的 steer，保留顺序、引用和当前 `runId`。sleep 始终串行执行，不与同一轮的其他工具并行：排在它前面的工具先完成，排在后面的工具在等待结束或被唤醒后才开始。
- 子 Agent（`agent_invoke`、Team 成员）中的 sleep 不被 steer 唤醒：steer 写给根 Run，子任务内的等待按原时长结束或随 Run 取消结束。
- 只读旁聊（BTW / Explain）不开放 sleep，调用返回 `btw_tool_disabled`。
- Interrupt / 父 context 取消停止 timer，返回 `reason: "canceled"` 及 `sleep_canceled` 工具错误，Run 按原取消流程收尾；不触发新的模型调用。
- 跳过普通 `budget.tool.timeout` 和工具重试，避免长等待被默认 30 秒截断或重新开始。仍计入工具调用次数，遵守父 Run 取消与其余预算限制。
- 等待时间计入 Run 总时长（`budget.timeout`，默认 3600 秒）。`durationMs` 超过当前 Run 剩余时长时不开始等待，直接返回 `sleep_exceeds_run_timeout` 工具错误及 `remainingMs`，不发送 `tool.wait`。
- 这是活动进程内等待，不是持久化定时调度；Platform 重启后不会恢复剩余 timer。长时、跨进程任务应使用 automation。

最终 `tool.result.result` 包含 `reason`、`durationMs`、`elapsedMs`、`startedAt`、`deadlineAt`、`endedAt`。绝对时间均为 Unix epoch 毫秒整数；elapsed 使用单调时钟测量实际等待时间。

## WebClient 倒计时协议

实际开始执行后发送一次 `tool.wait`，经既有 SSE / WS / 活动 Run attach backlog 传输：

```json
{
  "type": "tool.wait",
  "runId": "run_1",
  "toolId": "call_1",
  "toolName": "sleep",
  "startedAt": 1790812800000,
  "deadlineAt": 1790812860000,
  "durationMs": 60000
}
```

和其他事件一样，外层附带统一 `seq`、`timestamp`；适用时包含 `taskId`。没有每秒推送，也不把倒计时塞入 stdout。

WebClient 接入约定：

1. 按 `runId + toolId` 关联工具卡片，收到 `tool.wait` 后显示等待状态，并按 `deadlineAt` 在本地刷新倒计时。可用事件 `timestamp` 校正客户端时钟偏差。
2. `tool.end` 只代表参数流结束，不能停止等待卡片；收到唯一的 `tool.result` 才结束等待。数字到零但结果未到时显示“等待结束确认”，不主动发起 query。
3. 等待期间保留向当前 Run 发送 `/api/steer` 的入口。steer 成功后等待服务端结果，不额外创建 query/Run。
4. 收到 Run 终态时停止倒计时。活动 attach 回放先后应用 wait/result，已结束的工具不能重启计时。
5. `tool.wait` 不进入 Chat JSONL、导出和冷回放；历史使用工具参数与最终结果展示实际时长和结束原因，不播放倒计时。

**当前实现范围：** 本仓库已实现服务端工具、通知及事件协议；WebClient 源码不在本仓库，倒计时卡片和输入交互尚需在客户端按此协议接入。
