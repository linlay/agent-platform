# 连接器安装与授权

## 认证类型

新清单的 `connector.json.authMode` 必须显式声明，取值为 `none`、`self`、`token`、`mcp`、`oneid`；长期接受两个别名：`oauth` 等同 `mcp`，`oneid-token` 等同 `oneid`，读取时归一，管理与使用接口只返回规范值。独立的 OAuth 认证模式（显式 `authorizationEndpoint`/`tokenEndpoint`、不经 MCP 发现）已删除，MCP 标准授权中的 OAuth 流程保留。取值区分凭据来源和认证流程，与 `type=cli/mcp/view` 独立。新字段不接受 `null`、空字符串和旧值 `no_auth`、`cli`；本版本对已有包的旧字段、旧默认值和内联表单提供[临时读取兼容](连接器.md#清单临时兼容下个版本移除)，下个版本移除。WorkBuddy 的 `server-side` 需要其云端代管凭据，不支持。Agent、管理端与通用执行共用当前部署的 `.state/connectors/<id>` 凭据，不提供多租户隔离。连接器认证与执行授权独立，详见 [连接器执行协议](连接器执行协议.md)。

| authMode | 凭据来源与获取方式 | 当前行为 |
| --- | --- | --- |
| `none` | 无需认证 | 无需连接配置，Agent 挂载后即可调用；客户端能力、权限与可用性仍在执行时检查 |
| `self` | 连接器自己认证，例如 CLI 登录命令、扫码，或 MCP 依赖本包 CLI 登录 | 不推断无需认证，不阻挡 MCP 初始化；仅显式声明受管 CLI 生命周期时提供管理端登录助手 |
| `token` | 用户在第三方后台生成并手工填写 | 按 `token-schema.json` 校验、保存、查询状态与清除；发送 HTTP 或启动 stdio/Host CLI 时读取，由组件文件中的模板消费 |
| `mcp`（别名 `oauth`） | 用户通过浏览器完成 MCP 标准授权（OAuth 2.1） | 以未认证 initialize 获取 Bearer 挑战并发现资源和授权服务器元数据，使用预注册客户端、Client ID Metadata Document 或动态注册，再执行 PKCE 与刷新 |
| `oneid` | Desktop 企业 SSO 自动提供 | 按调用即时提供 AP_ACCESS_TOKEN；Host CLI/stdio MCP 通过环境变量使用，HTTP MCP 生成 Bearer Header，不保存连接器凭据 |

builtin.dbx 和 builtin.httpx 的认证委托给各自 CLI/Skill，清单使用 `self`，随包不可修改或删除。

`oneid` 复用 Desktop SSO：Desktop 原子写入 `<Desktop dataRoot>/state/desktop/sso-access-token.txt`，启动参数 `--identity-file` 将该文件路径交给 Platform。已验证的单条 oneid Host CLI 子进程与 oneid 的 stdio MCP 在创建进程时即时读取，注入保留环境变量 `AP_ACCESS_TOKEN`；普通 Agent Host Shell 不再继承身份或连接器凭据；不修改 Platform 进程环境。HTTP MCP 无子进程环境，使用同一身份环境生成 `Authorization: Bearer ...`，每次请求重新读取，并严格绑定 HTTPS（默认端口 443）的完整 MCP endpoint。Token 不复制进连接器包、Agent 运行包或 `.state/connectors`。HTTP `headers.Authorization`（Header 名不区分大小写）支持 `Bearer ${ONEID_TOKEN}` 和 `Bearer ${AP_ACCESS_TOKEN}` 两种当前有效的模板，也可省略该 Header，由平台自动生成 Bearer。解析时仅将精确值 `Bearer ${ONEID_TOKEN}` 在内存中归一为 `Bearer ${AP_ACCESS_TOKEN}`，两种模板均使用同一身份文件中的 Token；不改写原包，也不提供 `ONEID_TOKEN` 环境变量。该归一规则不适用于其他 Header、stdio env、static 字段或拼接模板；完整 HTTPS endpoint 限制保持不变。

## 资源包边界

连接器资源包独立于 Platform 发布。平台只读取统一清单与组件配置，不依赖特定来源市场或客户端。分发边界见 [连接器打包与分发](连接器打包与分发.md)。

外部 `connectors-center/` 中的连接器按目录组织；扫描跳过根层普通文件（如 `README.md`、`order.json`）及隐藏条目。目录和符号链接仍执行原有包校验，非法包不会被静默忽略。

## ZIP 导入

`POST /api/admin/connectors/import` 使用现有 Platform 鉴权和 `{code,msg,data}` 包裹。multipart 表单只接受一个 `file`，可选 `overwrite=true`。

调用方可在同一 multipart 表单中提供 `expectedId`、`expectedVersion`，分别约束 ZIP 清单的连接器 ID 和完整 SemVer 版本；两者可独立省略，普通本地 ZIP 导入不需要填写。提供时必须各自只有一个非空、格式合法的值，不裁剪空白或归一化版本。平台在已校验但尚未发布的候选包上做精确比较，不改写清单；不匹配返回 HTTP 409、`data.error.code=connector_identity_mismatch`，不覆盖原包、不触发 Catalog 重载或 CLI 准备。字段重复、为空或格式非法返回 HTTP 400。市场客户端仍应检查安装响应的 ID 和版本；发布前校验需要支持这些字段的 Platform，旧版本不能仅靠客户端发送字段获得此保证。外部连接器发布到 `<AP_RUNTIME_DIR>/connectors-center/<connectorId>/`，版本保留在包内定义，不保留市场版本目录层。

Agent 通过 `catalog_manage.import {resourceType:"connector", archivePath, overwrite?}` 使用相同的包校验与发布能力。后端识别身份、计算 ZIP 与候选整树摘要并绑定当前安装基准；来源读取权限先于包审阅，包发布先于异步 CLI 准备。连接器自带技能保留在 `connectors-center/<id>/skills/`，不会拆成普通 Skill。工具审批与幂等语义见 [平台控制工具](Platform控制工具设计.md#zip-包导入)。

ZIP 支持根目录直接放 `connector.json`，或一层与 id 同名的包装目录。清单决定安装目录；文件名不决定 id。单包上传最多 64 MiB、8192 个条目、解压合计 256 MiB、单文件 128 MiB；拒绝路径穿越、符号链接、特殊文件、大小写路径冲突、Windows 保留文件名及 `builtin.*`。可执行权限保留为 0755，普通文件为 0644。

当前连接器清单没有通用的操作系统/架构兼容性声明，导入不根据 ZIP 文件名推断兼容平台，也不硬拒绝其他平台的合法包。调用者需选取适合目标主机的归档；`installed:true` 仅表示包发布成功，CLI 是否可用仍以准备状态为准。平台兼容性校验尚未交付。

完整包和 MCP key 冲突先校验，之后替换来源并本地 reload。同名包默认返回 409，显式覆盖替换整个目录。本地 reload 失败恢复旧来源；远端服务连接失败只报告不可用，不回滚合法包。当前过程处理普通运行错误，不承诺断电时目录替换的跨步骤事务。

导入与删除临时目录放在 `connectors-center` 的同级目录，不参与后台目录监控或热重载。HTTP 导入、覆盖在 Catalog mutation 边界外解压和静态校验，边界内重新检查已安装资源并发布；定义保存和删除复用该串行边界。目录发布和删除只释放连接器资源根的监听，完成发布或回滚后恢复并做内容差异检查；普通定义保存保持监听。API 已成功加载且内容未再变化时，重复事件和恢复检查不再次重载，其他资源根继续监听。Windows 下这避免监控句柄阻止正式目录重命名，macOS 同样遵循未发布内容不触发重载的边界。删除保持 Agent mutation → Catalog mutation → 连接器 mutation 的锁顺序，引用检查与删除共同受到 Agent mutation 保护。回滚失败保留备份并返回恢复位置，不清理唯一旧副本。

不启动完整服务也可以管理包：

```bash
agent-platform connector-manage import --runtime-dir /absolute/runtime /path/to/example.zip
agent-platform connector-manage status --runtime-dir /absolute/runtime --id example
agent-platform connector-manage login --runtime-dir /absolute/runtime --id example
agent-platform connector-manage logout --runtime-dir /absolute/runtime --id example
agent-platform connector-manage set-token --runtime-dir /absolute/runtime --id example-api --credentials-file /absolute/token-values.json
```

`--runtime-dir` 选择需要管理的部署，原包固定使用该根下的 `connectors-center`；旧 `connectors`、`connector-state` 和包根内状态目录直接忽略，管理命令不自动迁移。状态根只读取环境变量 `AP_RUNTIME_STATE_DIR`，未设置或为空时使用 `<runtime-dir>/.state`；连接器固定使用其 `connectors/<id>` 子目录。独立 CLI 不自动读取 `.env`，应由调用方注入与 Platform 相同的环境；相对状态路径按命令当前工作目录解析。`--state-dir`、`--connectors-center-dir`、`--connectors-dir` 和 `--connector-state-dir` 已移除，传入会报错。CLI 登录输出状态和授权链接，保持前台等待；Ctrl+C 取消。登录、保存 Token 或退出只更新凭证目录，不改写或触碰 connector.json、mcp.json、cli.json。Platform 每秒检查凭证变化，仅更新 MCP Registry 和后台同步，不重建 Agent 运行包。已运行的旧版本 Platform 需要重启到支持授权的新版本。此功能不提供独立授权界面，Platform 现有客户端通过下述 API 发起授权和显示状态。

## MCP 地址导入

`POST /api/admin/connectors/import-mcp` 接受 JSON `{ "mcpUrl": "https://example.com/mcp", "authMode": "mcp" }`，沿用 Platform 鉴权与 `{code,msg,data}` 响应。`authMode` 省略时使用 `mcp`（标准 MCP OAuth），也可显式选择 `none`（无需平台认证，包括服务通过 URL 自行校验访问密钥的情况）；其他模式、空值、未知字段、重复字段和大小写变体均拒绝。请求最多 64 KiB，超限返回 413。

地址必须是完整 HTTP(S) URL，不接受 userinfo 或 fragment；`mcp` 模式要求 HTTPS，仅 localhost、127.0.0.1 与 ::1 可使用 HTTP。导入不访问远端；OAuth 发现、登录与工具可用性检查仍由既有入口负责。`none` 模式允许普通 HTTP，但不推断服务的认证需求。地址会保存到可回显的 mcp.json，不应把私有凭据当作隐藏的 Token 字段。

平台使用小写主机名生成连接器 ID（非法字符替换为 `-`，去除首尾 `-` 与 `.`），显示名为主机名，本地生成包初始版本为 `1.0.0`；此版本仅标识生成的配置包，不代表远端 MCP 服务版本。生成包只包含 connector.json 与 main streamableHttp 组件的 mcp.json。生成与静态校验归 adminsource，发布复用 ZIP 的锁、校验、回滚与 Catalog 重载。成功响应与 ZIP 导入相同。

路径和端口不参与 ID，因此同一主机只能通过此入口导入一个连接器，重复返回 `409 connector_exists`，不覆盖旧包。需要同主机多个服务、其他认证方式或自定义头时使用完整连接器包。WebClient 在连接器导入弹窗提供 ZIP 和 MCP 地址两种方式；成功后刷新并选中连接器，需要 OAuth 时在概览中登录。

## 登录 API

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| POST | `/api/admin/connectors/auth?id=<id>` | 异步开始登录，相同连接器的活动登录幂等复用 |
| GET | 同上 | 查询状态及等待中的授权链接，不回显 CLI 原始输出或 Token |
| PUT | 同上 | token 模式接受 `{ "credentials": { "API_KEY": "用户填写值" } }`，完整替换凭据；mcp 模式可提交 oauthClient 注册信息，与 credentials 互斥 |
| DELETE | 同上 | 清除 token/MCP 授权本地凭据，或执行受管 CLI 退出；不清除 Desktop SSO 或任意 CLI 自管状态 |
| POST | `/api/admin/connectors/auth/cancel?id=<id>` | 只取消登录会话和进程树 |

响应字段为 `connectorId/componentId/sessionId/status/authorizationUrl/userCode/userCodeExpiresAt/message/expiresAt`；`userCode` 只在 CLI 设备码登录时出现。状态包含 `no_auth`、`delegated`、`setup_required`、`unauthorized`、`preparing`、`pending`、`authorized`、`failed`、`canceled`。管理端轮询 GET，当状态为 pending 时打开 authorizationUrl。登录 session 上限 15 分钟，CLI 上游自身的更短超时仍生效；进程重启不恢复等待会话，需重新发起。

## 凭证消费与多组件授权

新包将凭据模板直接写在组件文件里：MCP 写在 `mcp.json` 的 `headers`、`env`，CLI 写在 `cli.json` 的 `env`。旧清单的 `auth_bindings` 在本版本读取时合入内存组件，并保留逐组件 MCP 授权配置和 CLI grant（只接受 mcp 模式的 oauth 字段，显式端点拒绝）；下个版本移除兼容。新组件 `type` 只接受 `streamableHttp` 与 `stdio`；旧清单中的 `http` 本版本读取时转换；WorkBuddy 原包的 `http`、`streamable-http` 或省略 type 需在导入前改为 `streamableHttp`，Platform 不提供转换工具，`sse` 暂不支持。`staticHeaders`/`staticEnv` 已删除，常量直接写入 `headers`/`env`。组件支持布尔 `disabled` 和大小写组件名（大小写冲突拒绝）。

### Token 保存、验证与状态读取

Token 先按 schema 校验，验证使用临时私有凭据目录与 HOME/XDG/tmp；Windows 另将 APPDATA/LOCALAPPDATA 指向候选环境的 config/data，保留系统命令所需的 PATH/PATHEXT/SystemRoot 等基础变量，不继承真实账号的 AppData。验证复用现有 CLI status 或 MCP Initialize/ListTools，不执行业务工具。Token CLI 的结构化认证拒绝与普通执行失败分别处理：INTERNAL_ERROR、网络错误或未知非零退出不能作为密码错误，也不能因输出包含公共 envelope 字段而视为验证成功；这类候选保持待验证，既有凭据不变。明确认证拒绝也可能来自验证码挑战或账号限制，不等同于密码错误；该次候选不能替换现有凭据，解除上游限制后需重新显式提交或检查。单独的 HTTP 403 不能证明凭据无效，仍按 CLI 的结构化错误分类。无独立验证命令且无 MCP 的 Token 配置返回 `configured`。其他认证方式的完成判定保持不变。

明确拒绝凭据时返回错误并保留原值。验证暂时不可用时允许保存到 `.state/connectors/<id>/pending-credentials.json`（0600），返回 `pending_verification`；既有正式凭据不变，候选也不改变配置完成状态；首次配置没有正式凭据时保持未配置，readiness 为 `pending_verification`，业务调用提示使用 Check 验证而不是重新填写。正式提交同时更新凭据、配置完成、认证代次、验证结果并清理候选，任一步失败整体恢复原文件。业务 CLI、Host Bash、stdio 与 HTTP MCP 在凭据锁内读取正式凭据，只会看到提交前或提交后的完整账号；通用 CLI 执行使用与凭据一同读取的版本号，账号在调度期间切换时返回 `connector_auth_expired`。候选校验期间不持有凭据锁，正在使用的账号可以继续执行；提交前重新加锁，校验期间认证代次或候选已变化时放弃提交。显式 `POST /api/connectors/check?id=<id>` 优先验证待验证值，成功后原子替换正式凭据并清理候选。新候选提交会替换旧候选；成功提交正式值也会清理候选。没有有效候选时检查当前值。

验证结果保存在私有 `verification.json`，绑定包认证配置、凭据摘要和退出代次。GET 授权状态与连接器列表只读本地结果，不逐项发起网络请求或启动 CLI。存在候选时返回 `pendingVerification:true`；已有有效正式凭据仍展示其认证状态。Token 保存/显式检查使用已有超时常量；用户取消或退出期间的检查不能以离线保存为由迟到写入。退出会清理正式/待验证凭据和验证结果，但保留其他配置与数据。本次仅提供后端契约，客户端状态展示需要消费这些字段。

静态 Token 的消费示例（字段 API_KEY 必须在 `token-schema.json` 的 fields 中声明）：

```json
// mcp.json
{"mcpServers": {"main": {"type": "streamableHttp", "url": "https://example.com/mcp", "headers": {"X-API-Key": "${API_KEY}"}}}}
// cli.json
{"env": {"SERVICE_TOKEN": "${API_KEY}"}}
```

HTTP MCP 在 mcp 与 oneid 模式下自动注入 Bearer。`cli.json.env` 中 MCP 授权的访问令牌写作 `${OAUTH_ACCESS_TOKEN}`，OneID 写作 `${ONEID_TOKEN}`，在内存中映射到现有凭据来源；`authMode: mcp` 的 CLI 共用本包唯一 MCP 组件的授权，没有 MCP 组件或有多个组件时加载报错，不支持只有 CLI 的 OAuth 包。Token 不放进工具参数、catalog 或原包。

同一连接器多个 HTTP MCP 组件通过 `?component=<组件原名>` 分别登录；省略 component 的 GET 汇总全部组件是否已授权，多组件 POST 必须选择目标。同一连接器同进程只允许一个活动授权会话。所有组件共用 `connector.json.oauth`，不再支持按组件覆盖 OAuth 配置或让 CLI 借用其他组件的 grant。

Host Bash 只在启动已验证的直接连接器子进程时读取本连接器凭据，已启动进程保留环境快照。Terminal 只获得各连接器 `cli.json.env` 的公开值，不获得任何凭据。Container 不通过此链路获得宿主凭据。

自管 CLI 在 `cli.json.env` 中写 `"XXX_CONFIG_DIR": "${CONNECTOR_CONFIG_DIR}"`，指向 `.state/connectors/<id>/config`，由 CLI 自行读写其原生文件。Platform 不猜测任意 CLI 的加密格式或将 Token 拼进参数；仅接受特定文件格式的 CLI 由资源包适配器处理。

OAuth 客户端信息通过 PUT auth API 的 `oauthClient` 写入部署凭证目录，不写入 mcp.json：

```json
{"oauthClient":{"issuer":"https://accounts.example.com","clientId":"registered-client","redirectUri":"http://127.0.0.1:8765/callback"}}
```

更换客户端信息会使本连接器既有 grant 失效，需要重新授权。退出按整个连接器执行，不接受 component 参数。

可选 `clientSecret` 和 `tokenEndpointAuthMethod`（none/client_secret_basic/client_secret_post）；public client 的 none 不接受 secret。命令行使用 `connector-manage set-oauth-client --runtime-dir <root> --id <id> --component <name> --credentials-file <private-json>`，login/status 同样支持 --component。客户端界面需调用这些接口，Platform 不提供新的注册信息表单页面。

实际私有状态继续复用旧文件布局，无需整体目录迁移：

| 文件 | 用途 |
| --- | --- |
| credentials.json | 手工 Token 字段值，0600 JSON，不承诺静态加密 |
| oauth.json | 兼容旧顶层 grant，额外资源保存在 grants；包括刷新票据与目标绑定。已删除的独立 OAuth 流程留下的 grant（未标记 `mcp`）不再匹配，需重新登录 |
| auth-state.json | revision 和退出 generation，不含票据 |
| client-<hash>.json | 按目的地保存预注册或动态注册结果，可含客户端 secret |
| discovery-<hash>.json | 校验后的资源和授权服务器元数据快照 |
| config/ | CLI 原生登录文件；不向 CLI 暴露整个状态目录 |

HTTP 明确返回 401 时最多刷新并重试一次可重放请求；再次拒绝要求重新登录。刷新失败按原因区分：`invalid_grant` 或缺少刷新令牌要求重新登录（`connector_auth_required`）；`invalid_client` 是客户端注册配置问题，保留凭据并返回 `connector_setup_required`；网络、上游或本地凭据存储故障保留凭据并返回 `connector_execution_failed`。403 insufficient_scope 保存所需 scopes，等待用户发起追加授权，不自动弹浏览器。MCP 刷新请求携带 resource，认证层不会因网络错误重放业务请求。票据可用和 MCP tools/list 可用性分别报告。

## 企业 SSO / oneid

清单只声明 `"authMode": "oneid"`（也接受 `oneid-token`），不提供 `token-schema.json` 或 oauth。Host CLI 直接读取 `AP_ACCESS_TOKEN`。stdio MCP 自动获得同名变量；若 SDK 需要其他变量名，可在 mcp.json 使用 `"env": {"SERVICE_TOKEN":"${AP_ACCESS_TOKEN}"}`。这是受管身份来源替换，不读取任意进程环境；`AP_ACCESS_TOKEN` 本身仍不能被 Agent/Skill/连接器配置覆盖。普通 MCP 子进程会清除继承的同名变量，不获得 SSO。

HTTP MCP 默认发送 Bearer Header，也可在动态 headers 中引用 `${AP_ACCESS_TOKEN}`；Authorization 若显式声明，仅接受 `Bearer ${AP_ACCESS_TOKEN}`。禁止在 URL、静态字段或其他占位符中使用 SSO。`platform.authSource` 只能出现在 `authMode: oneid` 下；旧包依靠 `identity-file` 自动归为 OneID 的行为已删除，需在清单中显式声明。

授权状态只表示当前 Desktop Token 是否可用，不验证上游权限。GET 返回 authorized/unauthorized；缺失、为空或非法时提示登录 Desktop，不阻止 Platform 启动。此模式不支持连接器的手工 Token 写入、交互登录或退出；SSO 登录/退出由 Desktop 管理。Token 更新后，HTTP 下次请求读取新值；stdio 下次调用检测身份变化并关闭旧 session、以新环境创建进程。Desktop 删除 Token 后，新的 MCP 调用拒绝执行，旧 stdio session 回收；已启动的普通 CLI 进程保持其启动时环境。

独立 `connector-manage status` 默认读取 `<有效 StateDir>/identity/access-token`；使用 Desktop 管理的部署时，传入与 Platform 启动参数相同的 `--identity-file /absolute/path/sso-access-token.txt`。管理命令只读取这个文件，不复制、不刷新、不删除它。Terminal、Container、Proxy、ACP、LSP 与 sidecar 不通过此链路获得 Token。

## 静态 Token

`authMode: token` 必须提供 `token-schema.json`，其他模式不得提供。结构沿用 WorkBuddy：顶层 `title`、`description`、`docLabel`、`docUrl` 与 `fields`，多语言写在 `i18n.<语言>` 中（`title`、`description`、`docLabel`）。每个字段定义 `key`、`label`、`type`（text/password，默认 password）、`required`，可带 `placeholder`、`description`、`i18n.<语言>`（`label`、`placeholder`、`description`）；text 可带公开 `defaultValue`，password 禁止默认值。key 必须是唯一的大写字母、数字、下划线标识，以字母开头；旧 `name` 字段和 WorkBuddy 的 `title_en`、`label_en` 等后缀写法拒绝，需改写为 `i18n.<语言>`，Platform 不提供转换工具。校验错误指明文件、字段序号或 key 及原因，例如 `fields[1].key "TOKEN" is duplicated`；遇到 `_en` 后缀字段时提示改用 `i18n.<语言>`。保存接口只接受声明字段，检查必填、单行和每字段 64 KiB 上限，不验证第三方业务权限。PUT 请求上限 1 MiB，拒绝重复字段、未知请求属性与尾随 JSON。CLI 的 credentials-file 使用字段值对象 `{ "API_KEY": "用户填写值" }`，不使用内联命令参数传 Secret。

凭据原子写入 `.state/connectors/<id>/credentials.json`（0600），GET 只返回是否配置。HTTP MCP 的动态 headers/query 每次请求读取当前文件；query 只允许值中出现 `${KEY}`，替换后逐项 URL 编码，不允许凭据决定 host/path/query 参数名。源码 URL、catalog、SDK 原请求和错误保留模板，退出后旧 HTTP session 不能继续使用已删除的 Token。stdio env 在连接前解析，凭证变化重建实例；Host CLI 在启动已验证的直接连接器子进程时，按 `cli.json.env` 中引用凭据的模板读取票据并注入。自带认证的 CLI 使用 `authMode: self`。用户填写的就是已从上游取得的 Token/API Key，表单提交不执行换票。

## CLI 准备与隔离

CLI 准备与认证独立。HTTP ZIP 导入在原子发布和本地重载成功后异步准备 CLI；`installed:true` 只表示来源包已导入，响应另附 `preparation`。初始化失败保留包，不回滚脚本已产生的外部副作用。独立 `connector-manage import` 则等待准备完成；失败明确报告包已导入但 CLI 准备失败。可用 `connector-manage prepare --runtime-dir /absolute/runtime --id example` 显式重试。

| CLI 包内容 | 准备行为 |
| --- | --- |
| 有 `bin/` | 不执行 init，只从包内解析命令并检查版本；空 bin、缺失入口或版本不合格直接失败，不回退全局同名程序 |
| 无 `bin/`，有 init | 原样执行当前操作系统脚本，npm 全局安装落入私有安装目录，再检查版本；有 init 必须声明 versionCheck |
| 无 `bin/`，无 init | 有 versionCheck 时检查环境中的既有命令；都没有时只记录包指纹，不安装程序 |

`cli.json.init` 是唯一安装事实源，支持多行、条件、管道和重定向。macOS/Linux 使用 Bash，Windows 使用 cmd.exe 批处理；需要 PowerShell 等解释器时由 init 显式调用。工作目录是已发布的连接器源码目录，不重设 HOME，也不改写安装版本。init 运行时 `npm_config_prefix` 指向本次安装目录 `<AP_RUNTIME_DIR>/connector-installs/<id>/<版本>/<准备前的包指纹>/`，`npm_config_cache` 指向共享的 `connector-installs/.npm-cache`，因此 `npm install -g` 不写入用户全局目录；其他安装方式（curl、pip 等）不受影响，仍装到脚本指定的位置。HOME 保持用户真实目录，`~/.npmrc` 的镜像、代理和私有源照常生效；不支持配置目录变量的 CLI 仍把登录写在用户 HOME。init 未锁定 npm 精确版本时准备照常成功，状态消息给出警告。`npmRegistry`（单个）或 `npmRegistries`（有序列表，二选一，均为 https）通过 `npm_config_registry` 依次尝试，仅在输出含网络类错误时换下一个源；不声明时沿用用户自己的 npm 配置。Node runtime 声明只检查前提，不安装 Node。

受管入口由 `versionCheck.command` 的第一个词推出（Windows 去掉 `.cmd`）；第一个词是解释器或启动器（bash、sh、env、node、npx、python、powershell 等）或路径时，包没有受管入口，生命周期照常执行，但不提供直接 CLI 调用。准备通过 `minVersion` 和可选 `versionPattern` 检查版本，第一捕获组提取版本。`cli.json.platform` 允许保留但整体忽略，不参与安装、入口解析或环境变量配置。

生命周期命令（init、versionCheck、auth、skipIf、status、unAuth）与 WorkBuddy 一致，按操作系统 Shell 执行：macOS/Linux 用 Bash（缺失时 sh），Windows 用 cmd.exe 批处理；可以使用 `$VAR`、管道、`node -e` 和 `powershell -File`。导入包即信任这些命令。业务调用仍只启动受管入口并直接传 argv，不经过 Shell。

新增 HTTP 接口 `/api/admin/connectors/prepare?id=<id>`：GET 查询，POST 准备或重试，DELETE 取消。返回统一 JSON 包裹，data 包括 connectorId、status、fingerprint、stage、message、exitCode、diagnostic、activeVersion、activeFingerprint、updatedAt；可选字段按需出现。状态为 pending/preparing/ready/failed/canceled，连接器列表附带不含过程诊断正文的 preparation 摘要。GET 不执行 CLI；无记录返回 pending，包变更要求重新准备。diagnostic 是安装或版本检查输出的末尾摘录（最多 4096 字符），去除 Basic/Bearer/npm `_authToken`、URL 中的用户名密码和控制字符。

### 当前可用安装

准备成功后写入 `connector-installs/<id>/active.json`：版本、包指纹、安装目录和受管入口的路径与 SHA-256。之后的准备失败、取消或尚未准备的新版本都不替换它：生命周期、业务调用、Host Bash 与 Terminal 继续使用这份安装，准备状态以 `activeVersion` 报告正在使用的旧版本，readiness 不因此变为 unavailable。每次准备（包括同一包的重试）都装进新的独立目录，失败目录随即删除；成功后只保留新的当前安装和仍被 Agent 版本或 Run 持有租约的安装，其余在准备成功和 catalog 重载时回收；准备成功后自动重载 catalog，Agent 的 PATH 与入口随之更新；Windows npm 启动器连同它实际执行的脚本一起固定 SHA-256；删除连接器时同时清空 `connector-installs/<id>` 与有效状态根 `connectors/<id>` 的全部内容，重新导入需重新准备和登录；完整清理失败通过 `connector_cleanup_pending` 报告并允许重复 DELETE 重试。

活动安装的 bin 目录加入挂载该连接器的 Agent 的 Host Bash 与 Terminal PATH（在包内 bin 之后、npm 全局目录之前），因此复合命令也能找到 CLI。其中的入口与包内 bin 一样在 catalog 发布时冻结路径和 SHA-256，直接调用免入口审批、Token 模式可接收凭据；校验按入口所属安装目录进行，连接器取消挂载或入口内容变化即失效。Container 不挂载安装目录。生命周期命令与 Host Bash 使用同一份 `bash.inherit-env` 继承的宿主环境。

准备状态原子保存到 `<AP_RUNTIME_DIR>/connector-installs/<id>/preparation.json`，不再放在 `.state`（旧文件在下次保存时删除，升级后需重新准备）。任务最长 15 分钟；同进程重复请求合并，跨进程通过 OS 锁与来源导入、编辑、删除和 CLI 登录互斥，占用返回 409；业务调用（含 VIEW 查询）不取该锁，只在执行期间租用所用安装目录。`<AP_RUNTIME_DIR>/.lock/connectors/operations/<id>.lock` 只用于 OS 锁，不含凭据；进程退出会释放锁。重启后首次查询将未完成记录标记为 canceled，等待显式重试，不自动重放 init。取消不代表脚本外部副作用已经撤销。由独立管理进程持有的任务不能被另一进程直接取消，应在任务所属进程中取消。

### Host PATH

Platform 以实际运行账号及环境中的 `npm prefix -g` 探测全局命令目录：macOS/Linux 为 `<prefix>/bin`，Windows 为 `<prefix>`。结果按环境缓存，启动时预热、init 完成后刷新；找不到 npm 不阻止服务启动或非 npm CLI。非 npm 自定义目录需要由部署环境提供 PATH，不增加 pathCommand 等新字段。

Host 使用顺序为：当前 Agent 已挂载连接器 bin → 已挂载连接器的活动安装 bin → Platform builtins/bin → 基础 PATH → 尚未包含的 npm 全局命令目录。已存在的 npm 全局目录保留原位置，不提升优先级，确保 Desktop 等宿主显式提供的 Node/npm 优先于系统运行时。生命周期、Host Bash、Terminal 和 stdio MCP 采用同一目录机制；默认 Bash 不读取登录 profile，PATH 由审查环境提供；已挂载连接器 `cli.json.env` 的公开值（含配置目录）注入所有 Host Bash 命令与 Terminal，Agent 配置或 run env 不能覆盖；凭据只注入已验证的直接连接器子进程。npm 全局目录不授予免审权限；包内入口和活动安装入口按快照授权。Container 不注入宿主 npm 路径或凭据，容器 npm 自动探测未实现。

### 独立凭据与升级

配置目录写在 `env` 里：

```json
{"env":{"EXAMPLE_CLI_CONFIG_DIR":"${CONNECTOR_CONFIG_DIR}"}}
```

Platform 向生命周期命令和已挂载连接器的 Host Agent/Terminal 注入这些公开值。Agent 配置或 run env 不得替换它们；不同连接器声明同名 env 冲突时在 catalog 装配时报错。退出不删除全局程序，也不使用用户默认 CLI 凭据目录。`unAuth` 为空字符串表示没有 CLI 原生退出；需要清理配置目录时在 `unAuth` 中显式写删除命令。

CLI 登录是幂等的“确保可用”：外部包没有可用安装（未准备、安装目录被删除或受管入口摘要不符）时，登录在同一会话内先准备再授权，会话依次为 `preparing`（message `Preparing CLI`）、`pending`、`authorized`/`failed`；准备已在进行时登录加入该准备而不返回占用，重复发起返回同一会话；取消登录（含退出）只取消由该登录发起的准备，加入的准备归原发起方（如导入），继续执行。用户点击登录即视为同意执行 init；状态查询、退出、Check 和业务调用不调用 init。认证状态 GET 与 `/api/connectors/connection` 的 authentication 使用同一判定与同一结果：没有可用安装时返回 `setup_required`，message 按当前准备状态说明需要准备、准备中、失败或已取消；缓存的登录结果和此前失败的登录会话都不能掩盖缺失的 CLI；登录正在准备时两者都返回该会话。管理接口与业务执行（含执行前状态检查和启动受管入口）对没有可用安装统一返回 409 `connector_preparation_required`。

### 登录与状态判定

`auth` 可以是 OS 命令表，也可以是有序步骤数组 `[{command, skipIf, authUrlDomain, authWaitForExit, authSuppressBrowser, authDeviceFlow}]`；步骤里未写的字段继承顶层同名字段。`skipIf` 成功退出时跳过该步，其输出全部丢弃。

| 字段 | 行为 |
| --- | --- |
| `authUrlDomain` | 只采用该域名（含子域）的 https 授权链接；不写时采用第一个 https 链接 |
| `authWaitForExit` | 默认 false：输出授权链接后结束该步进程，所有步骤后每 3 秒查询 status，最长 5 分钟；true 时等待命令退出，非零退出即登录失败 |
| `authSuppressBrowser` | true 表示 CLI 自己打开浏览器，Platform 不返回 `authorizationUrl`，避免重复打开 |
| `authDeviceFlow` | `uriPattern`（必填）、`codePattern`、`defaultExpiresInSeconds`（30–3600，默认 300）、`codeEmbeddedInUri`；取第一捕获组，会话返回 `authorizationUrl` 与 `userCode`，并总是等待命令退出 |

`status` 退出码为 0 才可能已登录；`statusMatch`（对 stdout+stderr 的正则）与 `statusMatchJson`（stdout JSON 子集，支持 `{ok,data}` 包裹，字符串期望值也匹配打印相同的布尔/数字）任一匹配即已登录，二者都不写时只看退出码。非零退出表示未登录；126、127、9009 表示命令无法启动，按检查失败处理而非未登录。Token 模式可以只声明 status 用于验证候选凭据；`auth`、`unAuth` 与登录行为字段只允许 `authMode: self`。

`mcp.json` 顶层 `"preAuth": "cli"` 要求 `authMode: self` 且 cli.json 声明 auth：CLI 登录状态为已授权前，本包 MCP 组件不启动，登录或检查成功后自动重建。

从旧启动器包迁移到无 bin 的安装命令型包时，需显式覆盖导入；不自动删除、猜测改写用户 bin。旧 `.state/connectors/<id>/npm` 与此前装进 npm 全局目录的程序都不再使用，也不自动清理，已有 config 凭据继续复用；升级后每个 CLI 连接器需要重新准备一次。服务端接口已提供；客户端可直接发起登录由服务端完成准备，也可先调用 preparation 接口展示安装进度与重试。

## MCP 标准授权

`authMode: mcp`（别名 `oauth`）按 MCP 授权规范完成 OAuth 2.1 授权，通过官方 Go MCP SDK 校验元数据并要求 PKCE S256。独立 OAuth 模式已删除：`oauth` 块中的 `authorizationEndpoint`、`tokenEndpoint` 加载时报错并说明端点由 MCP 发现获得；只有 CLI、没有 HTTP MCP 组件的包和 stdio MCP 组件不支持此模式。

oauth 块可省略，只接受 `resourceMetadataUrl`、`scopes`、`clientId`、`resource`、`issuer`、`clientMetadataUrl`、`redirectUri`；其他字段（含旧 `discovery`）报错并列出允许字段。oauth 内部字段与清单一样使用小驼峰，授权服务器协议本身的字段（如注册响应的 client_id）不受影响。优先使用部署或包内预注册 clientId；其次使用服务器支持的 HTTPS Client ID Metadata Document（须配置与文档匹配的 redirectUri）；否则动态注册并保存结果供后续登录复用。均不可用时提示配置客户端信息。

```json
{
  "authMode": "mcp",
  "oauth": {
    "resourceMetadataUrl": "https://mcp.example.com/.well-known/oauth-protected-resource",
    "scopes": ["documents.read"]
  }
}
```

发现顺序：

1. 声明了 `oauth.resourceMetadataUrl` 时直接读取。
2. 否则向 MCP endpoint 发送未认证的 `initialize` POST（带组件 `headers` 中的常量值，含 `${...}` 模板的凭据头不发送），从 401 的 `WWW-Authenticate: Bearer resource_metadata=...` 读取元数据地址和 scope。部分服务对 GET 返回 200 或 405 且不带挑战（如腾讯地图网关、flova），因此不使用 GET 探测。只读取状态码和响应头，响应体不读取直接关闭，保持连接的 SSE 响应不会阻塞发现；服务意外接受未认证 initialize 并返回 `Mcp-Session-Id` 时立即 DELETE 关闭。
3. 没有挑战时按 RFC 9728 依次尝试路径插入式 well-known 地址和根地址；非 2xx 都视为不可用继续尝试，2xx 但内容无效或 resource 不匹配直接报错。
4. 授权服务器发现复用 SDK 的 OAuth Metadata / OIDC 回退；多个 issuer 可通过 `oauth.issuer` 选择，默认第一个。

发现失败时，登录状态的 `message` 给出原因并列出每个请求的方法、URL 和 HTTP 状态。所有诊断文本（message、steps、报告字段、SDK 与网络错误）中的 URL 都去掉 userinfo 和 fragment，query 显示为 `?[redacted]`，避免泄露写在地址里的 API Key。已知地址（组件 URL、元数据、issuer 与授权服务器端点）先解析再脱敏，无法解析时只保留 scheme，并替换错误文本中的原样或转义形式；其余文本中的 query 一直脱敏到下一个空白，query 中的引号和尖括号不会提前结束脱敏，例如 `...; requests: POST https://.../mcp -> 200 (no Bearer challenge); GET https://.../.well-known/oauth-protected-resource/mcp -> 404`；不包含凭据、头部值或响应体。

### 登录前的授权发现检查

本地导入校验不访问网络，不能证明远端授权可以开始。`POST /api/connectors/check?id=<id>[&component=<name>]` 对未授权的 mcp 组件执行与登录相同的发现，但不打开浏览器、不注册客户端、不保存任何状态；多组件且未指定 component 时提示选择组件。检查直接读取已保存的授权，不复用已结束（failed/canceled）登录的缓存状态，完成后只取代检查开始时观察到的那次已结束登录；检查期间新发起的登录保留自己的结果，进行中的登录仍返回其进度。响应在原 Session 字段外增加 `discovery`：

| 字段 | 含义 |
| --- | --- |
| `status` | `passed` 或 `failed` |
| `code` | 失败分类：`discovery_request_failed`、`resource_metadata_not_found`、`invalid_resource_metadata`、`invalid_metadata_url`、`authorization_server_missing`、`issuer_not_advertised`、`insecure_authorization_server`、`authorization_server_metadata_not_found`、`client_registration_unavailable`、`pkce_s256_unsupported`、`invalid_configuration`、`invalid_component` |
| `message` | 含具体地址和原因的说明 |
| `resourceMetadataUrl`、`resource`、`issuer` | 发现到的元数据地址、授权 audience 和授权服务器 |
| `clientRegistration` | `configured`（包内或部署保存的客户端）、`client_metadata` 或 `dynamic` |
| `scopes` | 与登录实际申请的 scopes 相同：待追加授权（insufficient_scope）记录的 scopes 优先，其次初始 Bearer 挑战中的 scope（MCP 规范要求），再次包内 `oauth.scopes`，最后元数据 `scopes_supported` |
| `steps` | 每个请求的 method、url、status 与 result |

`platform_inspect.checkConnector` 在 mcp 模式缺少授权时同样执行发现，结果放在 `authorization` 阶段：通过时整体为 `authorization_required` 并给出登录入口；失败时整体为 `failed`，只返回 `code` 与不含地址的说明，不引导用户登录。

动态注册始终申请 `authorization_code`；服务器显式声明 `grant_types_supported` 且不包含 `refresh_token` 时不申请刷新，包含或未声明该字段时保留刷新申请，以兼容省略元数据但支持刷新的服务。没有刷新令牌时，访问令牌过期需重新登录。注册的结构化 HTTP 400 错误在当前授权 Session 的 `message` 中返回截断后的错误码和说明；其他注册错误保留通用提示，不透传响应体，错误详情不持久化。

resource 是授权 audience，默认使用 MCP URL；允许显式声明其他 HTTPS 资源标识，例如 resource 为 `https://api.example.com`、MCP endpoint 为 `https://api.example.com/mcp`。元数据必须匹配声明的 resource，实际 Token 发送目的地仍严格绑定 MCP endpoint 的 scheme/host/path/query，不能借 resource 扩大范围。mcp 模式不能混用 mcp.json 的 Authorization header 或 platform.authSource。

授权使用随机 state、PKCE S256 和本机 loopback callback，授权与换取 Token、刷新请求都携带 resource 参数，浏览器必须能够访问 Platform 所在机器。默认监听临时 `127.0.0.1` 端口；预注册客户端如需固定回调，可提供 `oauth.redirectUri`，仅接受 `http://127.0.0.1:<port>/<path>`。授权配置、Token、resource 与请求目的地以 0600 原子持久化至 `.state/connectors/<id>/oauth.json`，父目录 0700；保留旧单资源顶层结构，额外资源放在 grants 中，按 resource + destination 隔离。每次 MCP 请求读取当前凭据，过期时跨进程加锁刷新并持久化 refresh token；本地 catalog 不等待网络或刷新锁。退出删除全部本地 grant，保留客户端注册信息和发现缓存；auth-state.json 的 generation 阻止退出前的迟到登录恢复票据。取消只影响当前管理进程的待完成登录。连接器删除使用状态根外置于 ID 目录的稳定锁和删除代次，先停止在途任务再清空整个 ID；独立管理进程与 Platform 必须统一升级到新锁协议，旧回调和刷新不得在重新导入后恢复原授权。

认证按部署共享，未实现不同 Platform subject 的独立账号绑定。登录成功表示 CLI 或 MCP 授权凭据获取成功；MCP 后台 tools/list 的服务可用性、SDK 支持的协商版本和业务侧权限仍需单独检查，不把登录成功等同于所有工具均可调用。Platform 优先请求 `2025-11-25`，也接受 `2025-06-18`、`2025-03-26` 和 `2024-11-05`，服务返回支持的旧协议版本本身不会使同步失败；上游 HTTP 429 限流仍会独立报告。

## 授权页面展示

`connector.json.authBrowser` 决定展示策略，允许 `system` 和 `embedded`，未配置时为 `system`；WorkBuddy 原包的 `cli.json.authQrModal` 允许保留，Platform 忽略该字段，不据此推断或覆盖 `authBrowser`，无需改写原始 `cli.json`。Platform 在创建会话时固定策略，通过 start/status 的 `authBrowser` 返回；CLI 输出只提供授权链接，不能改变展示策略。

WebClient Standalone 在 embedded 模式使用模态 iframe；Desktop 内的 WebClient 通过受限宿主 bridge 打开隔离的模态 WebView。只有用户发起或继续的会话打开弹窗；观察状态不自动弹窗。成功以 Platform 状态为准，页面加载与跳转不能确认认证成功。内嵌失败不自动打开系统浏览器。

取消接口允许携带 `sessionId`，Platform 在同一锁内核对身份后取消，旧弹窗不得取消替换会话。CLI 继续由包配置非交互和禁止自行打开浏览器的参数；展示配置不能阻止不遵守该契约的 CLI 自行打开浏览器。

## Desktop 原生连接器

`builtin.platform-control` 与 `builtin.web-control` 使用 `native` 组件和 `authMode: "none"`。无需 Token、Connect 或 connection.json；每次调用仍检查 Agent 受信任挂载、Desktop 路由、审批及能力条件。分别自动导入 `platform-control`、`web-control` 技能和各自的工具，不自动授予 Bash。详见 [共享包与 Desktop 迁移](连接器共享包与Desktop迁移.md)。


## authMode none 的状态与客户端接入

`none` 与 `self` 是独立语义，不根据 builtin 身份推断。`none` 不允许与 `token-schema.json`、oauth 块、authBrowser、CLI auth 或 MCP platform.authSource 混用。下文的 `no_auth` 是状态值，不是清单取值。CLI 安装准备仍独立执行。

`GET /api/connectors/connection` 返回 `configurationRequired=false`、`configured=false`、`authentication.status="no_auth"`；无需准备或准备完成时 `readiness="no_auth"`，CLI 尚未准备时仍返回 preparing/setup_required。这些值不表示客户端在线或业务端可达。`canConnect/canDisconnect/canCheck` 均为 false。客户端应显示“无需配置”并隐藏认证操作，不可仅按 configured=false 显示“未连接”。WebClient 的 Composer 与连接器管理页按 no_auth 展示无需配置，复用通用认证展示，不保留 Desktop 专用配置流程。

对 no_auth 调用 connect/disconnect/check 返回 HTTP 409、`connector_auth_not_required`，不生成配置状态。取消 Agent 使用资格通过移除挂载完成；通用连接器执行仍要求 execution grant。Desktop 使用当前 API；本版本仅保留上述清单读取兼容，不恢复旧配置状态或旧 API。
