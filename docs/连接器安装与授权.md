# 连接器安装与授权

## 认证类型

`connector.json.auth_mode` 接受五个值，实际对应四类认证机制；`type=cli/mcp` 是连接器组件类型，与认证类型分开。

| auth_mode | 当前行为 | 典型用途 |
| --- | --- | --- |
| none | 无需 Platform 托管的交互登录，可直接使用已配置组件 | builtin.dbx、builtin.httpx |
| cli | 根据 cli.json 准备 CLI、执行登录、查询状态和退出；凭据保存在独立目录 | 企业微信、腾讯会议 |
| token | 要求 token_schema；MCP 从部署级 credentials.json 解析 headers/env 模板 | API Key、静态 Token、已有凭据迁移 |
| oauth | 要求 oauth 配置；发现元数据、动态注册、PKCE、回调和令牌刷新 | 腾讯文档、通达信 |
| mcp | 根据单个 HTTP MCP 服务自动发现认证，复用 OAuth 流程，无单独 oauth 配置块 | 提供标准认证发现的 MCP 服务 |

`token` 当前支持凭据读取与注入，尚无通用凭据填写/保存 API，不能使用交互登录接口。`mcp` 不是另一套登录协议；需要指定 scopes 或元数据地址时使用 `oauth`。按用户隔离账号尚未实现，当前认证属于部署级状态。

| id | 类型 | 授权 | 技能 |

| tencent-docs | HTTP MCP | OAuth 发现、动态注册、PKCE | 无 |

执行 `python3 scripts/package-workbuddy-connectors.py --source /path/to/workbuddy/connectors`，生成 `build/connectors/{tmeet,tencent-docs,tdx-connector,wecom}.zip`、展开包和 `sha256.json`。ZIP 内容稳定排序且固定时间戳；不复制 WorkBuddy 的用户配置或凭据。CLI 固定为 `@tencentcloud/tmeet@1.0.16` 与 `@wecom/cli@1.2.0`。MCP timeout 明确采用 Platform 毫秒单位，腾讯文档 60000、通达信 30000。

## ZIP 导入

`POST /api/admin/connectors/import` 使用现有 Platform 鉴权和 `{code,msg,data}` 包裹。multipart 表单只接受一个 `file`，可选 `overwrite=true`。

ZIP 支持根目录直接放 `connector.json`，或一层与 id 同名的包装目录。清单决定安装目录；文件名不决定 id。单包上传最多 64 MiB、8192 个条目、解压合计 256 MiB、单文件 128 MiB；拒绝路径穿越、符号链接、特殊文件、大小写路径冲突、Windows 保留文件名及 `builtin.*`。可执行权限保留为 0755，普通文件为 0644。

完整包和 MCP key 冲突先校验，之后替换来源并本地 reload。同名包默认返回 409，显式覆盖替换整个目录。本地 reload 失败恢复旧来源；远端服务连接失败只报告不可用，不回滚合法包。当前过程处理普通运行错误，不承诺断电时目录替换的跨步骤事务。

不启动完整服务也可以管理包：

```bash
agent-platform connector-manage import --runtime-dir /absolute/runtime /path/to/tmeet.zip
agent-platform connector-manage status --runtime-dir /absolute/runtime --id tmeet
agent-platform connector-manage login --runtime-dir /absolute/runtime --id tmeet
agent-platform connector-manage logout --runtime-dir /absolute/runtime --id tmeet
```

`--runtime-dir` 选择需要管理的部署，原包固定使用该根下的 `connectors-center`，旧迁移来源固定为 `connectors` 和 `connector-state`。状态根只读取环境变量 `AP_RUNTIME_STATE_DIR`，未设置或为空时使用 `<runtime-dir>/.state`；连接器固定使用其 `connectors/<id>` 子目录。独立 CLI 不自动读取 `.env`，应由调用方注入与 Platform 相同的环境；相对状态路径按命令当前工作目录解析。`--state-dir`、`--connectors-center-dir`、`--connectors-dir` 和 `--connector-state-dir` 已移除，传入会报错。CLI 登录输出状态和授权链接，保持前台等待；Ctrl+C 取消。登录或退出完成后原子重写内容不变的 connector.json，唤醒标准来源 watcher。已运行的旧版本 Platform 需要重启到支持授权的新版本。此功能不提供独立授权界面，Platform 现有客户端通过下述 API 发起授权和显示状态。

## 登录 API

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| POST | `/api/admin/connectors/auth?id=<id>` | 异步开始登录，相同连接器的活动登录幂等复用 |
| GET | 同上 | 查询状态及等待中的授权链接，不回显 CLI 原始输出或 Token |
| DELETE | 同上 | 取消活动登录，清除本部署登录状态并 reload |
| POST | `/api/admin/connectors/auth/cancel?id=<id>` | 只取消登录会话和进程树 |

响应字段为 `connectorId/sessionId/status/authorizationUrl/message/expiresAt`。状态包含 `not_required`、`setup_required`、`unauthorized`、`preparing`、`pending`、`authorized`、`failed`、`canceled`。管理端轮询 GET，当状态为 pending 时打开 authorizationUrl。登录 session 上限 15 分钟，CLI 上游自身的更短超时仍生效；进程重启不恢复等待会话，需重新发起。

## CLI 准备与隔离

宿主需要预装 Node.js/npm；tmeet 要求 Node >=14，wecom 要求 Node >=18。Platform 只安装 `cli.json.platform` 明确声明的 npm 包与固定版本，使用独立 prefix/cache，关闭 lifecycle scripts，不执行原 WorkBuddy 的全局 `init` shell 命令。`auth/status/unAuth` 只接受同一受管 CLI 的单条命令，不接受复合命令、重定向、变量展开或命令替换。

认证执行完全由配置声明，不按连接器 id 硬编码：`runtime` 检查 Node 主版本，`versionCheck.command/minVersion/versionPattern` 检查 CLI，`auth` 启动登录，`authUrlDomain` 限定返回链接，`status/statusMatch` 判定真实登录状态，`unAuth` 或 `platform.logoutMode` 退出。版本命令省略时使用 `--version`；`versionPattern` 若提供，第一捕获组必须是版本。WorkBuddy 的 `authQrModal` 只作为来源 UI 元信息，Platform 返回授权链接；登录始终等待命令退出并检查 status。

例如 tmeet 的 `cli.json.platform`：

```json
{"npmPackage":"@tencentcloud/tmeet","npmVersion":"1.0.16","entry":"scripts/tmeet.js","command":"tmeet","configEnv":"TMEET_CLI_CONFIG_DIR"}
```

各 Agent 运行包中的 `.platform-runtime.json` 只保存实际 stateDir 路径，不保存凭据；由 Platform 组装时生成，并适配已知旧版启动器。包内 `bin` 启动器用于 Host Bash/Terminal，自动设置 `TMEET_CLI_CONFIG_DIR` 或 `WECOM_CLI_CONFIG_DIR`，调用安装后的 CLI。目录布局：

```text
connectors-center/                 # 导入的外部原包
├── tmeet/
└── wecom/
ru-agents/<agentKey>/connectors/    # Platform 为当前 Agent 生成
├── tmeet/                         # 已挂载的清单、bin 启动器、skills
└── wecom/                         # 仅挂载时生成
.state/                            # Platform 通用持久化运行状态
└── connectors/                    # 不随运行包重建
    ├── tmeet/
    │   ├── npm/                   # 固定版本 CLI
    │   ├── npm-cache/
    │   └── config/                # 腾讯会议独立凭据
    └── wecom/
        ├── npm/
        ├── npm-cache/
        └── config/                # 企业微信独立加密凭据
```

企业微信没有正式 logout 子命令；包声明 `platform.logoutMode=delete-config`，只删除 `.state/connectors/wecom/config`。不删除用户默认的 `~/.config/wecom`。CLI 原始输出只在有界内存中检查，返回的登录 URL 必须属于包声明的 authUrlDomain。登录命令退出后再次执行 status，只有通过状态检查才返回 authorized。

Agent 挂载连接器即授权其运行包 CLI 执行。`wecom-cli auth show --status`、`message aibot sessions list` 和 `message aibot send` 等全部子命令，在 `default/auto_approve/full_access` 下都无需 Platform HITL 或自动审批审计；消息 JSON 和文件参数也不会再被当作普通脚本或目录访问单独审批。实际入口由运行包路径及内容摘要确认，原始命令和参数直接交给 CLI。登录未完成、目标不在企微允许的会话范围等业务错误仍按 CLI 实际返回处理。完整边界见 [连接器](连接器.md)。

这两个受管 CLI 的安装和凭据目前面向 Native Host。Container 不挂载 `.state`，因此不能直接复用 Host 登录或 npm 依赖。连接器目录 PATH 本身仍沿用现有容器挂载规则。

企业微信跨技能引用使用同包共享技能路径 `@connectors/wecom/skills/<name>/SKILL.md`。文档生成脚本在无 WorkBuddy 路径变量时使用 Platform 的 `AP_CHAT_DIR/AP_WORKSPACE_DIR`，读临时输入可使用系统 temp；该文档生成能力另需 Python 和 `python-docx`。

## MCP OAuth

两个 MCP 都使用 `auth_mode=oauth` 和 `oauth.discovery=true`。授权流程基于官方 Go MCP SDK 的资源/授权服务器元数据校验和动态客户端注册，以及 oauth2 的 PKCE code exchange。要求 S256，校验随机 state 和绑定的 resource。每次登录打开临时 `127.0.0.1` callback listener；浏览器必须能访问运行 Platform 的同一台机器。远程浏览器回调、预注册客户端和统一公共 callback URL 尚未实现。

`mcp.json.mcpServers.main.url` 是认证资源和令牌发送目的地的唯一事实源；`connector.json.oauth` 声明发现方式、可选 resourceMetadataUrl 和 scopes。未指定元数据地址时从 MCP 的 `WWW-Authenticate` 发现，再使用标准 well-known 地址。注册、授权和 Token endpoint 来自已校验的授权服务器元数据；不把 WorkBuddy 的私有认证代理写入 Platform。OAuth 不能混用 mcp.json 的 Authorization header 或 `platform.authSource`。

`.state/connectors/<id>/oauth.json` 以 0600 原子持久化授权配置和 Token，父目录为 0700，不进入包或可回显清单。每次 MCP 请求读取当前凭据，过期时通过跨进程文件锁串行刷新并保存轮换后的 refresh token；本地 catalog 加载不等待此锁或网络。凭据严格绑定完整资源地址，重定向到其他 host/path/query 不携带 Token。退出删除本地凭据并使旧 session 不能继续带授权发请求；当前不调用上游 revocation endpoint。取消只作用于当前管理进程发起的登录；不要同时使用多个管理进程发起同一账号的登录。

认证按部署共享，未实现不同 Platform subject 的独立账号绑定。登录成功表示 CLI 或 OAuth 凭据获取成功；MCP 后台 tools/list 的服务可用性、协议兼容和业务侧权限仍需单独检查，不把登录成功等同于所有工具均可调用。
