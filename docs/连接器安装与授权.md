# 连接器安装与授权

## 认证类型

`connector.json.auth_mode` 区分凭据来源和认证流程，与 `type=cli/mcp/view` 独立。Agent、管理端与 WebApp 共用当前部署的 `.state/connectors/<id>` 凭据，不提供多租户隔离。WebApp 登录交给 Platform/Desktop，详见 [WebApp 能力接入](WebApp能力接入.md)。

| auth_mode | 凭据来源与获取方式 | 当前行为 |
| --- | --- | --- |
| `token` | 用户在第三方后台生成并手工填写 | 按 token_schema 校验、保存、查询状态与清除；发送 HTTP 或启动 stdio/Host CLI 时读取，支持显式消费映射 |
| `oneid-token` | Desktop 企业 SSO 自动提供 | 按调用即时提供 AP_ACCESS_TOKEN；Host CLI/stdio MCP 通过环境变量使用，HTTP MCP 生成 Bearer Header，不保存连接器凭据 |
| `oauth` | 用户通过浏览器完成 OAuth 2.0 授权码流程 | 使用预注册 public client 和显式授权/Token endpoint，PKCE、loopback 回调与刷新 |
| `mcp` | 用户通过浏览器完成 MCP OAuth 2.1 认证 | 发现资源和授权服务器元数据，使用预注册客户端、Client ID Metadata Document 或动态注册，再执行 PKCE 与刷新 |
| `null` | 由 connector Skill / CLI / SDK 决定 | 不推断无需认证，不阻挡 MCP 初始化；仅显式声明受管 CLI 生命周期时提供管理端登录助手 |

`null` 是 JSON 空值，也可省略 auth_mode；字符串 `"null"` 和空字符串非法。读取旧包时，`none`、`cli` 归一为 `null`，旧 `oauth` + `oauth.discovery=true` 归一为 `mcp`；原包文件不自动改写，目录/API 元数据返回新值。builtin.dbx 和 builtin.httpx 的认证委托给各自 CLI/Skill，清单使用 `null`，随包不可修改或删除。

`oneid-token` 复用 Desktop SSO：Desktop 原子写入 `<Desktop dataRoot>/state/desktop/sso-access-token.txt`，启动参数 `--identity-file` 将该文件路径交给 Platform。普通 Agent Host Bash 与 oneid-token 的 stdio MCP 在创建进程时即时读取，注入保留环境变量 `AP_ACCESS_TOKEN`；不修改 Platform 进程环境。HTTP MCP 无子进程环境，使用同一身份环境生成 `Authorization: Bearer ...`，每次请求重新读取，并严格绑定 HTTPS（默认端口 443）的完整 MCP endpoint。Token 不复制进连接器包、Agent 运行包或 `.state/connectors`。兼容旧市场包时，仅将 HTTP `headers.Authorization`（Header 名不区分大小写）的精确值 `Bearer ${ONEID_TOKEN}` 在内存中归一为 `Bearer ${AP_ACCESS_TOKEN}`；不改写原包，也不提供 `ONEID_TOKEN` 环境变量。其他 Header、stdio env、static 字段或拼接模板不获得此兼容。新包应省略 Authorization 并使用平台自动 Bearer，或使用标准 AP_ACCESS_TOKEN 模板；原有完整 HTTPS endpoint 限制保持不变。

## 资源包边界

连接器资源包独立于 Platform 发布。平台只读取统一清单与组件配置，不依赖特定来源市场或客户端。分发边界见 [连接器打包与分发](连接器打包与分发.md)。

## ZIP 导入

`POST /api/admin/connectors/import` 使用现有 Platform 鉴权和 `{code,msg,data}` 包裹。multipart 表单只接受一个 `file`，可选 `overwrite=true`。

ZIP 支持根目录直接放 `connector.json`，或一层与 id 同名的包装目录。清单决定安装目录；文件名不决定 id。单包上传最多 64 MiB、8192 个条目、解压合计 256 MiB、单文件 128 MiB；拒绝路径穿越、符号链接、特殊文件、大小写路径冲突、Windows 保留文件名及 `builtin.*`。可执行权限保留为 0755，普通文件为 0644。

完整包和 MCP key 冲突先校验，之后替换来源并本地 reload。同名包默认返回 409，显式覆盖替换整个目录。本地 reload 失败恢复旧来源；远端服务连接失败只报告不可用，不回滚合法包。当前过程处理普通运行错误，不承诺断电时目录替换的跨步骤事务。

导入与删除临时目录放在 `connectors-center` 的同级目录，不参与后台目录监控或热重载。HTTP 导入、覆盖在 Catalog mutation 边界外解压和静态校验，边界内重新检查已安装资源并发布；定义保存和删除复用该串行边界。目录发布和删除只释放连接器资源根的监听，完成发布或回滚后恢复并做内容差异检查；普通定义保存保持监听。API 已成功加载且内容未再变化时，重复事件和恢复检查不再次重载，其他资源根继续监听。Windows 下这避免监控句柄阻止正式目录重命名，macOS 同样遵循未发布内容不触发重载的边界。删除保持 Agent mutation → Catalog mutation → 连接器 mutation 的锁顺序，引用检查与删除共同受到 Agent mutation 保护。回滚失败保留备份并返回恢复位置，不清理唯一旧副本。

不启动完整服务也可以管理包：

```bash
agent-platform connector-manage import --runtime-dir /absolute/runtime /path/to/example.zip
agent-platform connector-manage status --runtime-dir /absolute/runtime --id example
agent-platform connector-manage login --runtime-dir /absolute/runtime --id example
agent-platform connector-manage logout --runtime-dir /absolute/runtime --id example
agent-platform connector-manage set-token --runtime-dir /absolute/runtime --id example-api --credentials-file /absolute/token-values.json
```

`--runtime-dir` 选择需要管理的部署，原包固定使用该根下的 `connectors-center`，旧迁移来源固定为 `connectors` 和 `connector-state`。状态根只读取环境变量 `AP_RUNTIME_STATE_DIR`，未设置或为空时使用 `<runtime-dir>/.state`；连接器固定使用其 `connectors/<id>` 子目录。独立 CLI 不自动读取 `.env`，应由调用方注入与 Platform 相同的环境；相对状态路径按命令当前工作目录解析。`--state-dir`、`--connectors-center-dir`、`--connectors-dir` 和 `--connector-state-dir` 已移除，传入会报错。CLI 登录输出状态和授权链接，保持前台等待；Ctrl+C 取消。登录、保存 Token 或退出只更新凭证目录，不改写或触碰 connector.json、mcp.json、cli.json。Platform 每秒检查凭证变化，仅更新 MCP Registry 和后台同步，不重建 Agent 运行包。已运行的旧版本 Platform 需要重启到支持授权的新版本。此功能不提供独立授权界面，Platform 现有客户端通过下述 API 发起授权和显示状态。

## 登录 API

| 方法 | 地址 | 行为 |
| --- | --- | --- |
| POST | `/api/admin/connectors/auth?id=<id>` | 异步开始登录，相同连接器的活动登录幂等复用 |
| GET | 同上 | 查询状态及等待中的授权链接，不回显 CLI 原始输出或 Token |
| PUT | 同上 | token 模式接受 `{ "credentials": { "API_KEY": "用户填写值" } }`，完整替换凭据；OAuth 模式可提交 oauthClient 注册信息，与 credentials 互斥 |
| DELETE | 同上 | 清除 token/OAuth 本地凭据，或执行受管 CLI 退出；不清除 Desktop SSO 或任意 CLI 自管状态 |
| POST | `/api/admin/connectors/auth/cancel?id=<id>` | 只取消登录会话和进程树 |

响应字段为 `connectorId/componentId/sessionId/status/authorizationUrl/message/expiresAt`。状态包含 `delegated`、`setup_required`、`unauthorized`、`preparing`、`pending`、`authorized`、`failed`、`canceled`。管理端轮询 GET，当状态为 pending 时打开 authorizationUrl。登录 session 上限 15 分钟，CLI 上游自身的更短超时仍生效；进程重启不恢复等待会话，需重新发起。

## 凭证消费映射与多组件授权

`connector.json.auth_bindings` 只保存公开模板；`cli` 指向 CLI，`mcp:<组件原名>` 指向 MCP。HTTP 组件支持原始 `type: "http"` / `streamableHttp`、布尔 `disabled` 和大小写组件名（大小写冲突拒绝），只在内存中适配，不改写 mcp.json。

### Token 保存、验证与状态读取

Token 先按 schema 校验，验证使用临时私有凭据目录与 HOME/XDG/tmp，复用现有 CLI status 或 MCP Initialize/ListTools，不执行业务工具。无独立验证命令且无 MCP 的 Token 配置返回 `configured`。五种认证方式的既有完成判定不在本次重新设计。

明确拒绝凭据时返回错误并保留原值。验证暂时不可用时允许保存到 `.state/connectors/<id>/pending-credentials.json`（0600），返回 `pending_verification`；既有正式凭据不变，首次配置没有正式凭据时不能宣称已认证。显式 `POST /api/connectors/check?id=<id>` 优先验证待验证值，成功后原子替换正式凭据并清理候选。新候选提交会替换旧候选；成功提交正式值也会清理候选。没有有效候选时检查当前值。

验证结果保存在私有 `verification.json`，绑定包认证配置、凭据摘要和退出代次。GET 授权状态与连接器列表只读本地结果，不逐项发起网络请求或启动 CLI。存在候选时返回 `pendingVerification:true`；已有有效正式凭据仍展示其认证状态。Token 保存/显式检查使用已有超时常量；用户取消或退出期间的检查不能以离线保存为由迟到写入。退出会清理正式/待验证凭据和验证结果，但保留其他配置与数据。本次仅提供后端契约，客户端状态展示需要消费这些字段。

静态 Token 的消费示例（字段 API_KEY 必须在 token_schema.fields 中声明）：

```json
{
  "auth_bindings": {
    "mcp:DocX": {"headers": {"X-API-Key": "${API_KEY}"}},
    "cli": {"env": {"SERVICE_TOKEN": "${API_KEY}"}}
  }
}
```

HTTP OAuth / MCP OAuth / OneID 自动注入 Bearer，不允许 auth_bindings.headers 覆盖。OAuth 的 stdio/CLI env 可引用 `${ACCESS_TOKEN}`，OneID 可引用 `${AP_ACCESS_TOKEN}`；保留变量、PATH/HOME、配置目录变量和动态加载器变量不能作为凭证映射目标。模板和已有 headers/env/staticHeaders/staticEnv 同名冲突报错，不静默覆盖。Token 不放进工具参数、catalog 或原包。

同一连接器多个 HTTP MCP 组件通过 `?component=<组件原名>` 分别登录；省略 component 的 GET 汇总全部组件是否已授权，多组件 POST 必须选择目标。同一连接器同进程只允许一个活动授权会话。每个 `mcp:<name>` binding 可带 `oauth` 覆盖该组件的公开 OAuth 配置。CLI 默认使用自身 OAuth 配置；需要使用某 HTTP MCP 的 grant 时显式声明：

```json
{"auth_bindings":{"cli":{"grant":"DocX","env":{"SERVICE_TOKEN":"${ACCESS_TOKEN}"}}}}
```

grant 仅适用于访问相同授权资源的 CLI。stdio 使用普通 oauth 获取上游 API 票据；mcp 模式的发现仍限定 HTTP。Host Bash 在每次启动时读取当前凭据，已启动进程保留环境快照；Terminal 在打开时注入 token/OAuth 环境，不提供 OneID 及其别名。Container 不通过此链路获得宿主凭据。环境注入作用于已挂载连接器的 Host 执行环境，不提供同进程内的逐命令秘密隔离。

自管 CLI 继续使用 `platform.configEnv` 指向 `.state/connectors/<id>/config`，由 CLI 自行读写其原生文件。Platform 不猜测任意 CLI 的加密格式或将 Token 拼进参数；仅接受特定文件格式的 CLI 由资源包适配器处理。

OAuth 客户端信息通过 PUT auth API 的 `oauthClient` 写入部署凭证目录，不写入 mcp.json：

```json
{"oauthClient":{"issuer":"https://accounts.example.com","clientId":"registered-client","redirectUri":"http://127.0.0.1:8765/callback"}}
```

更换客户端信息会使本连接器既有 grant 失效，需要重新授权。退出按整个连接器执行，不接受 component 参数。

可选 `clientSecret` 和 `tokenEndpointAuthMethod`（none/client_secret_basic/client_secret_post）；public client 的 none 不接受 secret。命令行使用 `connector-manage set-oauth-client --runtime-dir <root> --id <id> --component <name> --credentials-file <private-json>`，login/status 同样支持 --component。客户端界面需调用这些接口，Platform 不提供新的注册信息表单页面。

实际私有状态继续复用旧文件布局，无需整体目录迁移：

| 文件 | 用途 |
| --- | --- |
| credentials.json | 手工 Token 字段值，0600 JSON，不承诺静态加密 |
| oauth.json | 兼容旧顶层 grant，额外资源保存在 grants；包括刷新票据与目标绑定 |
| auth-state.json | revision 和退出 generation，不含票据 |
| client-<hash>.json | 按目的地保存预注册或动态注册结果，可含客户端 secret |
| discovery-<hash>.json | 校验后的资源和授权服务器元数据快照 |
| config/ | CLI 原生登录文件；不向 CLI 暴露整个状态目录 |

HTTP 明确返回 401 时最多刷新并重试一次可重放请求；再次拒绝要求重新登录。403 insufficient_scope 保存所需 scopes，等待用户发起追加授权，不自动弹浏览器。MCP 刷新请求携带 resource，认证层不会因网络错误重放业务请求。票据可用和 MCP tools/list 可用性分别报告。

## 企业 SSO / oneid-token

清单只声明 `"auth_mode": "oneid-token"`，不声明 token_schema 或 oauth。Host CLI 直接读取 `AP_ACCESS_TOKEN`。stdio MCP 自动获得同名变量；若 SDK 需要其他变量名，可在 mcp.json 使用 `"env": {"SERVICE_TOKEN":"${AP_ACCESS_TOKEN}"}`。这是受管身份来源替换，不读取任意进程环境；`AP_ACCESS_TOKEN` 本身仍不能被 Agent/Skill/连接器配置覆盖。普通 MCP 子进程会清除继承的同名变量，不获得 SSO。

HTTP MCP 默认发送 Bearer Header，也可在动态 headers 中引用 `${AP_ACCESS_TOKEN}`；Authorization 若显式声明，仅接受 `Bearer ${AP_ACCESS_TOKEN}`。禁止在 URL、静态字段或其他占位符中使用 SSO。旧包所有 HTTP MCP 组件均使用 platform.authSource=identity-file 时，加载元数据自动归为 oneid-token，原文件不改写；离线迁移也会生成 oneid-token。

授权状态只表示当前 Desktop Token 是否可用，不验证上游权限。GET 返回 authorized/unauthorized；缺失、为空或非法时提示登录 Desktop，不阻止 Platform 启动。此模式不支持连接器的手工 Token 写入、交互登录或退出；SSO 登录/退出由 Desktop 管理。Token 更新后，HTTP 下次请求读取新值；stdio 下次调用检测身份变化并关闭旧 session、以新环境创建进程。Desktop 删除 Token 后，新的 MCP 调用拒绝执行，旧 stdio session 回收；已启动的普通 CLI 进程保持其启动时环境。

独立 `connector-manage status` 默认读取 `<有效 StateDir>/identity/access-token`；使用 Desktop 管理的部署时，传入与 Platform 启动参数相同的 `--identity-file /absolute/path/sso-access-token.txt`。管理命令只读取这个文件，不复制、不刷新、不删除它。Terminal、Container、Proxy、ACP、LSP 与 sidecar 不通过此链路获得 Token。

## 静态 Token

`token_schema.fields` 定义 key、label、type（text/password）、required，可带 placeholder、description，text 可带公开 defaultValue；password 禁止默认值。兼容旧字段 name 作为 key；key 必须是唯一的大写字母、数字、下划线标识，以字母开头。保存接口只接受声明字段，检查必填、单行和每字段 64 KiB 上限，不验证第三方业务权限。PUT 请求上限 1 MiB，拒绝重复字段、未知请求属性与尾随 JSON。CLI 的 credentials-file 使用字段值对象 `{ "API_KEY": "用户填写值" }`，不使用内联命令参数传 Secret。

凭据原子写入 `.state/connectors/<id>/credentials.json`（0600），GET 只返回是否配置。HTTP MCP 的动态 headers/query 每次请求读取当前文件；query 只允许值中出现 `${KEY}`，替换后逐项 URL 编码，不允许凭据决定 host/path/query 参数名。源码 URL、catalog、SDK 原请求和错误保留模板，退出后旧 HTTP session 不能继续使用已删除的 Token。stdio env 在连接前解析，凭证变化重建实例；Host CLI 按 auth_bindings 在启动 Bash 时读取票据并注入环境变量。自带认证的 CLI 使用 null 和 configEnv。用户填写的就是已从上游取得的 Token/API Key，表单提交不执行换票。

## CLI 准备与隔离

CLI 准备与认证独立。HTTP ZIP 导入在原子发布和本地重载成功后异步准备 CLI；`installed:true` 只表示来源包已导入，响应另附 `preparation`。初始化失败保留包，不回滚脚本已产生的外部副作用。独立 `connector-manage import` 则等待准备完成；失败明确报告包已导入但 CLI 准备失败。可用 `connector-manage prepare --runtime-dir /absolute/runtime --id example` 显式重试。

| CLI 包内容 | 准备行为 |
| --- | --- |
| 有 `bin/` | 不执行 init，只从包内解析命令并检查版本；空 bin、缺失入口或版本不合格直接失败，不回退全局同名程序 |
| 无 `bin/`，有 init | 原样执行当前操作系统脚本，再检查版本 |
| 无 `bin/`，无 init | 检查环境中的既有命令，不安装程序 |

`cli.json.init` 是唯一安装事实源，支持多行、条件、管道和重定向。macOS/Linux 使用 Bash，Windows 使用 cmd.exe 批处理；需要 PowerShell 等解释器时由 init 显式调用。工作目录是已发布的连接器源码目录，不重设 HOME、npm prefix，也不改写安装版本。Node runtime 声明只检查前提，不安装 Node。

命令由 `versionCheck.command` 声明；可选 `platform.command` 必须一致。准备通过 `minVersion` 和可选 `versionPattern` 检查 CLI，第一捕获组提取版本。旧 `platform.npmPackage/npmVersion/entry/nativeEntry` 不再驱动安装或决定运行路径。无登录声明的 CLI 同样能独立准备；auth/status/unAuth 仍沿用现有单条 CLI 命令及多步登录约束，不因此扩大为任意脚本。

新增 HTTP 接口 `/api/admin/connectors/prepare?id=<id>`：GET 查询，POST 准备或重试，DELETE 取消。返回统一 JSON 包裹，data 包括 connectorId、status、fingerprint、stage、message、exitCode、diagnostic、updatedAt；可选字段按需出现。状态为 pending/preparing/ready/failed/canceled，连接器列表附带不含过程诊断正文的 preparation 摘要。GET 不执行 CLI；无记录返回 pending，包变更要求重新准备。

准备状态和入口校验信息原子保存到 `.state/connectors/<id>/preparation.json`。任务最长 15 分钟；同进程重复请求合并，跨进程通过 OS 锁与来源导入、编辑、删除和 CLI 登录互斥，占用返回 409。目录中的隐藏 `.cli-<id>.lock` 只用于 OS 锁，不含凭据；进程退出会释放锁。重启后首次查询将未完成记录标记为 canceled，等待显式重试，不自动重放 init。取消不代表脚本外部副作用已经撤销。由独立管理进程持有的任务不能被另一进程直接取消，应在任务所属进程中取消。

### Host PATH

Platform 以实际运行账号及环境中的 `npm prefix -g` 探测全局命令目录：macOS/Linux 为 `<prefix>/bin`，Windows 为 `<prefix>`。结果按环境缓存，启动时预热、init 完成后刷新；找不到 npm 不阻止服务启动或非 npm CLI。非 npm 自定义目录需要由部署环境提供 PATH，不增加 pathCommand 等新字段。

Host 使用顺序为：当前 Agent 已挂载连接器 bin → Platform builtins/bin → 基础 PATH → 尚未包含的 npm 全局命令目录。已存在的 npm 全局目录保留原位置，不提升优先级，确保 Desktop 等宿主显式提供的 Node/npm 优先于系统运行时。生命周期、Host Bash、Terminal 和 stdio MCP 采用同一目录机制；Bash 在 shell profile 之后重新应用审查环境中的 PATH 与连接器配置目录。npm PATH 不授予全局目录免审权限；既有包内入口快照授权保持。Container 不注入宿主 npm 路径或凭据，容器 npm 自动探测未实现。

### 独立凭据与升级

保留 `platform.configEnv` 与 `logoutMode`，示例：

```json
{"platform":{"command":"example-cli","configEnv":"EXAMPLE_CLI_CONFIG_DIR","logoutMode":"delete-config"}}
```

Platform 向生命周期命令和已挂载连接器的 Host Agent/Terminal 注入 `.state/connectors/<id>/config`。Agent 配置或 run env 不得替换该挂载配置目录；不同连接器的 configEnv 冲突在 catalog 装配时报错。退出仅清理本连接器独立配置，不删除全局程序，也不使用用户默认 CLI 凭据目录。

CLI 登录要求当前包准备完成，不再隐式安装；状态查询和退出检查准备记录及入口有效性，不调用 init。多步登录、授权 URL 域名校验及 JSON/正则状态匹配保持。

从旧启动器包迁移到无 bin 的安装命令型包时，需显式覆盖导入；不自动删除、猜测改写用户 bin。旧 `.state/connectors/<id>/npm` 不再是新安装目标，但不自动清理，已有 config 凭据继续复用。服务端接口已提供，客户端展示安装进度与重试按钮需使用新的 preparation 接口。

## 普通 OAuth 与 MCP OAuth

`auth_mode=oauth` 使用显式 `oauth.client_id`、`authorization_endpoint`、`token_endpoint`、`resource` 和可选 scopes。client_id 是预注册的公开客户端标识；不接受包内 client_secret。此流程直接打开授权端点，不探测 MCP 元数据、不动态注册，也不强制发送 MCP 的 resource 请求参数。支持 public client + PKCE；部署私有客户端信息可通过 auth API 的 oauthClient 保存，支持 client_secret_basic / client_secret_post。按 issuer 自动发现普通 OAuth 端点、服务端公共回调与上游 revocation 尚未实现。

```json
{
  "auth_mode": "oauth",
  "oauth": {
    "client_id": "public-client-id",
    "authorization_endpoint": "https://accounts.example.com/authorize",
    "token_endpoint": "https://accounts.example.com/token",
    "resource": "https://api.example.com",
    "scopes": ["documents.read"]
  }
}
```

`auth_mode=mcp` 通过官方 Go MCP SDK 校验元数据并要求 PKCE S256。oauth 块可省略，支持 resourceMetadataUrl、scopes、client_id、resource、issuer、client_metadata_url；旧 discovery=true 兼容保留。优先使用部署或包内预注册 client_id；其次使用服务器支持的 HTTPS Client ID Metadata Document（须配置与文档匹配的 redirect_uri）；否则动态注册并保存结果供后续登录复用。均不可用时提示配置客户端信息。发现优先解析 WWW-Authenticate，再尝试 endpoint 对应 well-known 地址；该地址缺失（404/405/410）时回退根地址，不忽略错误资源声明。授权服务器发现复用 SDK 的 OAuth Metadata / OIDC 回退；多个 issuer 可通过 oauth.issuer 选择，默认第一个。

OAuth resource 是授权 audience，默认使用 MCP URL；允许显式声明其他 HTTPS 资源标识，例如 resource 为 `https://api.example.com`、MCP endpoint 为 `https://api.example.com/mcp`。元数据必须匹配声明的 resource，实际 Token 发送目的地仍严格绑定 MCP endpoint 的 scheme/host/path/query，不能借 resource 扩大范围。两个模式均不能混用 mcp.json 的 Authorization header 或 platform.authSource。

两个流程都使用随机 state、PKCE S256 和本机 loopback callback，浏览器必须能够访问 Platform 所在机器。默认监听临时 `127.0.0.1` 端口；预注册客户端如需固定回调，可提供 `oauth.redirect_uri`，仅接受 `http://127.0.0.1:<port>/<path>`。授权配置、Token、resource 与请求目的地以 0600 原子持久化至 `.state/connectors/<id>/oauth.json`，父目录 0700；保留旧单资源顶层结构，额外资源放在 grants 中，按 resource + destination 隔离。每次 MCP 请求读取当前凭据，过期时跨进程加锁刷新并持久化 refresh token；本地 catalog 不等待网络或刷新锁。退出删除全部本地 grant，保留客户端注册信息和发现缓存；auth-state.json 的 generation 阻止退出前的迟到登录恢复票据。取消只影响当前管理进程的待完成登录。

认证按部署共享，未实现不同 Platform subject 的独立账号绑定。登录成功表示 CLI 或 OAuth 凭据获取成功；MCP 后台 tools/list 的服务可用性、SDK 支持的协商版本和业务侧权限仍需单独检查，不把登录成功等同于所有工具均可调用。Platform 优先请求 `2025-11-25`，也接受 `2025-06-18`、`2025-03-26` 和 `2024-11-05`，服务返回支持的旧协议版本本身不会使同步失败；上游 HTTP 429 限流仍会独立报告。

## 授权页面展示

`connector.json.auth_browser` 优先决定展示策略，允许 `system` 和 `embedded`；未配置时兼容读取 `cli.json.authQrModal`，仅布尔值 `true` 使用 `embedded`，否则默认 `system`。显式 `auth_browser: system` 覆盖 `authQrModal: true`。Platform 在创建会话时固定策略，通过 start/status 的 `authBrowser` 返回；CLI 输出只提供授权链接，不能改变展示策略。资源包保留原有 `cli.json.authQrModal`，无需为适配删除字段。

WebClient Standalone 在 embedded 模式使用模态 iframe；Desktop 内的 WebClient 通过受限宿主 bridge 打开隔离的模态 WebView。只有用户发起或继续的会话打开弹窗；观察状态不自动弹窗。成功以 Platform 状态为准，页面加载与跳转不能确认认证成功。内嵌失败不自动打开系统浏览器。

取消接口允许携带 `sessionId`，Platform 在同一锁内核对身份后取消，旧弹窗不得取消替换会话。CLI 继续由包配置非交互和禁止自行打开浏览器的参数；展示配置不能阻止不遵守该契约的 CLI 自行打开浏览器。
