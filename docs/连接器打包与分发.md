# 连接器打包与分发

## 平台与资源包的边界

Platform 定义并校验通用连接器契约，负责导入、准备、授权状态和 Agent 挂载。具体服务的安装命令、授权参数、域名、技能和品牌素材由连接器资源包维护，不作为 Platform 的产品规则。来源市场的目录格式、打包工具和适配记录属于资源维护流程，不参与运行时决策。

## 分发方式

`type: cli` 表示通过命令行调用，不表示 ZIP 已包含真实程序。

| 分发方式 | 包内容 | 准备行为 |
| --- | --- | --- |
| 自带 CLI | `bin/` 中的程序及依赖、`cli.json` | 跳过 init，仅校验包内入口与版本 |
| 安装命令型 | 无 `bin/`，由 `cli.json.init` 声明安装脚本 | 执行当前操作系统的 init，再检查版本 |
| 使用既有 CLI | 无 `bin/`、无 init | 检查环境中的命令与版本 |
| 远程 MCP | `mcp.json` 与认证声明，可附技能 | 配置认证并连接服务；无 CLI 组件时不准备 CLI |

分发方式、认证方式和授权页面展示相互独立。`connector.json.auth_mode` 声明凭据来源；`auth_browser` 声明 `system` 或 `embedded`，未配置时兼容 `cli.json.authQrModal: true` 为 `embedded`，否则默认 `system`。CLI 安装和认证命令在 `cli.json` 中声明。辅助索引或打包元数据不能覆盖这些运行时配置。

## 包结构与版本

每个可导入 ZIP 对应一个连接器，包含 `connector.json`、声明的组件 JSON，以及可选 `assets/`、`skills/`、`bin/`。清单决定连接器 id；合集应先解压，再分别导入其中的连接器 ZIP。结构和校验约束见 [连接器](连接器.md)。

包版本由资源发布方维护，不将 CLI、Skill 或客户端版本当作连接器版本。包、分发索引和校验摘要应保持一致。Platform 不根据品牌、来源市场或重新打包动作推断版本。

图标由 `connector.json.icon` 引用包内 `assets/` 文件，随 ZIP 分发。Platform 校验图标并通过目录 `iconUrl` 提供受鉴权保护的资源接口；客户端负责展示。补图标需更新资源包，升级客户端不会自动修改已安装包。

## 安装与授权声明

安装脚本由资源包明确提供；Platform 不按连接器名称猜测安装方法，也不改写 npm prefix 或安装版本。Host 自动发现 npm 全局命令目录；非 npm 自定义目录由部署环境提供 PATH。详细准备状态、跨进程互斥及取消语义见 [连接器安装与授权](连接器安装与授权.md)。

受管 CLI 通过 `platform.configEnv` 使用本部署的独立配置目录，通过 `logoutMode: delete-config` 清理本连接器配置。包不得包含用户凭据或依赖其他客户端已有登录态。

多步 `auth` 按声明顺序执行，各步骤独立限制 `authUrlDomain`；`skipIf` 依据同一 CLI 的退出码决定跳过，检查超时终止流程。步骤完成后清除旧授权链接，最终由 status 判断认证状态。JSON 状态匹配、URL 提取和非交互参数由配置与通用解析实现，不按品牌分支。

## 导入与挂载

```bash
agent-platform connector-manage import --runtime-dir /absolute/runtime /path/to/example.zip
```

HTTP 导入发布定义后异步准备 CLI；独立管理命令等待准备完成。安装成功、授权成功、远端 MCP 工具可用是不同状态。同名包覆盖需要显式指定，不能自动改写已有包内程序。

```yaml
connectorConfig:
  connectors:
    - example
```

Agent 挂载后由 Platform 组装运行包到 `ru-agents/<agentKey>/connectors/<id>`，自动导入连接器技能。凭据留在 `.state/connectors/<id>`，不手工修改运行包，也不将连接器技能重复配置到普通技能列表。
