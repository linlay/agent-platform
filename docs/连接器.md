# 连接器

## 当前实现

连接器统一封装 MCP、CLI、可执行文件和技能。外部连接器原包使用 `<AP_RUNTIME_DIR>/connectors-center/<id>/`；内置原包随 Platform verified bundle 分发。Agent 挂载后，Platform 将所选完整包组装到 `<AP_RUNTIME_DIR>/ru-agents/<agentKey>/connectors/<id>/`。MCP、CLI、技能使用当前 Agent 的运行副本；管理接口读写原包，builtin 仍只读。不存在独立的 `ru-connectors` 运行目录。持久化授权和受管 CLI 状态使用通用状态根下的 `.state/connectors/<id>/`，重建运行副本不会清除它。

`dbx`、`httpx` 分别是 `builtin.dbx`、`builtin.httpx`，都是 CLI connector，随包附带技能。`rg`、`pdftotext` 和 `kbase-lance-engine` 继续作为平台内部 helper，供 FileTools/KBASE 使用。

已实现包校验、ZIP 导入/覆盖、Agent 挂载、Host/Terminal/Container PATH、技能自动组装、MCP 后台同步、配置编辑、builtin 随包加载和旧引用迁移。管理端支持受管 CLI 的固定版本 npm 准备、版本/状态检查、扫码登录与退出；HTTP MCP 支持 OAuth 发现、动态客户端注册、PKCE、loopback 回调、凭据持久化和刷新。认证是部署级共享状态，尚未实现按用户隔离的凭据、通用 Node 安装或任意 CLI init 脚本执行。详细操作见 [连接器安装与授权](连接器安装与授权.md)。

## 安装包

```text
Platform 随包根/connectors/
├── builtin.dbx/
│   ├── connector.json
│   ├── cli.json
│   ├── bin/
│   │   ├── dbx                     # Windows 为 dbx.exe
│   │   └── libs/                   # 私有依赖，不加入 PATH
│   └── skills/
│       └── builtin-dbx/
│           ├── SKILL.md
│           ├── references/
│           └── assets/
└── builtin.httpx/                  # skills/builtin-httpx，其他结构同上

runtime/connectors-center/
└── remote-search/
    ├── connector.json
    ├── mcp.json
    └── skills/                    # 可选
```

`builtin.*` 为平台保留命名空间，内置连接器不可修改或删除；Agent 可以解除挂载，包本体仍保留。外部根里的旧 builtin.* 副本不读取、不校验、不作为缺包时的回退，不会覆盖随包版本。

包**可以携带 `bin/`，依赖库放在 `bin/libs/`**。加载不执行任意安装脚本。`id` 必须与目录名一致，由小写字母、数字、点、下划线或短横线组成，首字符为字母或数字；`name` 非空，`version` 使用 SemVer。

```json
{
  "id": "remote-search",
  "name": "Remote Search",
  "version": "1.0.0",
  "type": "mcp",
  "auth_mode": "none"
}
```

`type` 为主类型（`mcp` 或 `cli`），决定相应 JSON 文件必填；同一个包可以同时携带两种组件。JSON 拒绝重复键、尾随值、非 UTF-8 和清单未知字段。包根必须是真实目录；符号链接不得逃出包目录，特殊文件拒绝加载。

Skill 支持 `skills/SKILL.md` 单技能，或 `skills/<name>/SKILL.md` 多技能，两者不能混用。每个技能要求 frontmatter `name` 和 `description`；多技能的 name 与子目录名一致。脚本、资料、references 和 assets 随完整包复制进 Agent 的 connectors 子目录；`.config` 默认值按 Agent 独立合并。

## Agent 挂载

```yaml
connectorConfig:
  connectors:
    - builtin.dbx
    - builtin.httpx
    - remote-search
```

挂载列表顺序稳定，重复 id 去重。缺包或包非法时隔离该 Agent 并保留管理端诊断；不会静默少挂一部分能力。

- Host Bash 和 Workspace Terminal 为当前 Agent 前置 `ru-agents/<agentKey>/connectors/<id>/bin`，顺序与挂载列表一致；后挂载的同名命令优先级较低。连接器不修改 Platform 的进程 PATH，也不把 `libs` 加入 PATH。
- Container 自动将所选包只读挂到 `/connectors/<id>`，使用 `/connectors/<id>/bin`。审批解析与实际执行使用一致的容器路径。二进制必须匹配容器的 OS/架构；挂载不会把 macOS/Windows 二进制转换成 Linux 程序。
- 自动导入全部连接器技能的元数据，指令路径为 `@connectors/<id>/skills/<skillName>/SKILL.md`（单技能包为 `@connectors/<id>/skills/SKILL.md`）。文件从本 Agent 的 `ru-agents/<agentKey>/connectors/<id>` 读取，不再重复复制到同级 `skills/`，也不写入 `skillConfig.skills` 或技能中心。`skillId` 直接使用包内 `SKILL.md` 的原始 `name`（如 `wecomcli-shared`），不添加连接器前缀；连接器来源由独立的 `ConnectorID` 与 `instructionsPath` 表达。同一 Agent 挂载的连接器之间，或连接器技能与 `skillConfig.skills` 之间出现同名（忽略大小写）时，隔离该 Agent 并返回冲突诊断，不自动改名或覆盖。
- 技能 prompt、`.runtime-env.json` 和 hooks 从本 Agent 的连接器技能目录读取，`.config` 复用正常 Agent 合并规则并写入各自 `ru-agents/<agentKey>/.config`。`@connectors` 只解析当前 Agent 已挂载的包；已挂载包进入 run trusted read + readonly roots，不能通过 write approval 放宽为可写。
- MCP 组件的当前同步工具自动加入 Agent 的 run 工具集合。纯 MCP 且无 CLI/技能的包不会额外授予 Bash；含 CLI/技能时沿用普通 Skill 的 Bash 追加规则。

专用 KBASE 保持固定工具边界，即使挂载 CLI 也不追加 Bash；ACP CODER 不执行 Platform 工具，因此拒绝连接器挂载。Team 成员按各自 Agent 挂载，其他 Agent 不继承调用方挂载。解除挂载后，空闲 Agent 的下一次 catalog 组装移除整个运行包及技能。活动 Run、子 Agent 调用、Team 成员和 Terminal 持有运行目录租约；更新或删除该 Agent 延迟到最后一个使用者结束，其他空闲 Agent 继续发布。已有 run 的 prompt/env/工具列表保持原快照。

PATH 是命令发现范围，实际访问与执行继续遵守 AccessPolicy/HITL。用户自行在系统 PATH 安装的同名程序不归本连接器安装器管理。

## mustUseSkills

连接器技能**不能被 `mustUseSkills` 选中，包括 Agent 已挂载的技能**：

- `/api/skills` 的可选列表不包含自动导入的连接器技能。
- 请求传入当前 Agent 已挂载的连接器技能原始名称时直接拒绝；技能中心同名项也不在该 Agent 的可选列表中展示。历史 `connector-` 前缀与旧内置技能名 `builtin-dbx`、`builtin-httpx` 保留给连接器，技能中心列表不加载这些副本，普通技能导入/编辑也拒绝这些 key。不能用 `skillConfig.skills` 绕过来源约束。
- 技能随连接器挂载自动可用；不需要、也不允许再以 mustUse 强制选择。
- 普通 Agent 自有技能和技能中心技能仍保持原来的 mustUse 行为。

## MCP 配置和生命周期

HTTP 示例 `mcp.json`：

```json
{
  "mcpServers": {
    "main": {
      "type": "streamableHttp",
      "url": "https://example.com/mcp",
      "timeout": 30000,
      "staticHeaders": {"X-Tenant": "local"},
      "disabledTools": ["delete_all"]
    }
  }
}
```

`url` 是完整地址，不再追加隐式 `/mcp`。stdio 示例：

```json
{
  "mcpServers": {
    "main": {
      "type": "stdio",
      "command": "service",
      "args": ["serve"],
      "staticEnv": {"LOG_LEVEL": "info"},
      "timeout": 30000
    }
  }
}
```

stdio 裸命令从当前 Agent 包内 `bin` 解析；相对路径以该运行包为基准。显式 command/cwd 若指向来源包内部，也映射到 Agent 副本；真正位于包外的绝对路径仍支持迁移后的部署程序。工作目录默认运行包根；`platform.workingDirectory` 可显式覆盖。HTTP 不接受 env/command/args/runtime；stdio 不接受 url/headers。动态与静态字段不能同名，请求头大小写不敏感；保留 AP 环境变量不可覆盖。`timeout` 是正整数毫秒，适配到现有 MCP client 的秒级超时（向上取整）。

组件来源标识中，`main` 对应 `<connector-id>`，其他组件对应 `<connector-id>.<component>`；跨包来源标识重名会硬失败。实际 MCP 实例由 `(agentKey, connectorId, component)` 唯一确定，具有独立 session、stdio 进程、工具快照和重试状态。内部 serverKey 和模型工具名包含稳定摘要以避免多 Agent 冲突，调用远端时仍发送原始 MCP 工具名；工具路由拒绝其他 Agent 调用该实例。未挂载的包只做本地校验，不建立连接。部署专属的 `platform` 块保留 enabled、name、workingDirectory、toolPrefix、aliasMap、authSource、connect-timeout、startup-timeout、retry、tools，主要用于旧配置无损迁移。

HTTP/stdio 统一使用官方 SDK 协商协议版本：优先请求 `2025-11-25`，接受 SDK 支持的 `2025-06-18`、`2025-03-26` 和 `2024-11-05`；缺失、无效及未知版本仍拒绝。stdio 清理和后台同步机制保持一致。启动和保存只同步校验本地定义；远程连接/工具发现不阻塞服务监听。连接变化清除旧工具快照，后台结果按 Registry version 发布，状态变化发送 `catalog.updated(reason=connectors)`。

`auth_mode=none` 可直接使用。迁移工具将原来的部署级 headers/env/token 保存到 `.state/connectors/<id>/credentials.json`（0600），放在包目录外，JSON 定义仅保留 `${KEY}` 模板；模板只从这份部署级存储替换一次，不读取任意进程环境。此存储保持旧部署的认证语义，**不代表已经实现按用户绑定凭据**。迁移保留的 `platform.authSource=identity-file` 继续复用已有 HTTPS 身份适配器。MCP 的 token 缺失、OAuth 尚未完成或 runtime 尚未准备时，后台状态为 unavailable。单 HTTP 组件的 OAuth 登录凭据另存于 `.state/connectors/<id>/oauth.json`，权限 0600，支持持久化刷新和退出；不通过清单、ZIP 或状态接口回显。详见 [连接器安装与授权](连接器安装与授权.md)。

## 管理接口

接口均使用现有鉴权和统一 `{code,msg,data}` 包裹：

| 接口 | 用途 |
| --- | --- |
| `GET /api/connectors` | 已安装包列表、组件标识、技能名、各 MCP 组件同步状态与工具数 |
| `GET /api/admin/connectors` | 相同的管理端目录视图 |
| `GET /api/admin/connectors/detail?id=<id>&file=<file>` | 读取 connector.json、mcp.json 或 cli.json，返回 content、sha256 |
| `PUT /api/admin/connectors/detail` | 以 id、file、content、必填 baseSha256 保存已存在的定义文件 |
| `POST /api/admin/connectors/import` | multipart `file` ZIP、可选 `overwrite`，完整校验后安装并 reload |
| `GET/POST/DELETE /api/admin/connectors/auth?id=<id>` | 状态、开始登录、退出登录 |
| `POST /api/admin/connectors/auth/cancel?id=<id>` | 取消当前登录会话及子进程 |

列表的 `mcp` 按 Agent 实例返回 `agentKey`、内部 `serverKey`、同步状态和工具数；组件未挂载时状态为 `unmounted`。列表还返回 `builtin`、`readOnly` 和 `canDelete`，内置项分别为 true、true、false；内置定义可读，PUT 和 detail DELETE 返回 403。`canDelete` 描述包所有权约束，外部包删除仍由部署流程处理，当前没有通用删除 API。

外部定义保存先校验候选完整包和 MCP 配置，再原子替换文件并立即本地 reload；哈希冲突返回 409，本地 reload 失败恢复原文件，远端不可用不回滚合法定义。ZIP 导入默认拒绝同名包，显式覆盖以隐藏 staging/backup 完整替换；包解压和定义编辑共享 mutation 边界。本地 reload 失败恢复旧包，远端不可用不回滚合法安装。不提供通用删除包或直接编辑凭据的 API。不要把真实凭据写入清单或可回显的定义文件。

`catalog.validate(resourceType=connector)` 只校验提交的 connector.json 清单；组件与实际目录校验由加载和保存完成。旧 `resourceType=mcp-server`、Registry 的 mcp-servers 管理入口、`toolConfig.mcp-servers` 已移除。

## Agent 运行目录与凭证

外部原包固定使用 `<AP_RUNTIME_DIR>/connectors-center`，执行包固定使用 `<AP_RUNTIME_DIR>/ru-agents/<agentKey>/connectors/<id>`。两种目录随 `AP_RUNTIME_DIR` 调整，不提供独立目录覆盖入口。YAML `paths` 节出现即报错。

连接器状态从环境变量 `AP_RUNTIME_STATE_DIR` 派生到 `connectors/<id>`；未设置或为空时为 `<AP_RUNTIME_DIR>/.state/connectors/<id>`。CLI 登录信息、MCP token/OAuth 凭据和受管 CLI 的 npm/config 状态都留在这里，按部署共享。运行包中的 `.platform-runtime.json` 只记录 stateDir 引用，不写入凭据。重建或删除 Agent、解除挂载不会清除状态；退出登录通过独立认证接口处理。原包不得夹带顶层 `.state`、`.credentials`、`connector-state`、`credentials.json` 或 `oauth.json`。

每个 Agent 只复制已挂载包；bin、bin/libs、skills、references、assets 和合法包内符号链接随包保留，不建立跨 Agent 硬链接。多个 Agent 挂载同一连接器会占用多份运行文件，并建立多份 MCP 实例；原包和认证状态仍各保留一份。

启动清空并重建 ru-agents。热重载先校验本地来源，在 `.staging` 组装完整 Agent 候选；含连接器的 Agent 按整目录替换，未变化的目录保留原文件。发布失败恢复旧目录，恢复失败保留备份并报告路径。活动 Run/Terminal 的 Agent 暂缓组装，最后一个使用者结束后触发正常重载。新 Run 只有在本地 MCP 路由完成绑定后才可获取运行目录；远端初始化和 tools/list 仍由后台执行。Windows 文件占用导致发布失败时保留旧副本并报告诊断，不强行删除正在使用的文件。

`@connectors/<id>/...` 只映射当前 Agent 已挂载的 `ru-agents/<agentKey>/connectors/<id>`；Container 只读挂载对应 `/connectors/<id>`。未挂载 ID、`..` 和符号链接逃出对应包直接拒绝；运行包加入 trusted read + readonly roots。容器不默认挂载 `.state`，受管 CLI 的 Host 登录与 npm 安装不能直接在容器复用。

## 旧配置迁移

普通启动自动把旧 `<AP_RUNTIME_DIR>/connectors` 中的包移到 `connectors-center`，把旧包根、connectors-center 或旧 `connector-state` 根下的 `.state/<id>` 移到 `<state-dir>/connectors/<id>`，把 `.credentials/<id>.json` 合并到同一连接器的 `credentials.json`。旧包根与旧状态根固定从同一 `AP_RUNTIME_DIR` 派生；YAML `paths` 迁移来源键也已删除。过去使用自定义旧来源目录的部署，需要在升级前离线整理到标准来源位置。迁移先检查冲突，不覆盖已有目的文件，重复启动不重复迁移；迁移保留文件权限、空目录和连接器内部的相对 npm 链接，拒绝跨连接器链接与特殊文件，普通移动失败会恢复已移动文件。迁移前须停止使用旧路径的 Platform、受管 CLI 和独立登录进程；不承诺跨进程热迁移或断电事务。旧 builtin 副本和 `.builtin-state` 保存在同级 `.connector-layout-backup-<timestamp>` 下，不进入 connectors-center；正式运行副本只来自 Platform。

Agent 运行目录及 MCP 本地绑定成功后，旧 `ru-connectors` 整体移入同级 `.connector-layout-backup-<timestamp>/ru-connectors`，不再创建或读取它；备份保留可能存在的手工文件。中央 `.state/connectors` 不参与此清理。

下面的离线命令另用于转换旧 MCP 定义、Agent 引用并把遗留 builtin 和技能中心副本移入备份：

先停止使用该 runtime 的 Platform，再运行；命令读取与服务相同的 `AP_RUNTIME_STATE_DIR` 环境变量（相对路径按命令当前工作目录解析），不会自动读取 `.env`：

```bash
agent-platform connector-migrate --runtime-dir /absolute/runtime
agent-platform connector-migrate --runtime-dir /absolute/runtime --apply
```

默认预演在系统临时目录生成、校验并清理候选，不改写 runtime；输出连接器 id、Agent 文件名和将迁出的路径，不输出凭据。`--apply` 先检查来源是否在准备期间变化，再备份旧目录并发布 `connectors-center`、有效 `AP_RUNTIME_STATE_DIR` 下的 `connectors` 分区和 `agents`，其他 state 分区不参与迁移，将旧 `connector-state`、`registries/mcp-servers`、旧内置连接器副本/marker 和技能中心的 builtin-dbx/builtin-httpx 移入备份。备份位置是 runtime 下的 `.connector-migration-backup-<timestamp>`；普通执行错误尝试恢复来源。它是离线多目录迁移，不承诺进程崩溃或断电时的跨目录事务：中断后保留备份并在再次启动前检查备份中的 connectors、agents、registries/mcp-servers 和两个 skills-center 子目录。

迁移沿用旧加载器的示例过滤规则：`*.example.yml/.yaml` 只随旧目录保留在备份，不启用为连接器。转换保留旧最终 URL、别名、工具覆盖、启停、超时和部署凭据；Agent 的 `toolConfig.mcp-servers` 改为 `connectorConfig.connectors`，其余文本、注释和环境变量占位符保留。id 统一小写，重名、缺失引用、符号链接和不支持的内联 Agent 配置会中止。旧 stdio 使用外部绝对 command/cwd；未显式指定 cwd 时使用新包根。指向即将删除的旧 Registry 内部的显式 command/cwd 必须先迁出。

启动与热重载先校验 Platform 内置来源与 `runtime/connectors-center` 外部原包，再按 Agent 挂载组装 `ru-agents/<agentKey>/connectors`；资源包校验使用相同的新来源目录；`registries/mcp-servers` 直接忽略，即使其中有非空或非法 YAML 也不报错、不加载、不改写。需要沿用旧 MCP 定义时可显式执行迁移命令；迁移不是启动前置条件。迁移成功后的重复运行不再次迁移或覆盖。

迁移也支持没有旧 MCP 目录的 runtime：`skillConfig.skills` 中的 builtin-dbx/builtin-httpx 转为 `connectorConfig.connectors` 的 builtin.dbx/builtin.httpx，保留普通技能和已有挂载并去重。旧内置包、`.builtin-state` 与两个技能中心目录完整保留在备份中；包的正式来源已纳入 Platform，原有配置数据不写入随包技能。

## builtin 发布

源码事实源为 `internal/resources/connectors/builtin.dbx/` 和 `internal/resources/connectors/builtin.httpx/`，分别包含 connector.json、cli.json 和完整 skills/builtin-dbx 或 skills/builtin-httpx。资源通过 Go embed 随工具构建保留，发布时落入各自包目录。二进制仍由现有 builtin 流程装配，依赖位于 bin/libs。

`sync-local-builtins` 继续负责独立项目构建和 cache 激活；Go 运行/发布不重新构建 CLI 或 Rust。Release 先验证 cache，再在发布副本合并当前 Platform 版本的清单与完整技能、清理旧生成技能并重新计算哈希；即使二进制版本未变化，技能变化也会进入本次发布。原 cache 不被 release 改写。本地技能修改后，需要刷新本机 cache 资源或执行 sync-local-builtins，make run 继续只使用本机 cache。

启动校验随包 manifest 后，只为挂载它的 Agent 将内置连接器组装到 `ru-agents/<agentKey>/connectors/<id>`。它是可重建的运行副本，原包所有权仍属于 Platform，不生成旧 `.builtin-state`。原始全局 bin cache 仍需升级为 connector 布局，以免未挂载的 Agent 获得内置命令。包清单版本来自对应 target 的实际 release；技能自身版本保留在 SKILL.md 中。

验证包括双来源解析、内置命名空间与只读接口、完整技能/引用/图片随包校验、技能单独更新时刷新发布哈希、挂载与解除挂载、mustUse 拒绝和列表过滤、PATH 不跨 Agent 泄漏、Host 命令执行、容器路径映射、MCP 协议/同步、外部定义保存回滚，以及旧 MCP/内置技能的迁移预演、备份与幂等。
