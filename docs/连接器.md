# 连接器

## 当前实现

连接器统一封装 MCP、CLI、可执行文件和技能。外部连接器使用 `<AP_RUNTIME_DIR>/connectors/<id>/`，`paths.connectors-dir` 只覆盖外部根。内置连接器直接从 Platform verified bundle 的 `connectors/<id>/` 加载，由 app 解析来源，不安装到 runtime。两者通过同一 Sources 解析器进入 MCP、Catalog、管理接口和 Agent 挂载。

`dbx`、`httpx` 分别是 `builtin.dbx`、`builtin.httpx`，都是 CLI connector，随包附带技能。`rg`、`pdftotext` 和 `kbase-lance-engine` 继续作为平台内部 helper，供 FileTools/KBASE 使用。

已实现包校验、Agent 挂载、Host/Terminal/Container PATH、技能自动组装、MCP 后台同步、配置编辑、builtin 随包加载和旧 MCP/内置技能引用迁移。本文只描述已实现行为；原方案中的自动依赖安装、CLI init/versionCheck 执行、交互登录、OAuth、按用户隔离的认证与凭据管理 API 尚未实现。声明了所需 runtime 的 MCP，以及未完成认证的 MCP 会报告不可用，不会静默推断另一种认证方式。CLI 必须已准备好可执行文件；平台当前不执行 `cli.json` 的生命周期命令。

## 安装包

```text
Platform 随包根/connectors/
├── builtin.dbx/
│   ├── connector.json
│   ├── cli.json
│   ├── bin/
│   │   ├── dbx                     # Windows 为 dbx.exe
│   │   └── libs/                   # 私有依赖，不加入 PATH
│   └── skills/
│       └── builtin-dbx/
│           ├── SKILL.md
│           ├── references/
│           └── assets/
└── builtin.httpx/                  # skills/builtin-httpx，其他结构同上

runtime/connectors/
└── remote-search/
    ├── connector.json
    ├── mcp.json
    └── skills/                    # 可选
```

`builtin.*` 为平台保留命名空间，内置连接器不可修改或删除；Agent 可以解除挂载，包本体仍保留。外部根里的旧 builtin.* 副本不读取、不校验、不作为缺包时的回退，不会覆盖随包版本。

包**可以携带 `bin/`，依赖库放在 `bin/libs/`**。加载不执行任意安装脚本。`id` 必须与目录名一致，由小写字母、数字、点、下划线或短横线组成，首字符为字母或数字；`name` 非空，`version` 使用 SemVer。

```json
{
  "id": "remote-search",
  "name": "Remote Search",
  "version": "1.0.0",
  "type": "mcp",
  "auth_mode": "none"
}
```

`type` 为主类型（`mcp` 或 `cli`），决定相应 JSON 文件必填；同一个包可以同时携带两种组件。JSON 拒绝重复键、尾随值、非 UTF-8 和清单未知字段。包根必须是真实目录；符号链接不得逃出包目录，特殊文件拒绝加载。

Skill 支持 `skills/SKILL.md` 单技能，或 `skills/<name>/SKILL.md` 多技能，两者不能混用。每个技能要求 frontmatter `name` 和 `description`；多技能的 name 与子目录名一致。额外的脚本、资料和 `.config` 与技能一起组装。

## Agent 挂载

```yaml
connectorConfig:
  connectors:
    - builtin.dbx
    - builtin.httpx
    - remote-search
```

挂载列表顺序稳定，重复 id 去重。缺包或包非法时隔离该 Agent 并保留管理端诊断；不会静默少挂一部分能力。

- Host Bash 和 Workspace Terminal 为当前 Agent 前置每个包的 `bin`，顺序与挂载列表一致；后挂载的同名命令优先级较低。连接器不修改 Platform 的进程 PATH，也不把 `libs` 加入 PATH。
- Container 自动将所选包只读挂到 `/connectors/<id>`，使用 `/connectors/<id>/bin`。审批解析与实际执行使用一致的容器路径。二进制必须匹配容器的 OS/架构；挂载不会把 macOS/Windows 二进制转换成 Linux 程序。
- 自动导入全部连接器技能，组装到 `ru-agents/<agentKey>/skills/connector-<id长度>-<id>-<skillName>/`，不写入 `skillConfig.skills` 或技能中心。
- 技能 prompt、资源、`.config`、`.runtime-env.json`、hooks 复用正常 Agent 组装规则。已挂载包及导入的技能目录进入 run trusted read + readonly roots，不能通过 write approval 放宽为可写。
- MCP 组件的当前同步工具自动加入 Agent 的 run 工具集合。纯 MCP 且无 CLI/技能的包不会额外授予 Bash；含 CLI/技能时沿用普通 Skill 的 Bash 追加规则。

专用 KBASE 保持固定工具边界，即使挂载 CLI 也不追加 Bash；ACP CODER 不执行 Platform 工具，因此拒绝连接器挂载。Team 成员按各自 Agent 挂载，其他 Agent 不继承调用方挂载。卸载挂载后，下次 catalog 组装移除该 Agent 的相关技能；已有 run 的 prompt/env/工具列表不重算。与现有稳定 `ru-agents` 一样，后续读文件可看到更新后的内容，当前不提供每个 run 独立的不可变包版本。

PATH 是命令发现范围，实际访问与执行继续遵守 AccessPolicy/HITL。用户自行在系统 PATH 安装的同名程序不归本连接器安装器管理。

## mustUseSkills

连接器技能**不能被 `mustUseSkills` 选中，包括 Agent 已挂载的技能**：

- `/api/skills` 的可选列表不包含自动导入的连接器技能。
- 请求传入连接器技能 key 时直接拒绝；`connector-` 与旧内置技能名 `builtin-dbx`、`builtin-httpx` 保留给连接器，技能中心列表不加载这些副本，普通技能导入/编辑也拒绝这些 key。不能用 `skillConfig.skills` 绕过来源约束。
- 技能随连接器挂载自动可用；不需要、也不允许再以 mustUse 强制选择。
- 普通 Agent 自有技能和技能中心技能仍保持原来的 mustUse 行为。

## MCP 配置和生命周期

HTTP 示例 `mcp.json`：

```json
{
  "mcpServers": {
    "main": {
      "type": "streamableHttp",
      "url": "https://example.com/mcp",
      "timeout": 30000,
      "staticHeaders": {"X-Tenant": "local"},
      "disabledTools": ["delete_all"]
    }
  }
}
```

`url` 是完整地址，不再追加隐式 `/mcp`。stdio 示例：

```json
{
  "mcpServers": {
    "main": {
      "type": "stdio",
      "command": "service",
      "args": ["serve"],
      "staticEnv": {"LOG_LEVEL": "info"},
      "timeout": 30000
    }
  }
}
```

stdio 裸命令从包内 `bin` 解析；相对路径以包目录为基准，绝对路径可用于迁移后仍由部署管理的现有程序。工作目录默认包根；`platform.workingDirectory` 可显式覆盖。HTTP 不接受 env/command/args/runtime；stdio 不接受 url/headers。动态与静态字段不能同名，请求头大小写不敏感；保留 AP 环境变量不可覆盖。`timeout` 是正整数毫秒，适配到现有 MCP client 的秒级超时（向上取整）。

`main` 对应 server key `<connector-id>`，其他组件对应 `<connector-id>.<component>`；跨包解析后重名会硬失败。部署专属的 `platform` 块保留 enabled、name、workingDirectory、toolPrefix、aliasMap、authSource、connect-timeout、startup-timeout、retry、tools，主要用于旧配置无损迁移。

官方 SDK、严格 `2025-11-25` 协议版本、stdio 清理和后台同步机制保持一致。启动和保存只同步校验本地定义；远程连接/工具发现不阻塞服务监听。连接变化清除旧工具快照，后台结果按 Registry version 发布，状态变化发送 `catalog.updated(reason=connectors)`。

`auth_mode=none` 可直接使用。迁移工具将原来的部署级 headers/env/token 保存到 `connectors/.credentials/<id>.json`（0600），放在包目录外，JSON 定义仅保留 `${KEY}` 模板；模板只从这份部署级存储替换一次，不读取任意进程环境。此存储保持旧部署的认证语义，**不代表已经实现按用户绑定凭据**。迁移保留的 `platform.authSource=identity-file` 继续复用已有 HTTPS 身份适配器。MCP 的 token 缺失、cli/mcp/oauth 认证或 runtime 准备未实现时，后台状态为 unavailable。

## 管理接口

接口均使用现有鉴权和统一 `{code,msg,data}` 包裹：

| 接口 | 用途 |
| --- | --- |
| `GET /api/connectors` | 已安装包列表、组件标识、技能名、各 MCP 组件同步状态与工具数 |
| `GET /api/admin/connectors` | 相同的管理端目录视图 |
| `GET /api/admin/connectors/detail?id=<id>&file=<file>` | 读取 connector.json、mcp.json 或 cli.json，返回 content、sha256 |
| `PUT /api/admin/connectors/detail` | 以 id、file、content、必填 baseSha256 保存已存在的定义文件 |

列表返回 `builtin`、`readOnly` 和 `canDelete`，内置项分别为 true、true、false；内置定义可读，PUT 和 detail DELETE 返回 403。`canDelete` 描述包所有权约束，外部包删除仍由部署流程处理，当前没有通用删除 API。

外部定义保存先校验候选完整包和 MCP 配置，再原子替换文件并立即本地 reload；哈希冲突返回 409，本地 reload 失败恢复原文件，远端不可用不回滚合法定义。当前不提供包创建/删除、ZIP 上传、登录或凭据编辑 API；安装第三方包由部署流程完整放入连接器根，再触发目录 reload。不要把真实凭据写入清单或可回显的定义文件。

`catalog.validate(resourceType=connector)` 只校验提交的 connector.json 清单；组件与实际目录校验由加载和保存完成。旧 `resourceType=mcp-server`、Registry 的 mcp-servers 管理入口、`toolConfig.mcp-servers` 已移除。

## 旧配置迁移

先停止使用该 runtime 的 Platform，再运行：

```bash
agent-platform connector-migrate --runtime-dir /absolute/runtime
agent-platform connector-migrate --runtime-dir /absolute/runtime --apply
```

默认预演在系统临时目录生成、校验并清理候选，不改写 runtime；输出连接器 id、Agent 文件名和将迁出的路径，不输出凭据。`--apply` 先检查来源是否在准备期间变化，再备份并替换 connectors/agents，将 `registries/mcp-servers`、旧内置连接器副本/marker 和技能中心的 builtin-dbx/builtin-httpx 移入备份。备份位置是 runtime 下的 `.connector-migration-backup-<timestamp>`；普通执行错误尝试恢复来源。它是离线多目录迁移，不承诺进程崩溃或断电时的跨目录事务：中断后保留备份并在再次启动前检查备份中的 connectors、agents、registries/mcp-servers 和两个 skills-center 子目录。

迁移沿用旧加载器的示例过滤规则：`*.example.yml/.yaml` 只随旧目录保留在备份，不启用为连接器。转换保留旧最终 URL、别名、工具覆盖、启停、超时和部署凭据；Agent 的 `toolConfig.mcp-servers` 改为 `connectorConfig.connectors`，其余文本、注释和环境变量占位符保留。id 统一小写，重名、缺失引用、符号链接和不支持的内联 Agent 配置会中止。旧 stdio 使用外部绝对 command/cwd；未显式指定 cwd 时使用新包根。指向即将删除的旧 Registry 内部的显式 command/cwd 必须先迁出。

启动、热重载和资源包校验使用 Platform 内置来源与 `runtime/connectors` 外部来源；`registries/mcp-servers` 直接忽略，即使其中有非空或非法 YAML 也不报错、不加载、不改写。需要沿用旧 MCP 定义时可显式执行迁移命令；迁移不是启动前置条件。迁移成功后的重复运行不再次迁移或覆盖。

迁移也支持没有旧 MCP 目录的 runtime：`skillConfig.skills` 中的 builtin-dbx/builtin-httpx 转为 `connectorConfig.connectors` 的 builtin.dbx/builtin.httpx，保留普通技能和已有挂载并去重。旧内置包、`.builtin-state` 与两个技能中心目录完整保留在备份中；包的正式来源已纳入 Platform，原有配置数据不写入随包技能。

## builtin 发布

源码事实源为 `internal/resources/connectors/builtin.dbx/` 和 `internal/resources/connectors/builtin.httpx/`，分别包含 connector.json、cli.json 和完整 skills/builtin-dbx 或 skills/builtin-httpx。资源通过 Go embed 随工具构建保留，发布时落入各自包目录。二进制仍由现有 builtin 流程装配，依赖位于 bin/libs。

`sync-local-builtins` 继续负责独立项目构建和 cache 激活；Go 运行/发布不重新构建 CLI 或 Rust。Release 先验证 cache，再在发布副本合并当前 Platform 版本的清单与完整技能、清理旧生成技能并重新计算哈希；即使二进制版本未变化，技能变化也会进入本次发布。原 cache 不被 release 改写。本地技能修改后，需要刷新本机 cache 资源或执行 sync-local-builtins，make run 继续只使用本机 cache。

启动校验随包 manifest 并直接加载内置连接器，不复制到 runtime、不生成 `.builtin-state`。原始全局 bin cache 仍需升级为 connector 布局，以免未挂载的 Agent 获得内置命令。包清单版本来自对应 target 的实际 release；技能自身版本保留在 SKILL.md 中。

验证包括双来源解析、内置命名空间与只读接口、完整技能/引用/图片随包校验、技能单独更新时刷新发布哈希、挂载与解除挂载、mustUse 拒绝和列表过滤、PATH 不跨 Agent 泄漏、Host 命令执行、容器路径映射、MCP 协议/同步、外部定义保存回滚，以及旧 MCP/内置技能的迁移预演、备份与幂等。
