# 连接器

## 当前实现

连接器统一封装 MCP、CLI、VIEW、受信任内置 native 能力、可执行文件和技能。外部连接器原包使用 `<AP_RUNTIME_DIR>/connectors-center/<id>/`；内置原包随 Platform verified bundle 分发。Agent 挂载后，Platform 将所选完整包组装到 `<AP_RUNTIME_DIR>/ru-connectors/<id>/<contentDigest>/`。MCP、CLI、VIEW、技能使用当前 Agent 挂载的共享运行包；管理接口读写原包，builtin 仍只读。Agent 的 `ru-agents/<agentKey>/connectors/<id>.json` 仅保存挂载引用，同一内容版本跨 Agent 共享。持久化授权和受管 CLI 状态使用通用状态根下的 `.state/connectors/<id>/`，重建运行副本不会清除它。

`dbx`、`httpx` 分别是 `builtin.dbx`、`builtin.httpx`，都是 CLI connector，随包附带技能。`rg`、`pdftotext` 和 `kbase-lance-engine` 继续作为平台内部 helper，供 FileTools/KBASE 使用。

已实现包校验、ZIP 导入/覆盖、Agent 挂载、Host/Terminal/Container PATH、技能自动组装、MCP 后台同步、配置编辑、builtin 随包加载和旧引用迁移。管理端支持受管 CLI 的原始 init 异步准备与 npm 全局 PATH、版本/状态检查、扫码登录与退出；HTTP MCP 支持 OAuth 发现、动态客户端注册、PKCE、loopback 回调、凭据持久化和刷新。认证是部署级共享状态，尚未实现按用户隔离的凭据、通用 Node 安装或交互式 CLI 初始化终端。详细操作见 [连接器安装与授权](连接器安装与授权.md)。

## 名称本地化与互斥选择

`connector.json` 可选 `i18n`，按服务支持的规范语言键 `en`、`zh-CN` 提供 `name`、`description`。未提供翻译或字段为空时回退顶层值。例如：

```json
"name": "Web Control",
"i18n": {
  "en": {"name": "Web Control"},
  "zh-CN": {"name": "网页控制"}
}
```

`/api/connectors` 与 `/api/admin/connectors` 沿用请求语言解析，响应 `name/description` 为解析后的文本，不返回翻译表；原始定义接口仍保留清单原文。响应本地化不修改包或内容摘要。

`connector.json` 的可选 `mutuallyExclusiveWith` 数组是互斥关系的唯一事实源，内置包和外部包使用相同规则。例如 `"mutuallyExclusiveWith": ["another-connector"]`。任意一方声明即不能在同一 Agent 同时选择；缺省或空数组表示无声明，不根据 ID、名称、工具或技能推导。数组成员必须是有效且不重复的连接器 ID，不能引用自身；允许引用尚未安装的包，不要求反向声明。

管理目录直接返回该字段，使用目录仅保留其他可见条目的互斥 ID。服务端在连接器选择、Agent 编辑和运行包解析时统一校验完整挂载（含预置）；保存冲突返回 HTTP 400，`data.error.code=connector_selection_conflict`，并携带 `connectorId` 和 `conflictingConnectorIds`，不会保存冲突选择。WebClient 按未经过搜索筛选的使用目录提前检查，点击冲突项显示本地化名称与“请先取消原选择”；服务端兜底错误也显示，原选择不变，不自动替换。

## 使用目录与管理目录

使用目录与挂载接口同时提供 HTTP 和主 `/ws` 请求/响应契约，共用目录过滤、来源写入、预置只读、互斥校验与重载状态计算。WS `/api/connectors` 以可选 `{agentKey}` 读取，名称与说明使用连接语言；WS `/api/agents/connectors` 以 `{agentKey}` 读取、以 `{agentKey,connectorId,enabled}` 更新单项。出现任一 mutation 字段即按写入校验，`enabled:false` 是关闭，null 或缺字段报 400，未知字段拒绝。WS 使用标准 response/error frame，不新增连接或推送类型；管理、认证和图标保持现有 HTTP 接口。

Composer 使用 `GET /api/connectors?agentKey=<key>`，条目仅返回 `id/name` 和非空的 `description/iconUrl/mutuallyExclusiveWith`。平台预置由 `configs/agent-settings.yml` 的全局与对应 mode 的 `preset-connectors` 决定；当前 Agent 的预置不进入使用目录，省略 agentKey 时过滤所有 mode 的预置并集。非预置的 builtin 包仍可选择；无效 Agent key 返回 404，不能退回全局目录。使用目录没有 builtin、readOnly、canDelete、版本、认证、组件、工具或技能信息。

`GET /api/agents/connectors?agentKey=<key>` 和同路径 PUT 使用独立的精简挂载响应 `{agentKey,connectorIds,reloadPending}`，connectorIds 过滤预置（包括源码中显式重复声明的预置）。PUT 仅接受 `{agentKey,connectorId,enabled}`。reloadPending 仍比较完整配置与已发布挂载，因此活动 Run 延后发布时保留等待提示；隐藏预置不影响运行时工具和技能。

管理端 `GET /api/admin/connectors` 保留完整包摘要、组件、技能和同步状态；`GET/PUT /api/admin/agents/connectors` 保留 connectorIds、presetConnectorIds、declaredConnectorIds、activeConnectorIds 和 reloadPending。两套 PUT 都拒绝切换预置，返回 HTTP 403 `preset_connector_readonly`，不写入 Agent 源文件。builtin 包编辑、删除和覆盖继续使用已有只读保护。WebClient 的 `/agents/:agentKey` 显示只读预置区，包详情仍由 `/connectors` 管理。

内置的 `builtin.platform-control`（桌面端）和 `builtin.web-control`（网页控制）没有互斥声明：两者工具互不重叠，可以同时挂载。互斥声明只约束组合选择，不是执行权限策略。两者的边界见 [Desktop 与网页控制连接器](连接器共享包与Desktop迁移.md#builtinplatform-control)。

## 安装包

```text
Platform 随包根/connectors/
├── builtin.dbx/
│   ├── connector.json
│   ├── cli.json
│   ├── bin/
│   │   ├── dbx                     # Windows 为 dbx.exe
│   │   └── libs/                   # 私有依赖，不加入 PATH
│   └── skills/
│       └── builtin-dbx/
│           ├── SKILL.md
│           ├── references/
│           └── assets/
└── builtin.httpx/                  # skills/builtin-httpx，其他结构同上

runtime/connectors-center/
└── remote-search/
    ├── connector.json
    ├── mcp.json
    ├── assets/                    # 可选品牌图标
    │   └── icon.svg
    └── skills/                    # 可选
```

`builtin.*` 为平台保留命名空间，内置连接器不可修改或删除；Agent 可以解除挂载，包本体仍保留。外部根里的旧 builtin.* 副本不读取、不校验、不作为缺包时的回退，不会覆盖随包版本。

包**可以携带 `bin/`，依赖库放在 `bin/libs/`**。加载不执行任意安装脚本。`id` 必须与目录名一致，由小写字母、数字、点、下划线或短横线组成，首字符为字母或数字；`name` 非空，`version` 使用 SemVer。

```json
{
  "id": "remote-search",
  "name": "Remote Search",
  "version": "1.0.0",
  "type": "mcp",
  "icon": "assets/icon.svg",
  "auth_mode": null
}
```

`type` 为主类型（`mcp`、`cli` 或 `view`），决定相应 JSON 文件必填；同一个包可同时携带三种组件。VIEW 使用 `view.json` 和 `views/` 资源，见 [VIEW连接器](VIEW连接器.md)。JSON 拒绝重复键、尾随值、非 UTF-8 和清单未知字段。包根必须是真实目录；符号链接不得逃出包目录，特殊文件拒绝加载。

`icon` 可选，必须引用包内 `assets/` 下的 SVG 或 PNG，相对路径不接受 URL、查询参数或目录逃逸。图标不超过 256 KiB；PNG 必须是有效图片且宽高分别不超过 4096，SVG 只接受静态图形、局部引用和标准 SVG 1.1 文档声明，拒绝脚本、内嵌页面、自定义 DTD 和外部资源。导入、加载及定义保存时检查路径与内容；声明图标但文件缺失时拒绝发布。未声明图标的旧包仍有效，由客户端显示默认图标。

管理目录响应保留 `icon` 相对路径，并提供 `iconSha256` 与 `iconUrl`；使用目录只提供展示所需的 `iconUrl`。客户端通过 `GET /api/connectors/icon?id=<id>&v=<sha256>` 获取图片；接口只读取清单声明的图标，沿用 Platform 鉴权，提供正确图片 MIME、ETag 与重新验证缓存。使用 Bearer 鉴权的客户端应携带请求头获取 Blob 后交给 `<img>`，不能把 Token 放入 URL，也不要将 SVG 内联为 HTML。覆盖包后摘要与 URL 随图标内容更新。完整包中的 `assets/` 同样进入 Agent 的连接器运行副本。

Skill 支持 `skills/SKILL.md` 单技能，或 `skills/<name>/SKILL.md` 多技能，两者不能混用。每个技能要求 frontmatter `name` 和 `description`；多技能的 name 与子目录名一致。脚本、资料、references 和 assets 随完整包安装到共享运行目录；`.config` 默认值按 Agent 独立合并。

## Agent 挂载

Composer 可通过 `GET /api/admin/agents/connectors?agentKey=<key>` 读取 Agent 源配置的挂载列表。响应为 `{agentKey, connectorIds, activeConnectorIds, reloadPending}`：`connectorIds` 来自注册的 `agent.yml`，即使 Agent 运行中仍显示已保存的选择；`activeConnectorIds` 来自当前发布定义，二者集合不同时 `reloadPending=true`。该接口不返回提示词、环境变量或授权凭据。

`PUT /api/admin/agents/connectors` 接收 `{agentKey, connectorId, enabled}`，其中 `enabled` 必填。服务与现有 Agent 编辑共用写锁，读取最新源文件，只增删 `connectorConfig.connectors` 中的单个 ID；写入前检查连接器包及技能冲突，以源摘要防止覆盖并发源码编辑。同值请求不重复写入或重载，builtin 包可挂载或解除挂载。

原子保存后调用现有 `agents` catalog 重载链；活跃 Run、子调用、Team 成员和 Terminal 租约继续使用旧运行副本，结束后经现有回调发布新配置。硬重载失败时按新文件摘要恢复原始源内容并尝试恢复 catalog，返回失败诊断。挂载操作不修改部署共享授权，也不更改其他 Agent 的挂载列表。两个接口使用现有鉴权、标准 ApiResponse，并禁止缓存。


```yaml
connectorConfig:
  connectors:
    - builtin.dbx
    - builtin.httpx
    - remote-search
```

挂载列表顺序稳定，重复 id 去重。缺包或包非法时隔离该 Agent 并保留管理端诊断；不会静默少挂一部分能力。

- 含 MCP/CLI/技能的包，由 Host Bash 和 Workspace Terminal 为当前 Agent 前置 `ru-connectors/<id>/<contentDigest>/bin`，顺序与挂载列表一致；后挂载的同名命令优先级较低。连接器不修改 Platform 的进程 PATH，也不把 `libs` 加入 PATH。
- Container 自动将所选包只读挂到 `/connectors/<id>`，使用 `/connectors/<id>/bin`。审批解析与实际执行使用一致的容器路径。二进制必须匹配容器的 OS/架构；挂载不会把 macOS/Windows 二进制转换成 Linux 程序。
- 自动导入全部连接器技能的元数据，指令路径为 `@connectors/<id>/skills/<skillName>/SKILL.md`（单技能包为 `@connectors/<id>/skills/SKILL.md`）。文件从本 Agent 的 `ru-connectors/<id>/<contentDigest>` 读取，不再重复复制到同级 `skills/`，也不写入 `skillConfig.skills` 或技能中心。`skillId` 直接使用包内 `SKILL.md` 的原始 `name`（如 `example-shared`），不添加连接器前缀；连接器来源由独立的 `ConnectorID` 与 `path` 表达。同一 Agent 挂载的连接器之间，或连接器技能与 `skillConfig.skills` 之间出现同名（忽略大小写）时，隔离该 Agent 并返回冲突诊断，不自动改名或覆盖。
- 技能 prompt、`.runtime-env.json` 和 hooks 从本 Agent 的连接器技能目录读取，`.config` 复用正常 Agent 合并规则并写入各自 `ru-agents/<agentKey>/.config`。`@connectors` 只解析当前 Agent 已挂载的包；已挂载包进入 run trusted read + readonly roots，不能通过 write approval 放宽为可写。
- 技能加载提示要求 Agent 主动匹配普通技能与连接器技能，命中或用户点名后，先将 catalog 的 `path` 原样传给 `file_read.filePath`，再执行对应工作流或 CLI。`@skills`、`@skills-center`、`@connectors` 是不同的语义根，不能根据 `skillId` 拼路径或改写前缀。读取失败先核对 catalog；精确路径仍失败时报告错误，不搜索或替换为其他目录的同名旧副本。该加载规则由 `internal/server/prompt_context.go` 固定附加，通用调度默认文案在 `internal/contracts/prompt_types.go` 与 `configs/agent-prompt.example.yml`，`file_read` 参数说明也明确支持 `@connectors/<id>/...`。这是提示词约束，不是工具执行层的强制读取门禁。
- 纯 VIEW 包只增加展示能力，不自动增加 Bash/PATH。
- MCP 组件的当前同步工具自动加入 Agent 的 run 工具集合。纯 MCP 且无 CLI/技能的包不会额外授予 Bash；含 CLI/技能时沿用普通 Skill 的 Bash 追加规则。

专用 KBASE 与其他内置类型一样处理连接器挂载：CLI 连接器会追加 Bash，native 连接器按连接器 ID 对应的源码注册表导入工具；未开启 `editingMode` 时 Workspace 的只读保护仍由通用访问策略执行；ACP CODER 不执行 Platform 工具，因此拒绝连接器挂载。Team 成员按各自 Agent 挂载，其他 Agent 不继承调用方挂载。解除挂载后，空闲 Agent 的下一次 catalog 组装移除整个运行包及技能。活动 Run、子 Agent 调用、Team 成员和 Terminal 持有运行目录租约；更新或删除该 Agent 延迟到最后一个使用者结束，其他空闲 Agent 继续发布。已有 run 的 prompt/env/工具列表保持原快照。

挂载同时授予本 Agent 运行包 `bin` 内 CLI 的执行权：全部子命令和参数在所有 `accessLevel` 下获得入口执行授权，不产生入口审批审计；匹配的业务 Hook 仍独立生效。识别使用实际执行路径和 catalog 冻结的入口摘要，支持二进制、Shell/Node 启动器、Windows `.cmd/.exe` 及显式解释器启动包内入口；不按命令名称或 `sh/node` 全局放行。CLI 参数、cwd、内部文件与网络行为由该授权覆盖，登录状态和服务端业务权限由 CLI 自行校验。

运行包 `bin` 顶层的可执行常规文件及支持的脚本入口被纳入快照，不扫描 `bin/libs` 为额外命令；包内符号链接按真实目标冻结，越包链接拒绝。其他命令、Shell 重定向、命令替换和环境赋值继续独立审查，例如 `example-cli ... && python ...` 只豁免前者。执行前重验实际入口和 SHA-256，未挂载、同名外部程序、入口内容变更或容器探测失败回到普通策略。纯 CLI 调用的工具结果可带 `accessPolicy.decision=allow`、`ruleKey=bash-access:connector`，没有审批来源或审批消息。

## mustUseSkills

连接器技能**不能被 `mustUseSkills` 选中，包括 Agent 已挂载的技能**：

- `/api/skills` 的可选列表不包含自动导入的连接器技能。
- 请求传入当前 Agent 已挂载的连接器技能原始名称时直接拒绝；技能中心同名项也不在该 Agent 的可选列表中展示。历史 `connector-` 前缀与旧内置技能名 `builtin-dbx`、`builtin-httpx` 保留给连接器，技能中心列表不加载这些副本，普通技能导入/编辑也拒绝这些 id。不能用 `skillConfig.skills` 绕过来源约束。
- 技能随连接器挂载自动可用；不需要、也不允许再以 mustUse 强制选择。
- 普通 Agent 自有技能和技能中心技能仍保持原来的 mustUse 行为。

## MCP 配置和生命周期

HTTP 示例 `mcp.json`：

```json
{
  "mcpServers": {
    "main": {
      "type": "streamableHttp",
      "url": "https://example.com/mcp",
      "timeout": 30000,
      "staticHeaders": {"X-Tenant": "local"},
      "disabledTools": ["delete_all"]
    }
  }
}
```

`url` 是完整地址，不再追加隐式 `/mcp`。stdio 示例：

```json
{
  "mcpServers": {
    "main": {
      "type": "stdio",
      "command": "service",
      "args": ["serve"],
      "staticEnv": {"LOG_LEVEL": "info"},
      "timeout": 30000
    }
  }
}
```

stdio 裸命令从当前 Agent 包内 `bin` 解析；相对路径以该运行包为基准。显式 command/cwd 若指向来源包内部，也映射到 Agent 副本；真正位于包外的绝对路径仍支持迁移后的部署程序。工作目录默认运行包根；`platform.workingDirectory` 可显式覆盖。HTTP 不接受 env/command/args/runtime；stdio 不接受 url/headers。动态与静态字段不能同名，请求头大小写不敏感；保留 AP 环境变量不可覆盖。`timeout` 是正整数毫秒，适配到现有 MCP client 的秒级超时（向上取整）。

组件来源标识中，`main` 对应 `<connector-id>`，其他组件对应 `<connector-id>.<component>`；跨包来源标识重名会硬失败。实际 MCP 实例由 `(agentKey, connectorId, component)` 唯一确定，具有独立 session、stdio 进程、工具快照和重试状态。内部 serverKey 和模型工具名包含稳定摘要以避免多 Agent 冲突，调用远端时仍发送原始 MCP 工具名；工具路由拒绝其他 Agent 调用该实例。未挂载的包只做本地校验，不建立连接。部署专属的 `platform` 块保留 enabled、name、workingDirectory、toolPrefix、aliasMap、authSource、connect-timeout、startup-timeout、retry、tools，主要用于旧配置无损迁移。

HTTP/stdio 统一使用官方 SDK 协商协议版本：优先请求 `2025-11-25`，接受 SDK 支持的 `2025-06-18`、`2025-03-26` 和 `2024-11-05`；缺失、无效及未知版本仍拒绝。stdio 清理和后台同步机制保持一致。启动和保存只同步校验本地定义；远程连接/工具发现不阻塞服务监听。连接变化清除旧工具快照，后台结果按 Registry version 发布，状态变化发送 `catalog.updated(reason=connectors)`。

`auth_mode=null` 委托连接器 Skill/CLI 自行鉴权，不等同于无需认证。静态 Token 使用 `token`，通用 OAuth 授权码流程使用 `oauth`，MCP OAuth 发现使用 `mcp`；`oneid-token` 复用 Desktop SSO，在 Host CLI/stdio MCP 的调用环境注入 `AP_ACCESS_TOKEN`，HTTP MCP 按同一身份来源生成 Bearer Header，Token 不复制到连接器状态目录。迁移工具将原来的部署级 headers/env/token 保存到 `.state/connectors/<id>/credentials.json`（0600），放在包目录外，JSON 定义仅保留 `${KEY}` 模板；模板只从这份部署级存储替换一次，不读取任意进程环境。此存储保持旧部署的认证语义，**不代表已经实现按用户绑定凭据**。迁移保留的 `platform.authSource=identity-file` 继续复用已有 HTTPS 身份适配器。MCP 的 token 缺失、OAuth 尚未完成或 runtime 尚未准备时，后台状态为 unavailable。OAuth 登录凭据按资源与目标地址隔离，兼容保存在 `.state/connectors/<id>/oauth.json`，权限 0600，支持持久化刷新和退出；不通过清单、ZIP 或状态接口回显。详见 [连接器安装与授权](连接器安装与授权.md)。

## 管理接口

接口均使用现有鉴权和统一 `{code,msg,data}` 包裹：

| 接口 | 用途 |
| --- | --- |
| `GET /api/connectors[?agentKey=<key>]` | 过滤平台预置的精简使用目录 |
| `GET/PUT /api/agents/connectors` | 当前 Agent 的非预置挂载状态和单项切换 |
| `GET /api/admin/connectors` | 完整管理目录：包摘要、组件、技能和 MCP 同步状态 |
| `GET/PUT /api/admin/agents/connectors` | 完整挂载状态和来源；预置仅可查看 |
| `GET /api/admin/connectors/detail?id=<id>&file=<file>` | 读取 connector.json、mcp.json 或 cli.json，返回 content、sha256 |
| `GET /api/admin/connectors/skills?id=<id>` | 原包技能摘要：名称、描述、版本、触发词、相对文档路径、字节数、更新时间 |
| `GET /api/admin/connectors/skills/detail?id=<id>&name=<name>` | 包内指定技能摘要、完整 SKILL.md 和 sha256，只读 |
| `PUT /api/admin/connectors/detail` | 以 id、file、content、必填 baseSha256 保存已存在的定义文件 |
| `DELETE /api/admin/connectors/detail?id=<id>` | 删除未被 Agent 引用的外部安装包，成功返回 `{id,deleted:true}` |
| `POST /api/admin/connectors/import` | multipart `file` ZIP、可选 `overwrite`，完整校验后安装并 reload |
| `GET/POST/DELETE /api/admin/connectors/auth?id=<id>` | 状态、开始登录、退出登录 |
| `POST /api/admin/connectors/auth/cancel?id=<id>` | 取消当前登录会话及子进程 |

### 配置完成与本地授权

| 接口 | 行为 |
| --- | --- |
| `GET /api/connectors/connection[?id=<id>]` | 单个或全部连接器的本地配置完成状态、授权快照、准备状态和能力；不启动 CLI、不访问第三方 |
| `POST /api/connectors/connect?id=<id>[&component=<name>]` | 按既有认证模式开始配置；多组件 OAuth 复用既有 component 选择，Token 仍通过管理端 credentials 提交 |
| `POST /api/connectors/check?id=<id>[&component=<name>]` | 显式检查；Token 验证待验证候选或当前凭据，受管 CLI 执行 status，OAuth/OneID 保留既有本地 grant/identity 判定 |
| `POST /api/connectors/disconnect?id=<id>` | 清除本地授权与配置完成标记；不删除包、CLI 私有设置或 Desktop SSO |

`connection.json` 仅保存 `connectorId/configured/updatedAt`。没有 bound/enabled 双开关，也没有 PUT 启用接口。除 `no_auth` 外，外部包和内置包缺少此文件时均为未配置；成功连接或保存完整 Token 配置后记录完成，无需再启用。此状态在 Platform 实例共享，Agent 挂载关系仍由 Agent 配置维护。内置定义不可修改或删除的包所有权规则，不限制其本地授权状态管理。

MCP 后续调用（包括已缓存 session）与 通用连接器执行准入检查当前配置完成状态。`configured` 不代表凭据永不过期或第三方始终可达；无独立验证命令的 Token 返回 `configured`，非受管 null 模式返回 `delegated`，通用执行接受这些既有认证模式的可调用状态。Host Bash 只向已验证的直接连接器子进程注入该连接器凭据；普通 Shell 不继承挂载连接器凭据或身份 Token。需要凭据的复合调用须拆成独立命令；Terminal 不因连接器状态增加打开限制。详见 [AccessPolicy 与 HITL 边界](AccessPolicy与HITL改造.md)。

退出取消未完成登录/凭据检查，迟到结果不得恢复配置；不主动取消已经开始的业务调用，也不强行关闭其 MCP session。后续调用按清理后的状态处理。退出只删除平台保存的 Token、待验证 Token、验证快照与 OAuth grant 文件，保留 `home/config/cache/data/state/tmp`。CLI 原生退出复用包声明的 `unAuth`；旧 `logoutMode: delete-config` 不再删除整个配置目录，会返回需单独重置配置的提示。此接口不提供通用第三方撤销或私有环境重置能力。

列表的 `mcp` 按 Agent 实例返回 `agentKey`、内部 `serverKey`、同步状态和工具数；组件未挂载时状态为 `unmounted`。列表还返回 `builtin`、`readOnly` 和 `canDelete`，内置项分别为 true、true、false；内置定义可读，PUT 和 detail DELETE 返回 403。`canDelete` 描述包所有权约束，实际删除时仍检查 Agent 引用。

外部包删除与 Agent 管理 mutation 串行，并与 ZIP 导入、定义编辑共享连接器 mutation 边界。删除前读取当前 Agent 源码引用（包括尚未重载或因其他配置错误而无效的 Agent）和已发布运行目录；仍被引用时返回 409，`data.error.agentKeys` 列出相关 Agent。应先在 Agent 管理取消挂载，并等待保留旧挂载的 Run/Terminal 结束；无法读取或解析 Agent 引用时拒绝删除。非法 id 或符号链接目标返回 400，不存在的包返回 404。删除先将包移至隐藏 staging，再本地 reload；失败返回 500 并恢复原包、重载原目录，若恢复失败则保留备份并返回诊断。成功后清理安装包，`.state/connectors/<id>` 的授权和受管 CLI 状态保留，重新导入可继续使用；如需清除授权，应在删除前退出登录。

外部定义保存先校验候选完整包和 MCP 配置，再原子替换文件并立即本地 reload；哈希冲突返回 409，本地 reload 失败恢复原文件，远端不可用不回滚合法定义。ZIP 导入默认拒绝同名包，显式覆盖以隐藏 staging/backup 完整替换；包解压和定义编辑共享 mutation 边界。本地 reload 失败恢复旧包，远端不可用不回滚合法安装。不要把真实凭据写入清单或可回显的定义文件。

Windows 下 ZIP 导入的目录发布、旧包备份与回滚遇到系统拒绝访问、共享冲突或锁冲突时采用有界退避重试；macOS/Linux 与其他错误立即失败。取消请求停止发布重试，但事务回滚使用独立的有界重试，不因请求取消跳过恢复。每次失败及重试恢复成功都记录操作阶段、平台、系统错误码、路径、次数与耗时；最终失败通过现有错误详情返回同一诊断，保留原始系统错误及回滚备份位置。临时目录继续排除在 Catalog watcher 之外，不通过复制覆盖或删除占用文件规避原子发布。

`catalog.validate(resourceType=connector)` 只校验提交的 connector.json 清单；组件与实际目录校验由加载和保存完成。旧 `resourceType=mcp-server`、Registry 的 mcp-servers 管理入口、`toolConfig.mcp-servers` 已移除。

技能管理接口仅位于 `/api/admin/connectors` 下，通过 Sources 读取内置或外部原包，支持单技能及多技能目录。同名技能按连接器 ID 隔离，复用 catalog 的 frontmatter 解析获取多行描述、metadata.version 和 triggers。详情只接受已登记技能名称，不接受任意文件路径；打开文件时以包根约束软链接，SKILL.md 必须为 UTF-8 常规文件且不超过 1 MiB。返回路径为包内相对路径，更新时间为 Unix 毫秒。非法目标返回 400，包或技能不存在返回 404，文档超限返回 413；不提供技能修改或执行入口，也不回退到 skills-center 或 Agent 运行副本。

`GET /api/admin/tools` 的 MCP 工具摘要额外返回可选 `mcpToolName`，取自同步时保留的远端原始名称，供管理界面展示完整名称；`key/name` 仍是带实例隔离前缀的调用标识，路由、别名与执行语义不变。该字段不透传整个内部 `meta`。

## Agent 运行目录与凭证

外部原包固定使用 `<AP_RUNTIME_DIR>/connectors-center`，执行包固定使用 `<AP_RUNTIME_DIR>/ru-connectors/<id>/<contentDigest>`。两种目录随 `AP_RUNTIME_DIR` 调整，不提供独立目录覆盖入口。YAML `paths` 节出现即报错。

连接器状态从环境变量 `AP_RUNTIME_STATE_DIR` 派生到 `connectors/<id>`；未设置或为空时为 `<AP_RUNTIME_DIR>/.state/connectors/<id>`。CLI 登录信息、MCP token/OAuth 凭据和受管 CLI 的 npm/config 状态都留在这里，按部署共享。运行包中的 `.platform-runtime.json` 只记录 stateDir 引用，不写入凭据。重建或删除 Agent、解除挂载不会清除状态；退出登录通过独立认证接口处理。原包不得夹带顶层 `.state`、`.credentials`、`connector-state`、`credentials.json` 或 `oauth.json`。

同一内容版本只安装一份完整运行包，bin、bin/libs、skills、references、assets 和合法包内符号链接随包保留。Agent 仅保存挂载引用；MCP 实例仍按 Agent 与包版本隔离，认证状态按部署共享。

启动清空并重建 ru-agents。热重载先校验本地来源，在 `.staging` 组装完整 Agent 候选；普通 Agent 内容按整目录替换，未变化的目录保留原文件；仅连接器版本改变时可以发布新挂载快照，旧 Run 继续使用旧版本。发布失败恢复旧目录，恢复失败保留备份并报告路径。活动 Run/Terminal 使用中的普通 Agent 文件暂缓替换，最后一个使用者结束后触发正常重载。新 Run 只有在本地 MCP 路由完成绑定后才可获取运行目录；远端初始化和 tools/list 仍由后台执行。Windows 文件占用导致发布失败时保留旧副本并报告诊断，不强行删除正在使用的文件。

`@connectors/<id>/...` 只映射当前 Agent 已挂载的 `ru-connectors/<id>/<contentDigest>`；Container 只读挂载对应 `/connectors/<id>`。未挂载 ID、`..` 和符号链接逃出对应包直接拒绝；运行包加入 trusted read + readonly roots。容器不默认挂载 `.state`，受管 CLI 的 Host 登录与 npm 安装不能直接在容器复用。

## 旧目录处理

Platform 只使用 `connectors-center` 原包和有效 `<state-dir>/connectors/<id>` 状态目录。旧 `connectors`、`connector-state`、`registries/mcp-servers` 以及包根内 `.state`、`.credentials` 直接忽略，不读取、不搬迁、不删除，也不因它们损坏或与新目录冲突而阻止启动。外部目录中的旧 builtin 副本同样忽略，不作为随包 builtin 的回退来源。

旧目录迁移实现和 `connector-migrate` 命令已移除。仅存在于旧位置的包和凭据需按当前格式重新安装、配置或登录；历史数据原样保留。Agent 使用 `connectorConfig.connectors` 挂载当前包。

启动、热重载和资源包校验使用相同的新来源。`ru-connectors` 保留已有内容版本和活动租约，不执行旧目录退役或备份迁移。独立的 Desktop 工具声明调整见 [连接器共享包与 Desktop 迁移](连接器共享包与Desktop迁移.md)，不涉及这里的旧包或凭据目录。

## builtin 发布

dbx/httpx 源码事实源为相邻 `agent-platform-builtins/{dbx,httpx}/`，各项目的 `connector/` 包含 connector.json 模板、cli.json 和完整 skills。根 VERSION 是 CLI 与连接器发布版本的唯一来源，构建器填入包版本并校验 cli.json.minVersion。Shell/PowerShell 发布脚本生成独立 CLI 包及完整连接器 ZIP；后者包含 `runtime/connectors/builtin.<name>/` 下的清单、bin 和 skills。Platform 不再内嵌它们的资源。

`sync-local-builtins` 从同一个 `agent-platform-builtins` 集合构建 builtin 与连接器项目，分别生成临时锁文件，再原子激活同一个目标 cache。`scripts/release-assets/builtins.lock.json` 仅锁底层依赖，`connectors.lock.json` 锁完整连接器 archive tree。正式锁更新仍遵守 native host、干净 checkout 与版本推进规则；连接器锁不自动加入 Git Bash。Go 运行/发布不重新构建 CLI 或 Rust，release 只验证并复制完整包，不更改清单、技能或包摘要。技能变化也须由连接器项目发布新包，再同步 cache。旧裸 CLI cache 拒绝并提示重新同步；完整旧包可按其自身摘要原样消费。Darwin 显式签名后摘要刷新仍按既有签名契约执行。

启动校验随包 manifest 后，只为挂载它的 Agent 将内置连接器组装到 `ru-connectors/<id>/<contentDigest>`。它是可重建的运行副本，原包所有权仍属于 Platform，不生成旧 `.builtin-state`。原始全局 bin cache 仍需升级为 connector 布局，以免未挂载的 Agent 获得内置命令。包清单版本来自对应 target 的实际 release；技能自身版本保留在 SKILL.md 中。

验证包括双来源解析、内置命名空间与只读接口、完整技能/引用/图片随包校验、技能单独更新时刷新发布哈希、挂载与解除挂载、mustUse 拒绝和列表过滤、PATH 不跨 Agent 泄漏、Host 命令执行、容器路径映射、MCP 协议/同步、外部定义保存回滚，以及旧 MCP/内置技能的迁移预演、备份与幂等。


### Desktop 内嵌连接器来源

`builtin.platform-control`、`builtin.task-control`、`builtin.kanban-control` 和 `builtin.web-control` 的工具 handler、清单和随包技能均随 Platform Go 程序编译分发。四个原生连接器统一从 `0.4.0` 开始使用 Platform 版本系列，后续版本由 Platform 发布时统一维护在各自的 `connector.json` 中；外部 dbx/httpx 继续使用独立项目版本。启动从内嵌资源校验并原子发布到 `ru-connectors/<connectorId>/<contentDigest>/`，已有相同内容的运行包直接校验复用；临时装配目录随即清理。进程持有共享包租约，确保未挂载 Agent 时管理接口仍可读取。各 Agent 仅持挂载引用，不复制包。

Desktop 不属于外部 builtin 构建缓存，不要求 `sync-local-builtins`，修改其源码资源后正常 `make run-local` 即可生效。`builtin.httpx`、`builtin.dbx` 和其他外部可执行组件仍按既有流程准备、校验缓存。旧缓存中的 Desktop 条目仍接受完整性校验，但应用装配始终选择当前程序内嵌版本；发布阶段从已校验的输出副本移除该旧条目，不改原缓存。运行时资源导入校验复用相同内嵌装配流程。此调整不改变连接器配置状态、Agent 挂载、工具权限或历史 Chat。


### 源码迁移与运行目录

`agent-platform-builtins` 是独立项目的集合目录，dbx/httpx 与其他 builtin 并列并保留各自 Git 历史。`runtime/ru-connectors/<id>/<contentDigest>` 是 Platform 管理的共享运行包，不能迁入源码集合，也不随源码迁移手工清空。新包产生新摘要，活动 Run/Terminal 的租约继续保护旧摘要；既有共享安装、校验、复用与回收流程负责切换。凭据和准备状态继续留在 `.state/connectors/<id>`，不写入源码或发布包。

`builtin.platform-control` 不迁出 Platform：其 native handler、协议声明和技能随程序一起发布，继续由内嵌资源原子安装到共享目录，且不依赖 CLI 构建缓存。集合目录不是 runtime 搜索路径；部署只需要完整 Platform 服务包。

连接器完整包锁初始仅登记原生 darwin-arm64 的已验证产物；其他平台通过本机同步生成临时目标并按既有正式锁更新规则推进，不借迁移写入交叉构建 SHA。


## Runtime 锁目录

连接器锁统一位于 `<AP_RUNTIME_DIR>/.lock`，各用途使用独立路径：

```text
.lock/
├── shared-connector-layout.lock          # ru-connectors 初始化互斥
└── connectors/
    ├── assembly.lock                    # 装配共享锁 / 回收排他锁
    ├── install/<connectorId>.lock        # 共享运行包安装互斥
    ├── operations/<connectorId>.lock     # 来源修改、准备与授权操作互斥
    └── leases/<connectorId>/<digest>.lock # 版本使用共享锁 / 回收排他锁
```

锁目录及其子目录必须是真实目录，锁文件必须是普通文件。锁由操作系统管理，释放后保留文件，存在不代表正在占用；不得在进程运行时删除。macOS/Linux 使用 flock，Windows 使用 LockFileEx；Windows 不因点前缀自动设置隐藏属性。Git 忽略 `/.lock/`。

`ru-connectors/.shared-v1` 保留为当前布局标记。初始化只创建目录和标记，不根据标记缺失推断旧布局，也不备份、重命名或迁移现有目录；没有旧版 ru-connectors 兼容流程。

锁路径直接切换，不双锁、不回退旧路径。更新前停止同一 runtime 的全部 Platform 和管理进程，再启动统一使用新路径的版本。原位置已有的锁文件不自动删除，停机后可清理；运行包和 `.shared-v1` 保留。

原生连接器通过 `connector.json` 的 `type: native` 和已注册连接器 ID 识别，工具归属唯一维护在 `internal/connector/native.go`。不再使用 `native.json` 或 capabilities 分组声明；旧文件会被加载器明确拒绝。受信任内置来源、无可执行组件及运行时挂载权限校验继续保留，API 的 `hasNative` 与 `nativeTools` 从源码工具注册表派生。

## 原生连接器的工具与技能分工

四个内嵌原生连接器的工具定义与配套技能成对维护，职责互不重叠：

- 工具顶层 `description` 只用一句话说明能力，并以 `Read the <skill> skill before use.` 结尾；技能名为连接器 ID 去掉 `builtin.` 前缀。
- 参数 `description` 只写字段含义（必填项保留 `Required.` 前缀）。类型、必填、枚举和 `additionalProperties` 由 Schema 承担机器校验；动作参数表、默认值、互斥条件、示例、审批与重试规则不写入工具定义。
- 技能 `SKILL.md` 用“工具 → 章节”对照表列出本连接器的全部工具，`references/` 按业务域提供完整参数手册。
- 新增或调整工具时先补齐技能章节，再写工具定义。`internal/tools/native_connector_tool_manual_test.go` 校验技能指引、描述长度上限、章节链接与 Schema 各层参数名在对应业务章节中的覆盖；顶层参数工具限定到自身标题或条目，不用其他工具的说明补足遗漏。这是名称覆盖检查，不证明参数类型、默认值或业务语义正确，也不证明模型先读技能。

`builtin.dbx`、`builtin.httpx` 没有 Platform 工具定义，经 Bash 调用 CLI，其手册由各自源项目的技能维护。

## Task Control 任务管理

`builtin.task-control` 是随 Platform 内嵌分发的原生连接器，包含 `chat_start`、`chat_get_status`、`chat_interrupt`、`chat_query`、`chat_manage`、`automation_query`、`automation_manage` 七个工具及独立 task-control Skill。普通 Native 根 Run 通过挂载获得这些工具；不自动授予网页、Desktop 或看板能力。

Chat 历史管理沿用会话访问权限，独立 Run 的查询和中断仍只允许同一调用 Agent 与 subject 操作其创建的 Run，禁止链式运行控制。Automation 仍是部署级资源，保留版本校验、审批和幂等收据，不增加按 Agent 隔离。执行、会话管理和自动化继续复用原有 runops、conversation、automation 服务。

分发示例已在全局 `preset-connectors` 中预置 `builtin.web-control` 与 `builtin.task-control`，普通 Native GENERAL/CODER/KBASE 自动合并挂载，配置变更需重启。未使用该预置的部署，迁移时为需要会话或自动化能力的 Agent 配置 `connectorConfig.connectors: [builtin.task-control]`；需要平台治理能力时另行保留 `builtin.platform-control`。仅声明 `chat_start/chat_get_status/chat_interrupt` 不再授予执行权限，必须挂载任务管理连接器。旧 platform-control 挂载不隐式获得新连接器。两者可与 `builtin.web-control` 一起挂载。

## Kanban Control 看板控制

`builtin.kanban-control` 随 Platform 内嵌分发，包含 `desktop_kanban` 工具及独立 `kanban-control` Skill，提供 listIssues、getIssue、createIssue、updateIssue、deleteIssue、moveIssue 六个动作。需要连接 Desktop；独立服务不会向模型暴露该工具。审批、修订校验和工作流执行仍由现有 Desktop 链路处理。

迁移时为需要看板的 Agent 添加 `connectorConfig.connectors: [builtin.kanban-control]`。平台控制不再授予看板工具，仅声明工具名也无法获得执行权。四个内嵌连接器可同时挂载，工具归属互不重叠；看板连接器不加入默认预置。无需同步外部 builtin 缓存，重新构建并重启 Platform 即可加载新资源。
