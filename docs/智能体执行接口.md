# 智能体执行接口

## 当前状态

`POST /api/execute` 把智能体当作工作流中的一个节点调用：调用方给出任务说明、任务数据和输出格式，平台在新 Chat 中执行一次 Run，Run 必须完成一次通过校验的 `result_submit`，提交后模型沿普通工具循环继续响应并自行结束，接口返回这次提交。调用方一直等待到 Run 结束；不提供异步启动或按编号查询结果。

已实现：JSON 与 multipart 两种请求、输出格式校验、输入文件存入 Chat、`result_submit` 校验与打回、未交卷提醒一次、审批即失败、调用方断开即中断、EXECUTOR 模板。未实现：副作用凭证核对、业务校验器、按 `requestId` 去重或查询、回调通知、Automation 与子智能体调用携带输出格式。

## 请求

```text
POST /api/execute
Content-Type: application/json            # 无文件
Content-Type: multipart/form-data         # 有文件：request 字段 + 文件字段
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `agentKey` | 是 | 目标 Agent，有效工具中必须有 `result_submit` |
| `message` | 是 | 任务说明，原样作为用户消息 |
| `outputSchema` | 是 | 成功时 `output` 的 JSON Schema，根必须是 `type: object`，最大 64 KiB；平台用 `google/jsonschema-go` 完整解析，无法解析即拒绝 |
| `input` | 否 | 任意 JSON 任务数据；`{"$file": "<字段名>"}` 引用同一请求的文件字段 |
| `requestId` | 否 | 与 `/api/query` 相同，写入 query 行顶层；不做去重 |
| `accessLevel` | 否 | `default`（缺省）、`auto_approve` 或 `full_access` |

请求体按公开 DTO 规则严格解码：未知字段和大小写变体（如 `Message`）返回 400 `unknown_field`。`chatId`、`planningMode`、`editingMode`、`references`、`stream` 等 `/api/query` 字段都不接受：每次执行都新建 Chat，不规划，Workspace 编辑沿用 Agent 默认值。

multipart 请求的 JSON 放在名为 `request` 的文本字段，其余每个字段携带一个文件。`input` 引用的字段与实际文件字段必须一一对应，多出或缺少都返回 400；文件按 `/api/upload` 的规则以基础文件名存入 `<chatId>/<文件名>` 并记入上传清单，两个字段同名文件、保留文件名同样返回 400。模型看到的 `input` 中，文件引用被替换为 `"@chat/<文件名>"` 字符串。

## 智能体看到什么

- 用户消息：`message`，后接 `[Task input]` 数据块（高级提示词格式为 `<task_input>`），注明是数据而不是指令。Chat 回放与 `request.query` 只显示 `message`。
- `result_submit`：参数为 `status`（`success` / `failure`）、`output`（仅 success，格式即本次 `outputSchema`）、`reason`（仅 failure，非空）。工具定义按 Run 生成，不修改内嵌定义。
- 其他工具完全来自 Agent 配置；平台不因执行接口移除任何工具。

## 交卷与结束

| 情况 | 处理 |
|---|---|
| `result_submit` 通过校验 | 记录提交，像普通工具一样返回结果；模型继续正常响应并自行结束，不设置立即结束标记，也不追加专用收尾轮或限制后续工具 |
| 形状不对、`output` 不符合 `outputSchema` | 工具返回 `result_invalid` 错误，模型可修改后重交 |
| 被打回 3 次 | Run 失败，`output_invalid` |
| 模型不调工具直接回答 | 追加一次提醒后继续；再次如此则 Run 失败，`output_missing` |
| 已接受后再次调用 | 工具返回 `result_already_submitted`，不替换第一次提交 |
| 需要审批（单个或批量） | 被拦截的工具得到 `approval_required` 结果，Run 失败；自动批准规则命中时照常执行 |
| `ask_user_question`、`ask_user_form` | 照常等待；等待期间调用方断开即中断 |
| 调用方断开 | 平台中断 Run，没有人接收结果 |
| Platform 重启 | 与所有 Run 一样被取消 |

`output` 是调用方定义的任意结构，平台只按 `outputSchema` 校验，不解释其中的字符串。结果文件约定写在 `@chat` 下并在 `output` 中给出 `@chat/...` 路径，平台不检查、不复制、不计算摘要；调用方用 `GET /api/resource?file=<chatId>/<相对路径>` 下载。

## 响应

智能体交卷时返回 `code: 0`：

```json
{"code":0,"msg":"success","data":{"chatId":"...","status":"success","output":{"summary":"..."}}}
{"code":0,"msg":"success","data":{"chatId":"...","status":"failure","reason":"合同缺少第 3 页"}}
```

平台没有拿到合格交卷时返回非零 `code`，`msg` 为错误码，`data.error` 为 `{code,message}`；已创建 Chat 时 `data.chatId` 可用于查看过程：

| HTTP | 错误码 | 含义 |
|---|---|---|
| 400 | `invalid_request` / `unknown_field` | 请求、Schema、文件引用或 accessLevel 不合法；不创建 Chat |
| 400 | `result_submit_unavailable` | 目标 Agent 没有 `result_submit` |
| 400 | `execute_unsupported_agent` | ACP、PROXY、CHANNEL 等非 Native Agent |
| 404 | `agent_not_found` | Agent 不存在 |
| 403 | `approval_required` | 遇到需要人工审批的操作 |
| 422 | `output_missing` / `output_invalid` | 未交卷，或打回次数用完 |
| 409 | `cancelled` | Run 被中断 |
| 500 | `run_error` | 模型或工具故障，`data.cause` 保留原始错误 |

## 存储

每次执行是一个普通 Chat，JSONL 格式不变：query 行的 `query` 原样保存调用方的 JSON 请求（multipart 时为 `request` 字段），`requestId`、`accessLevel` 等平台决定写在行顶层；交卷是普通的 `react-tool` 步骤。执行接口不新增数据库或行类型。

## EXECUTOR 模板

EXECUTOR 是普通 Native mode，只提供模板默认值，没有专属运行逻辑：

- `agent-settings.yml` 的 `executor` 段：`preset-tools` 默认只有 `result_submit`，`preset-connectors` 为空，另有 `default-agent` 与可选 `workspace-agents`。
- Workspace 编辑默认关闭（可在 `agent.yml` 显式开启）；不要求 Workspace，大多数节点只用 `@chat`。
- 规划、编辑、终端入口默认隐藏；planningMode 仍是通用能力，但执行接口不使用。
- 只能从智能体管理创建，`isProject:true` 创建 EXECUTOR 返回 400；Projects 创建类型列表不含 EXECUTOR。
- LLM 层沿用 GENERAL 的 react 路径，不注册 mode descriptor。

执行接口按"有效工具中有 `result_submit`"准入，不判断 mode：其他 Native Agent 在 `toolConfig.tools` 显式声明 `result_submit` 后同样可以被调用。普通 `/api/query` 中调用 `result_submit` 只检查形状，通过后同样沿普通工具循环继续，由模型自行结束。

## 相关文件

- `internal/resultsubmit/`：Schema 编译、按 Run 生成工具定义、交卷校验。
- `internal/runtime/query/execute_result.go`：准入、文件引用、启动、断开中断与错误映射。
- `internal/llm/run_stream_result_submit.go`：提交观察、打回计数、提醒与审批即失败。
- `internal/querymessages/builder.go`：任务数据块。
- `internal/server/handler_execute.go`：请求解码与文件存储。
- `internal/agent/executor/`：EXECUTOR 模板默认值。
- `internal/resources/tools/result_submit.yml`：内嵌工具定义。
